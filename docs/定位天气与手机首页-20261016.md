# 定位天气与手机首页

用户确认天气版概念图后开发，补充要求“城市是定位的”。沿用现有模型、会话、文件空间和拍照/语音能力，无新依赖。

## 首页

- 日期、定位城市及当前天气轻量显示在顶部，详情展示三天预报、最高/最低温和降雨概率。
- 左侧分时问候和天气关怀，右侧最新未央角色。未央使用带上指尾巴的对白气泡“摸摸我的头，打个招呼呀～”；摸头后换成第一人称回应。摸头轮换摸头、比心、眨眼、害羞，短暂特效后回到轻浮动招手；默认每7.5秒短暂眨眼，光圈缓慢呼吸。
- 严格对照确认稿：蓝金光带背景、放大的右侧未央、大号分时问候、蓝紫渐变创作按钮、三层立体文档、左右双任务卡、文件空间入口、圆润输入区和底部陪伴文字。
- 创作主卡片、两张可轮换任务卡、文件空间入口。不伪造上次任务或用户活动；无真实上次任务时用“从一个想法开始”。
- 原输入区保留附件、拍照、当前模型直接切换、语音与发送。PC 首页和滚动行为沿用原版。

## 定位与天气

- 首次首页申请系统定位授权；拒绝或失败后提供手动选城，不反复强制弹窗。
- 自动定位的城市在下次启动进入首页时更新位置；同一页面生命周期复用一次定位结果。手动选城后遵循该选择，点击“使用当前位置”可再次定位。
- 安卓为原生 WeatherLocation 插件，仅 ACCESS_COARSE_LOCATION，用系统 NETWORK_PROVIDER 一次性定位，及时停止监听，超时有手动入口。系统地理编码取得城市名，失败显示“附近”。坐标取两位小数后查询天气，不申请精确/后台定位权限。
- 浏览器使用 getCurrentPosition（低精度），常用城市附近匹配名称，其余显示“附近”；天气仍按实际粗略坐标查询。
- 天气接口超时 12 秒；缓存 15 分钟，过期且断网最多显示 48 小时缓存并明确标记。未来、损坏或更旧缓存拒绝显示；切换城市的旧请求不能覆盖新城市。
- 安卓使用既有原生网络回退；网页/PC 本机网关有固定天气上游代理，不接收任意 URL。公开服务在国内网络的可用性仍需真机验证，不保证所有网络可达。
- 关闭首页天气删除所选城市和缓存，不持续采集位置。

## 数据来源

天气依据 Open-Meteo 天气模型数据，界面不把它称为实测站点温度。城市搜索使用 Open-Meteo Geocoding/GeoNames；详情和城市选择页注明来源。

- https://open-meteo.com/en/docs
- https://open-meteo.com/en/docs/geocoding-api
- https://open-meteo.com/en/terms

未引入其他产品代码；卡片、排版和图标按现有结构自行实现。

## 验证

本地完成 JS 语法检查，以及真实模块解析、缓存复用、断网缓存、关闭清理、代理参数边界的 Node 断言。截图复核发现首页会被旧的对话底部跟随逻辑推走首行，已限定该逻辑仅用于对话，并在新建首页复位到顶部。完整依赖和浏览器执行由 Actions 完成，发布任务必须等待完整验证、安卓和 Windows 构建均成功。

新增天气单测覆盖缺失温度不变零、三日预报、提醒优先级、无城市不联网、非法坐标、缓存失效/损坏/未来时间、换城请求竞态、城市搜索过滤、固定上游和代理缓存。移动端新增自动定位、天气详情、离线标记、手动换城、摸头、窄屏与创作入口检查，并保存首页/详情/窄屏截图。

插画直接复用用户确认稿（home-concept.png）的三个无文字区域，通过固定 CSS 背景区域显示文档/热点/日程图案；真实天气、城市、日期及 UI 文字全部单独渲染，原稿中的示意值不会显示。没有照搬其他产品的代码。

没有连接用户 Windows 或 HarmonyOS 4.2 真机，不把浏览器定位模拟当作鸿蒙系统定位实测。
