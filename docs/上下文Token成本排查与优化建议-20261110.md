# 上下文 Token 成本排查与优化建议

状态：代码排查与方案，尚未实施上下文改造。用户报告平均每次请求约2.8万Token；未取得其逐次服务商usage，不能把本地估算当作账单归因或已节省费用。

## 已核对的实现

- `src/agent/compress.js`：KEEP=20条消息，BATCH=10；按软容量触发后台摘要，不是每次发送前限制5轮/8000Token。原消息保留，并有原话账本、任务状态与回读入口。
- `src/agent/turnContext.js`：工具结果总预算60000字，最近6条全文保留。单条长结果和近期多个长结果仍可能完整进入请求。已有有界原文缓冲和read_tool_result，可继续使用。
- `src/agent/tools.js`：文件默认分页20000字，部分工具摘要也达6000—30000字。需要在统一模型输入边界覆盖文件、网页、MCP、电脑工具及预取资料，不能只改tools.js的几个return。
- `src/agent/agent.js`：首次按taskToolCore选工具；续做、轻量升级、追问切换和架构接管等路径仍调用默认createToolLoader。`taskToolProfile.js`的带图、电脑和严格架构等分支也直接返回CORE。并非每次全带所有工具，但这些路径可能恢复较大的默认常驻集合；纯闲聊已有零工具路径，不应退化。
- `shared/modelMetrics.js`：目前是字符计数；未分开历史和工具结果。主模型和辅助模型已有诊断事件，model_end已有服务商usage；适配器内部重试、备用并发也需要逐次统计，不能将一次用户提问等同于一次API请求。

这不包含系统提示、历史、当前输入、工具返回、图片、MCP和电脑扩展，也不是服务商分词器结果。说明工具定义是重要嫌疑，不能据此断言每次2.8万都来自这里。

## 建议实施顺序和边界

1. 先补数字诊断，并修工具集合重建：保留本轮任务类型、已按需加载工具和冷却状态；通过tool_search明确加载所需能力，不为分类额外调用模型。完整名称和参数Schema仍须保留，不以删字段省Token。精简目录，避免将长Schema换成另一份长目录。
2. 在发送边界统一缩短文本工具结果：默认最多2000字（含摘要与回读指针）；保留真实成功/失败、文件路径、来源日期、数字单位及分页位置。全文留在有界原文存储/原文件，按需分页回读。文件编辑、表格核对和逐条需求不得把截断内容冒充完整。图片单独计量，不能按文本字数估算费用。
3. 已结束的历史按完整问答轮次取最近5轮，并以8000估算Token为上限；按完整assistant/tool-call/tool-result组缩减，不产生孤立回执。当前输入、当前未完成任务、最新纠正、必要引用不当作可随意丢弃的旧历史。原始会话不删除；较早内容用有上限的“目标、约束、已完成、待办、原文位置”结构摘要，不压成一句话。大模型摘要仅阈值触发、后台有界执行，失败仍可回读原文。
4. 每次实际发送记录system/history/current_input/tool_results/tool_schemas/assistant与调用参数的估算Token、模型与调用序号；结果记录实际input/output/cached与失败/重试。缺少usage写缺失，不能写0。只记录长度和受控字段，不输出正文、文件内容或Key。按用户轮次汇总调用次数与实际用量，区分缓存命中和不同模型价格。

## 验收要求

- 测试只加不删：5/6轮边界、恰好/超过8000、单条超长、工具配对、工具超2000、头尾关键数字/失败、分页回读、缓存逐出、多用户隔离；续做/模型切换后工具仍按需、权限不扩大。
- 同一组聊天、天气新闻、文件修改、编程、长文档任务做前后输入对照，记录每次请求与全轮合计。长文档检验原文约束及最终产物，不能仅凭Token减少判通过。
- 真实模型质量、实际账单和用户服务器费用对比尚未做。当前Windows更新、形象与手机语音修复批次不包含本方案，不宣称已降低Token费用。
