## 背景：Claude 的做法 vs 未央现在

| Claude 的做法 | 未央现在 |
|---|---|
| 几个搜索同时发，不搜一个等一个 | 已支持同一轮并行只读工具（防回退清单“并行只读工具”），但模型常常还是逐个调用 |
| 有公开数据接口就直接取结构化数据 | 只有天气 / 比分 / 行情等专用工具；其他只能 `fetch_url` 读网页正文 |
| 够用就停，自己判断查没查够 | `src/agent/retrievalBudget.js` 硬上限：普通查询 search 6 / read 4、45 秒；到了就整轮收尾，常停在半路 |
| 来源矛盾直说，查不全也给结论 | 查不全常交白卷（只给候选链接，或“没有可靠结果”） |
| 判断由强模型做 | 平时主模型 gpt-6-luna（便宜，判断弱），所以当初加了硬上限 |

## 要做的 5 项

1. **一次发多个搜索**
   - 在联网相关提示里写明：要查几个方面（如国内 / 国际 / 财经，或几家平台的价格），同一轮一起发出 `web_search` / `fetch_url`；
   - 加测试：用模拟模型确认多个检索在同一步并发执行、耗时取最大值而不是相加；
   - 搜索次数统计照常计入预算。
2. **预算从“次数优先”改成“时间优先”**
   - 普通查询保留总时长上限（现 45 秒，可按实测调）；
   - 次数上限放宽为防失控兜底（比如 search 12 / read 10），不再是常规的收尾条件；
   - 到时间或兜底触发时，照现有逻辑用已有资料作答；
   - 连续失败 3 次的保护保留；
   - 深度 / 逐项核验的预算不动；
   - `tests/` 里涉及预算数字的旧断言，**按新规则补新测试，旧测试如需改动先说明理由**，不能直接删。
3. **所有查询都不交白卷**
   - 把新闻单里“不交白卷”的规则推广到普通联网查询：拿到多少给多少；
   - 每条标来源，未打开原文的标“待核实”；
   - 一条都没拿到时，说清是哪一步失败（搜索超时 / 网页打不开 / 预算到时）；
   - `reviewOutcome` 的“部分完成”提示保留，但回答正文不能只剩链接。
4. **新工具：读公开数据接口**（名字自定，如 `fetch_json`）
   - 只读 GET，不带 Cookie / 用户凭据，不能自定义请求头里的鉴权；
   - 地址限制：只允许 https、公网地址（禁止内网 / 本机 / 元数据地址，复用现有网关的安全检查）；
   - 可配可信域名清单（设置里可增删），默认给一组常用公开数据源，比如国家统计局、交易所公开行情、政府开放数据，Codex 先实测哪些可用；
   - 返回大小上限（如 200KB）、超时 8 秒；JSON 结构化后交给模型，超长截断并说明；
   - 计入 read 预算；
   - 不提供任意代码执行。
5. **查资料时规划用强一点的模型**
   - 能力表里已有“推理”档（`routeFor(cfg, 'reason')`）；
   - 联网查询的第一步规划（决定查哪些方面、发哪些搜索）和最后的取舍判断，交给推理档；
   - 中间读网页、摘要仍用主模型；
   - 推理档没配时照旧用主模型，不报错；
   - 记录调用明细（taskTiming 的 calls），方便对比花费。

## 不能放松的

- 联网来源必须是真实取到的，不编链接、不编数字。
- 今日新闻的日期核对、`answerRequirements` 现有约束保留。
- 评测隔离、代码工具隔离不受影响。
