## 七、11-03 用户反馈：“23小时后是几点”报错（新任务，并补齐同类缺口）

**现象**：模型调用
`verify_numbers {"action":"date_add","data":{"date":"2026-11-03 15:50","days":0}}`，
工具报错 `日期必须为YYYY-MM-DD`（`src/agent/verifyNumbers.js` 的 `dateValue`）。之后回答卡在“搓搓手”。

**原因**：`date_add` 只认纯日期、只能加整天，不认带钟点的时间，也不能加小时、分钟。模型选对了工具，是工具能力不够。

**用户要求（11-03）：同类问题一起补齐，不用列清单问用户，按下面的方案直接做完、发版。**

### 1. 时间计算：新工具 `time_calc`（`src/agent/timeCalc.js`）
`verify_numbers` 的 `date_add`、`date_difference` 保留，也接受带钟点的写法，内部改调 `time_calc`，旧测试不动。

- **统一解析 `parseMoment(text, now)`**，默认时区 Asia/Shanghai（北京时间）。要接受：
  - `2026-11-03`、`2026-11-03 15:50`、`2026-11-03T15:50:00`、`2026/11/3`、`11月3日`、`11月3日下午3点50`；
  - `今天/明天/后天/昨天`、`现在`、`今晚8点`、`下周五`、`本月底`。

  解析不了就报错，并在报错里列出可接受的写法和一个例子。
- **操作**（`action`）：
  - `add`：加减 days/hours/minutes，可以组合。返回日期、钟点、星期几，跨天要写明。
  - `diff`：两个时刻相差多久，给出“x天x小时x分”和总分钟数；单位按天给的话，也给自然日数。
  - `weekday`：某天是星期几。
  - `countdown`：距离某个日期或节日还有多久，节日支持春节、元旦、清明、劳动节、端午、中秋、国庆。
  - `workdays`：两日期之间的工作日数，或某天加 N 个工作日。排除周末，按中国法定节假日和调休算。
  - `timezone`：把北京时间换成某个城市或 IANA 时区的时间，反过来也行。用 `Intl.DateTimeFormat` 和 IANA 名称；常见城市名（纽约、伦敦、东京、洛杉矶、悉尼、巴黎、迪拜、新加坡等）放一张小映射表。
  - `age`：生日 → 周岁和虚岁。
  - `lunar`：公历和农历互转。
- **节假日数据**：内置表 `src/agent/holidaysCN.js`，按国务院办公厅公布的放假调休通知整理（2025、2026 年），每年标注来源（gov.cn 通知标题和日期）。查询年份不在表里时，只排除周末，并在结果里写明“该年节假日未内置，只排除了周末”。
- **农历**：用 1900～2100 年的农历数据表做互转。只借鉴开源实现（先看 LICENSE，MIT 等）；照抄了数据或代码的，按 CLAUDE.md 在文件顶部注明出处和许可。不引入大依赖。
- 工具描述里写清楚每个 action 的参数，并各给一个例子。把 `time_calc` 加进常驻工具和并行只读工具。在系统提示的计算规则里写明：时间、日期、时区计算用 `time_calc`，不要心算。
