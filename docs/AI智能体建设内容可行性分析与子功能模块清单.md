# 长江流域重点水域禁捕执法装备设施建设项目

## AI智能体新增事项——建设内容可行性分析与子功能模块清单

（配套《AI智能体新增事项可行性分析报告V5》，用于向领导汇报与评审说明）

**第二版** —— 在第一版基础上新增：与标书功能逐项对比、审计合规对应关系、冲突与去重分析、可暂缓模块判断、分批实施建议。原有的通俗说明与272个子功能模块清单全部保留。

## 一、一页读懂

**一句话说清这次要干什么：**

在建的平台解决的是"**看得见、传得回、流程能走通**"；这次新增的AI智能体，解决的是"**看得懂、判得准、派得对、越用越准**"。两者是上下两层的关系，不是重复建设。

**举个例子，同一条预警，前后是这样的：**

| 环节 | 现在（在建平台） | 加了AI智能体之后 |
| --- | --- | --- |
| 发现 | 摄像头拍到岸边有人，系统弹出一条告警 | 同上（复用现有设备与告警） |
| 看懂 | 人工点开视频看：是钓鱼还是路过？ | AI自动识别持竿、抛竿动作，判定"正在垂钓"，并给出证据截图 |
| 研判 | 人工翻法条、翻案例，判定违法等级，耗时以"天"计 | AI自动检索法规和裁量基准，输出违法等级与处罚幅度建议，附完整依据，分钟级 |
| 派单 | 人工打电话找人，人工填工单 | AI自动算出最近的执法艇和人员，生成派单，盯签收 |
| 归档 | 人工回填表格 | 移动端回传自动归档 |
| 提升 | 模型不动，明年还是这个准确率 | 处置结果（正报/误报）自动回流训练，系统越用越准 |
| 负责 | 人工全程负责 | **AI只出建议，最终决定仍由执法人员作出并签字负责**（本次专设"人机协同与安全合规"模块保障） |

**总体可行性结论：**

10大模块67项功能，**全部技术可行**，其中：

- **6个模块为标书完全没有的新增能力**（多智能体协作、任务规划与自主决策、记忆管理、知识库与RAG、工具调用与执行、人机协同与安全合规）；
- **4个模块是在标书已建能力之上的深化**（视频智能识别、执法调度与派单、NL2SQL智能报表、智能巡查），**不重建底座、不重复采购硬件**，需在方案中逐项标注"复用/新增"以规避重复建设质疑；
- **3项前置条件必须先落实**：① 在建平台的接口开放清单与时间表；② 大模型的国产化部署与等保、密评合规路径；③ 视频识别的冷启动样本来源与分阶段验收指标；
- **1项成本必须单列**：大模型API调用费属持续性运营成本，不在本次建设采购范围内。
- **6处功能与标书重叠，必须主动去重**（详见第八章）。这是评审最可能追问的点，主动说清比被问出来好；
- **审计不是障碍，反而是理由**：标书已有的审计管的是"人操作系统"，管不到"AI做了什么决定"——这个缺口正是模块九要补的（详见第七章）；
- **2个模块建议暂缓**（智能巡查、NL2SQL智能报表），**2项不建议暂缓**（模块九审计底座、模块七第50项回流训练，详见第九章）。

## 二、判断依据：标书里已经有什么、还缺什么

本次可行性判断，逐条比对了标书《第四章 采购需求》的全部建设内容。标书已建成的能力如下：

| 标书已建能力 | 具体内容（摘自第四章） | 对本次AI智能体的作用 |
| --- | --- | --- |
| 智能预警子系统（22项） | 视频巡逻、雷视联动、智能分析、无人机联动、AIS、船舶汇聚等6类预警识别；预警规则配置；预警研判（人工）；预警取证；预警闭环处理；预警统计 | 提供告警来源和"预警—研判—签收—处置—审核"流程壳，AI在既有节点上接入自动研判 |
| 重点人员管理子系统（16项） | 人脸库、识别预警、布控管理、态势感知、事件档案与事件分析 | 提供重点人员画像的底层数据，AI不重复采集 |
| 巡查执勤处置子系统（14项） | 工作台、任务创建与流程配置、巡查路径管理、视频巡查、图片巡查、任务签收/调度/反馈、移动端 | 提供巡查业务流程与"苏农云"移动应用基座，AI不另建APP |
| 指挥调度子系统 | GIS地图、融合通信、执法力量实时位置与调度 | 提供AI派单结果的执行通道 |
| 业务能力中心 | 事件中心（接收/联动/处置/预案/参数配置）、报表引擎、地图服务 | AI工具调用与事件回写的对接点 |
| 数据能力 | 数据源接入、工作表、业务建模、驾驶舱、近30种图表类型、大数据存储与计算引擎 | NL2SQL的数据底座与图表渲染层，AI不重建BI |
| AI中台 | 人脸/人体/车辆/船只属性识别、区域入侵、视频结构化；算法调度（弹性伸缩、分时复用、倍速分析等）；算法仓库；算法策略编排；渔船捕鱼、人员垂钓、船舶非法入侵、船只种类、漂浮物、水位6类场景算法 | 提供算力调度与基础识别算法，AI智能体在其上做动作级、夜间、多人、跨点位的精度增强 |
| 系统对接 | 苏农云服务总线、省海洋渔业安全监管系统、公安"雪亮工程" | 跨系统工具代理的通道 |
| 多元联合感知平台 | 雷达、AIS、北斗、视频、无人机、船载、单兵执法记录仪、甚高频8类数据接入 | 多源融合研判的数据来源 |
| 硬件设备 | 双光谱重载云台32台（热成像640×512、激光补光≥3km）、全固态雷达12台、网络硬盘录像机32台（内置GPU、**支持视觉大模型导入与第三方算法插件导入**）、无人机5架、船载主机112台 | 视频识别与工具调用的物理载体，**本次无需新购算力硬件** |

**标书还缺什么（也就是本次要补的）：**

1. 缺"会思考的大脑"——标书的AI中台管的是"算法怎么调度到GPU上跑"，没有"业务上谁来拆任务、谁来做判断"；
2. 缺"记忆"——每条预警都是独立处理，系统不记得这条船、这个人以前干过什么；
3. 缺"法律知识"——法条和裁量基准没有进系统，研判全靠人工翻;
4. 缺"动手能力"——识别归识别，识别完不能自己去调云台、发工单、写文书；
5. 缺"自我进化"——模型训练完就固化了，一线处置结果不会回流；
6. 缺"AI管控机制"——AI进入执法环节，谁负责、怎么留痕、错了怎么兜底，标书里没有对应条款。

## 三、可行性总体判断（五个维度）

| 维度 | 判断 | 说明 |
| --- | --- | --- |
| 技术可行性 | **可行** | Multi-Agent协作、RAG检索增强、NL2SQL、视频行为识别均已有成熟开源框架与商用方案，属工程集成，不属算法攻关。67项功能中无一项依赖未验证技术 |
| 业务可行性 | **可行** | 全部功能均对应标书已明确的业务场景与用户角色，无凭空设想的新业务；AI承担的是"建议"角色，不改变现有执法权责体系 |
| 合规可行性 | **可行，有前置条件** | 大模型须选国产底座、部署于政务云内网、数据不出域，方可满足标书要求的等保三级、信创国产化与密评；AI输出须经人工确认后方可作为执法依据，需法制部门书面确认边界 |
| 衔接可行性 | **可行，需明确接口清单** | 采用增量叠加、不重构原系统的方式建设。最大依赖项是在建平台的接口开放（云台控制、无人机调度、工单下发、数据查询等），建议将"接口清单+开放时间表"作为前置条件写入实施计划 |
| 投资可行性 | **可行，需单列运营费** | 710人天、142万元建设费用不含大模型API调用费。按V5报告测算，正常运营约9000元/月；若依托江苏省政务云已有大模型资源，该费用可由政务云统一承担 |

## 四、10大模块建设内容详解与子功能模块清单

> 说明：下列每个模块先用一段话讲清"这个模块到底干什么"，再列出可交付、可验收的子功能模块。"与标书关系"一栏中：**新增**＝标书无对应内容；**深化**＝标书有基础能力，本次做精度或场景增强；**复用**＝直接调用标书已建能力，本次不重复建设。

### 4.1 模块一：多智能体协作框架（7项功能 / 29个子功能模块）

**这个模块干什么：** 相当于给平台配一个"AI执法专班"——一个班长带五个专业组员。班长（监督调度Agent）接到任务后负责拆活、派活、盯进度、处理异常；五个组员各管一段：看视频的、做研判的、派任务的、审案卷的。以前这些活全靠人在各个模块之间来回切换，现在由AI在后台自动串起来。

| 序号 | 功能模块 | 子功能模块 | 建设内容说明 | 与标书关系 |
| --- | --- | --- | --- | --- |
| 1 | 监督调度Agent | 任务受理与意图归集 | 统一接收预警事件、领导指令、定时任务三类输入，归集为待处理任务 | 新增 |
| | | 子任务拆分与分派 | 把一个复杂任务拆成若干可执行子任务，分派给对应的专业Agent | 新增 |

### 4.2 模块二：任务规划与自主决策（7项功能 / 27个子功能模块）

**这个模块干什么：** 让系统"听得懂人话、拆得开活、拿得准主意、拿不准会举手"。领导说一句"这周末重点盯洪泽湖夜钓"，系统能自己理解成一组具体任务并安排下去；同时给每个判断打一个"把握度"分数，把握不足的自动交回人工，绝不硬着头皮下结论。

1. **不需要新买算力硬件。** 标书已配32台内置GPU的网络硬盘录像机，明确支持视觉大模型导入和第三方算法插件导入；32台双光谱重载云台带640×512热成像和≥3km激光补光，夜间识别的硬件条件已具备。
2. **与标书的算法不重复。** 标书"AI中台—算法场景适配服务"已含人员捕捞钓鱼、渔船捕鱼、船舶非法入侵、船只种类4类算法，其判定逻辑是"坐姿＋遮阳伞＋钓竿＋渔具桶＋滞留30分钟"这类**组合规则级**识别；本模块新增的是**动作级、夜间、多人、跨点位、状态细化**能力。建议在合同与方案中统一表述为"在已建算法基础上的精度与场景增强"。
3. **验收指标建议分阶段设定。** 冷启动阶段样本稀缺是客观事实，建议约定：试运行期主要场景查准率≥85%，运行6个月（经处置结果回流训练后）≥90%，而不是一上来就承诺一个高指标。

**前置条件：** 先行盘点各点位夜间成像条件（补光/红外覆盖情况），对不满足的点位补充补光设备或调整识别策略；同时明确冷启动样本的来源与标注责任方。

### 7.1 先说一个从标书里读出来的关键事实

| 标书条款 | 审计的是什么 | 出处 |
| --- | --- | --- |
| 个人工作台-日志管理 / 日志系统对接 | WEB应用用户审计：记录管理员和所有用户的访问、操作、意外及信息安全事件，可重现访问行为、数据查询、拷贝记录 | 门户（第6、17项） |
| 数据资源平台管理-日志审计 | 大数据平台操作记录：添加用户、删除用户等平台操作 | 数据能力 |
| 工具调用类日志审计系统 | 上网日志审计：NAT、流日志、URL日志 | 网络安全设备 |
| 数据安全管控-鉴权中心 / 数据安全 | 字段级安全控制、列脱敏、行过滤 | 数据能力 |

**这四处审计的对象都是"人操作了系统"，不是"AI做了什么决定"。**

也就是说：谁在几点登录、查了哪张表、导了哪些数据——标书能查得清清楚楚；但"AI凭什么判定这是违规垂钓、它调用了哪个模型、喂进去了哪些证据、返回了什么、为什么最后派了这条艇"——**标书的日志体系里没有这一层，查不到。**

这就是模块九必须建、且必须第一批建的最硬理由。它不是"锦上添花的可解释性"，而是补上一个标书没有覆盖、但AI一旦进入执法环节就立刻需要的审计维度。

### 7.2 关于新国标的引用（需核实后再写入变更申请）

拟引用的《智能体应用安全基本要求》强制性国标（国标委〔2026〕41号，2026年6月27日发布，归口中央网信办，18个月达标期）及《智能体规范应用与创新发展实施意见》，其提出的核心要求是：

> 审计不只是"有没有日志"，而是能不能还原一条完整证据链：**谁、在什么时间、用什么身份、调了哪个模型、传了哪些数据、返回了什么、命中了哪些安全策略**；做到"过程可查、责任可分、风险可控"。

**这段要求的实质内容与本方案模块九完全对应，可以直接采用。**

但有一点必须提请注意：**上述标准编号、发布日期、归口单位和文号，建议在报送前由业务处室到全国标准信息公共服务平台（或国家标准全文公开系统）和中央网信办官网原文核对一次。** 政府采购变更申请里引用错一个文号，评审环节会很被动，而且这类硬性引用一旦被质疑，会连带影响整份材料的可信度。核对要点有三个：标准是强制性国标（GB）还是推荐性（GB/T）、准确的标准编号与名称、以及实施意见的发文机关与文号全称。

**同时建议准备一条不依赖该国标也成立的备用论证**，即使核对结果与预期有出入，模块九的优先级依然充分：

1. 标书自身已明确要求通过**国家网络安全等级保护三级测评**，并满足**《密码应用安全性评估规范》**——AI决策过程属于系统行为，纳入审计范围是等保三级的应有之义；
2. **《行政处罚法》**要求行政处罚全过程记录，AI参与研判后，其建议的形成过程属于办案过程的一部分；
3. **《数据安全法》《个人信息保护法》**——模块三的重点人员画像、模块六的人脸比对涉及个人信息处理，处理记录必须留存可查；
4. 标书已要求敏感数据（重点人员信息、案件证据）采用国密算法加密存储，AI访问这些数据的行为同样需要留痕。

| 模块 | 是否可暂缓 | 理由 |

### 9.3 对"第一批只建模块九+模块四"的一处修正

把审计底座和知识库放第一批，方向是对的。但有一个执行层面的问题需要补上：

**模块九审计的对象是"AI的决策链"。如果第一批没有任何AI在跑，审计模块就无对象可审，验收时会变成空转——界面做出来了，但没有一条真实的AI决策记录可以演示和核验。**

**建议第一批调整为：模块九（审计底座）＋ 模块四（知识库与RAG）＋ 模块一的最小集**，最小集包含三项：

1. 第1项 监督调度Agent（提供任务发起与分发的审计起点）
2. 第3项 智能研判Agent（提供第一条完整的"检索→推理→输出"决策链）
3. 第6项 Agent间通信协议中的全链路会话追踪（把上述过程串成一条可查的链）

这样第一批交付时，审计底座一上线就有真实的AI决策链可审、可演示、可验收，而不是一套等着被填充的空壳。三项合计约30人天，不显著增加第一批投入。

| 内容 | 处理建议 |

| 模块七 第45-49项 | 待在建平台接口全部开放后接入，复用既有流程壳 |
| 模块八 第51、53、54、55项 | 待语义层建模与高频问法模板库准备就绪 |
| 模块十 第66、67项 | 去重后仅保留影像水印归档与巡查质量AI质检，可作为预算谈判余量 |

### 三批之外的三条配套建议

1. **《接口开放清单》必须在第二批启动前落实**。由采购人牵头，逐项明确接口名称、提供方、协议、开放时间，作为合同附件。模块五、七能否落地完全取决于此。
2. **验收指标逐项量化并分阶段设定**。重点是三类：视频识别的查准率查全率（试运行期≥85%、运行6个月后≥90%）、研判环节平均耗时（从天级到分钟级）、AI建议采纳率（衡量AI实际水平最直接的指标）。
3. **大模型API调用费在运营预算中单独列支**。按V5报告测算，正常运营约9000元/月，满负荷约3.6万元/月；若依托江苏省政务云已有大模型资源，可由政务云统一承担，本项目无需另行采购。

## 十一、变更申请中的建议表述

> **关于与在建项目的关系：**
>
> 本次新增内容在现有平台架构上增量叠加，不重构原有系统。经与招标文件《第四章 采购需求》逐条比对，10大模块67项功能中，标书零覆盖的实质增量共计约四成（含多智能体协作框架、任务规划与自主决策、记忆管理、知识库与RAG、工具调用与执行、人机协同与安全合规六个模块的全部或主要内容）；其余功能均在方案中逐项标注为"复用"或"深化"，对标书已建的报表引擎、图表组件、移动端基座、船艇轨迹、算法仓库、案件评分等能力**直接调用，不重复建设**。
>
> **关于审计合规的保障：**
>
> 招标文件已要求系统通过国家网络安全等级保护三级测评并满足密码应用安全性评估规范，其中的审计条款（WEB应用用户审计、大数据平台日志审计、日志审计系统）覆盖的是"用户操作系统"这一层。AI智能体进入执法研判环节后，还需要回答"AI调用了哪个模型、传入了哪些数据、返回了什么、依据哪条法规、最终由谁确认"——这一层审计能力在原设计中没有对应内容。
>
> 本次新增的**模块九"人机协同与安全合规"**（第57-62项）正是针对这一缺口的专项建设，包含推理链可视化、操作全链路审计、责任主体标识、人工兜底机制等能力，确保AI进入执法环节后**过程可查、责任可分、风险可控**；并固化"AI只出建议，行政处罚决定由执法人员依法作出并签字负责"的基本原则。
>
> **关于实施安排：**
>
> 鉴于审计合规是AI智能体进入执法核心业务的前提条件，建议第一批次锁定"人机协同与安全合规"与"知识库与RAG"两个模块，并配套建设多智能体协作框架的最小集（监督调度Agent、智能研判Agent、全链路会话追踪），使审计能力上线即有真实决策链可审、可验收。其余模块在审计底座建成后分批推进，其中智能巡查、NL2SQL智能报表两个模块与在建内容重叠较多且不构成前置依赖，可视预算安排暂缓或简化。

## 十二、风险、前置条件与应对

| 风险项 | 具体说明 | 应对措施 | 责任方建议 |
| --- | --- | --- | --- |
| **接口开放依赖**（最大风险） | 模块五、七的大部分功能依赖在建平台开放云台控制、无人机调度、工单下发、数据查询等接口，接口不到位则功能无法交付 | 立项前形成《接口开放清单》，逐项明确协议、范围、开放时间，作为合同附件 | 采购人牵头，在建平台承建单位配合 |
| **样本冷启动** | 垂钓、偷捕样本稀缺，部分点位无补光导致夜间识别失效 | 采用迁移学习冷启动＋一线处置结果自动回流标注；先行盘点点位成像条件，补充补光或红外设备，或对该类点位调整识别策略 | 承建单位＋各湖区管理机构 |
| **验收指标不可量化** | "识别准确""研判智能"等表述无法验收 | 逐项设定可测指标，并按试运行期/运行6个月分阶段设定目标值 | 采购人与承建单位在合同中约定 |
| **大模型合规部署** | 标书要求等保三级、全栈信创国产化、密码应用安全性评估 | 大模型底座选用国产模型，部署于政务云内网，数据不出域；向量模型同步选用国产方案；建设期同步开展等保测评与密评 | 承建单位，采购人组织测评 |
| **运营成本未列支** | 大模型API调用费属持续性运营成本，不在本次建设采购范围 | 在项目运营预算中单独列支；设置调用配额与结果缓存控制成本；优先依托江苏省政务云已有大模型资源 | 采购人 |
| **AI责任边界** | AI参与执法研判，责任归属需明确 | 固化"AI只出建议、人工作决定"原则，全链路留痕并区分责任主体标识；由法制部门书面确认边界 | 采购人法制部门 |
| **重复建设质疑** | 模块六、七、八、十与标书已建内容有交集 | 在方案与合同中对67项功能逐条标注"复用/深化/新增"，本报告第四章已完成该标注 | 承建单位 |
| **采购程序** | 本次为原招标采购需求之外的新增事项 | 需由采购人会同财政、发展改革部门确认适用的变更或新增采购程序后再行推进；标书明确合同不得转包、未经采购人同意不得分包 | 采购人 |
| **实施周期衔接** | 在建项目总工期12个日历月，已进入中后期 | 尽快决策，并与在建项目进度对齐；视频级联通道先行打通，避免"通道等模型" | 采购人 |
