# 长江流域重点水域禁捕执法装备设施建设项目

## AI智能体新增事项——建设内容可行性分析与子功能模块清单

（配套《AI智能体新增事项可行性分析报告V5》，用于向领导汇报与评审说明）

---

## 一、一页读懂

**一句话说清这次要干什么：**

在建的平台解决的是"**看得见、传得回、流程能走通**"；这次新增的AI智能体，解决的是"**看得懂、判得准、派得对、越用越准**"。两者是上下两层的关系，不是重复建设。

**举个例子，同一条预警，前后是这样的：**

| 环节 | 现在（在建平台） | 加了AI智能体之后 |
| --- | --- | --- |
| 发现 | 摄像头拍到岸边有人，系统弹出一条告警 | 同上（复用现有设备与告警） |
| 看懂 | 人工点开视频看：是钓鱼还是路过？ | AI自动识别持竿、抛竿动作，判定"正在垂钓"，并给出证据截图 |
| 研判 | 人工翻法条、翻案例，判定违法等级，耗时以"天"计 | AI自动检索法规和裁量基准，输出违法等级与处罚幅度建议，附完整依据，分钟级 |
| 派单 | 人工打电话找人，人工填工单 | AI自动算出最近的执法艇和人员，生成派单，盯签收 |
| 归档 | 人工回填表格 | 移动端回传自动归档 |
| 提升 | 模型不动，明年还是这个准确率 | 处置结果（正报/误报）自动回流训练，系统越用越准 |
| 负责 | 人工全程负责 | **AI只出建议，最终决定仍由执法人员作出并签字负责**（本次专设"人机协同与安全合规"模块保障） |

**总体可行性结论：**

10大模块67项功能，**全部技术可行**，其中：

- **6个模块为标书完全没有的新增能力**（多智能体协作、任务规划与自主决策、记忆管理、知识库与RAG、工具调用与执行、人机协同与安全合规）；
- **4个模块是在标书已建能力之上的深化**（视频智能识别、执法调度与派单、NL2SQL智能报表、智能巡查），**不重建底座、不重复采购硬件**，需在方案中逐项标注"复用/新增"以规避重复建设质疑；
- **3项前置条件必须先落实**：① 在建平台的接口开放清单与时间表；② 大模型的国产化部署与等保、密评合规路径；③ 视频识别的冷启动样本来源与分阶段验收指标；
- **1项成本必须单列**：大模型API调用费属持续性运营成本，不在本次建设采购范围内。

## 二、判断依据：标书里已经有什么、还缺什么

本次可行性判断，逐条比对了标书《第四章 采购需求》的全部建设内容。标书已建成的能力如下：

| 标书已建能力 | 具体内容（摘自第四章） | 对本次AI智能体的作用 |
| --- | --- | --- |
| 智能预警子系统（22项） | 视频巡逻、雷视联动、智能分析、无人机联动、AIS、船舶汇聚等6类预警识别；预警规则配置；预警研判（人工）；预警取证；预警闭环处理；预警统计 | 提供告警来源和"预警—研判—签收—处置—审核"流程壳，AI在既有节点上接入自动研判 |
| 重点人员管理子系统（16项） | 人脸库、识别预警、布控管理、态势感知、事件档案与事件分析 | 提供重点人员画像的底层数据，AI不重复采集 |
| 巡查执勤处置子系统（14项） | 工作台、任务创建与流程配置、巡查路径管理、视频巡查、图片巡查、任务签收/调度/反馈、移动端 | 提供巡查业务流程与"苏农云"移动应用基座，AI不另建APP |
| 指挥调度子系统 | GIS地图、融合通信、执法力量实时位置与调度 | 提供AI派单结果的执行通道 |
| 业务能力中心 | 事件中心（接收/联动/处置/预案/参数配置）、报表引擎、地图服务 | AI工具调用与事件回写的对接点 |
| 数据能力 | 数据源接入、工作表、业务建模、驾驶舱、近30种图表类型、大数据存储与计算引擎 | NL2SQL的数据底座与图表渲染层，AI不重建BI |
| AI中台 | 人脸/人体/车辆/船只属性识别、区域入侵、视频结构化；算法调度（弹性伸缩、分时复用、倍速分析等）；算法仓库；算法策略编排；渔船捕鱼、人员垂钓、船舶非法入侵、船只种类、漂浮物、水位6类场景算法 | 提供算力调度与基础识别算法，AI智能体在其上做动作级、夜间、多人、跨点位的精度增强 |
| 系统对接 | 苏农云服务总线、省海洋渔业安全监管系统、公安"雪亮工程" | 跨系统工具代理的通道 |
| 多元联合感知平台 | 雷达、AIS、北斗、视频、无人机、船载、单兵执法记录仪、甚高频8类数据接入 | 多源融合研判的数据来源 |
| 硬件设备 | 双光谱重载云台32台（热成像640×512、激光补光≥3km）、全固态雷达12台、网络硬盘录像机32台（内置GPU、**支持视觉大模型导入与第三方算法插件导入**）、无人机5架、船载主机112台 | 视频识别与工具调用的物理载体，**本次无需新购算力硬件** |

**标书还缺什么（也就是本次要补的）：**

1. 缺"会思考的大脑"——标书的AI中台管的是"算法怎么调度到GPU上跑"，没有"业务上谁来拆任务、谁来做判断"；
2. 缺"记忆"——每条预警都是独立处理，系统不记得这条船、这个人以前干过什么；
3. 缺"法律知识"——法条和裁量基准没有进系统，研判全靠人工翻;
4. 缺"动手能力"——识别归识别，识别完不能自己去调云台、发工单、写文书；
5. 缺"自我进化"——模型训练完就固化了，一线处置结果不会回流；
6. 缺"AI管控机制"——AI进入执法环节，谁负责、怎么留痕、错了怎么兜底，标书里没有对应条款。

## 三、可行性总体判断（五个维度）

| 维度 | 判断 | 说明 |
| --- | --- | --- |
| 技术可行性 | **可行** | Multi-Agent协作、RAG检索增强、NL2SQL、视频行为识别均已有成熟开源框架与商用方案，属工程集成，不属算法攻关。67项功能中无一项依赖未验证技术 |
| 业务可行性 | **可行** | 全部功能均对应标书已明确的业务场景与用户角色，无凭空设想的新业务；AI承担的是"建议"角色，不改变现有执法权责体系 |
| 合规可行性 | **可行，有前置条件** | 大模型须选国产底座、部署于政务云内网、数据不出域，方可满足标书要求的等保三级、信创国产化与密评；AI输出须经人工确认后方可作为执法依据，需法制部门书面确认边界 |
| 衔接可行性 | **可行，需明确接口清单** | 采用增量叠加、不重构原系统的方式建设。最大依赖项是在建平台的接口开放（云台控制、无人机调度、工单下发、数据查询等），建议将"接口清单+开放时间表"作为前置条件写入实施计划 |
| 投资可行性 | **可行，需单列运营费** | 710人天、142万元建设费用不含大模型API调用费。按V5报告测算，正常运营约9000元/月；若依托江苏省政务云已有大模型资源，该费用可由政务云统一承担 |

## 四、10大模块建设内容详解与子功能模块清单

> 说明：下列每个模块先用一段话讲清"这个模块到底干什么"，再列出可交付、可验收的子功能模块。"与标书关系"一栏中：**新增**＝标书无对应内容；**深化**＝标书有基础能力，本次做精度或场景增强；**复用**＝直接调用标书已建能力，本次不重复建设。

### 4.1 模块一：多智能体协作框架（7项功能 / 29个子功能模块）

**这个模块干什么：** 相当于给平台配一个"AI执法专班"——一个班长带五个专业组员。班长（监督调度Agent）接到任务后负责拆活、派活、盯进度、处理异常；五个组员各管一段：看视频的、做研判的、派任务的、审案卷的。以前这些活全靠人在各个模块之间来回切换，现在由AI在后台自动串起来。

### 4.2 模块二：任务规划与自主决策（7项功能 / 27个子功能模块）

**这个模块干什么：** 让系统"听得懂人话、拆得开活、拿得准主意、拿不准会举手"。领导说一句"这周末重点盯洪泽湖夜钓"，系统能自己理解成一组具体任务并安排下去；同时给每个判断打一个"把握度"分数，把握不足的自动交回人工，绝不硬着头皮下结论。

### 4.3 模块三：记忆管理系统（8项功能 / 32个子功能模块）

**这个模块干什么：** 给AI装上"记事本+档案柜"。现在每条预警都是"从零开始处理"，系统不知道这条船上个月刚被查过、这个人是三次违规的老面孔。有了记忆，AI就能把孤立的事件串成线索，把"一次处置"变成"持续管控"。

| 序号 | 功能模块 | 子功能模块 | 建设内容说明 | 与标书关系 |
| --- | --- | --- | --- | --- |
| 15 | 短期记忆 | 多轮会话上下文管理 | 记住对话中的前几句，支持追问 | 新增 |
| | | 任务临时变量池 | 任务执行过程中的中间结果暂存 | 新增 |
| | | 待办与挂起事项 | 记录尚未完成、等待条件满足的事项 | 新增 |

2. **与标书的算法不重复。** 标书"AI中台—算法场景适配服务"已含人员捕捞钓鱼、渔船捕鱼、船舶非法入侵、船只种类4类算法，其判定逻辑是"坐姿＋遮阳伞＋钓竿＋渔具桶＋滞留30分钟"这类**组合规则级**识别；本模块新增的是**动作级、夜间、多人、跨点位、状态细化**能力。建议在合同与方案中统一表述为"在已建算法基础上的精度与场景增强"。
3. **验收指标建议分阶段设定。** 冷启动阶段样本稀缺是客观事实，建议约定：试运行期主要场景查准率≥85%，运行6个月（经处置结果回流训练后）≥90%，而不是一上来就承诺一个高指标。

**前置条件：** 先行盘点各点位夜间成像条件（补光/红外覆盖情况），对不满足的点位补充补光设备或调整识别策略；同时明确冷启动样本的来源与标注责任方。

## 七、实施建议

**建议一：调整建设顺序，把"安全合规底座"前移。**

V5报告原实施路径以"大模型基座＋知识库＋研判Agent"起步。建议将**模块九（人机协同与安全合规）**中的推理链留痕、责任主体标识、人工兜底、全链路审计四项一并放入第一阶段。理由是：这些是AI进入执法环节的准入条件，如果放到最后建，前面所有阶段的试运行成果都可能因不满足审计和责任要求而无法投入实际使用。

**建议二：把《接口开放清单》作为立项前置条件。**

模块五、七能否落地完全取决于此。建议在立项文件中附一份清单，逐项列明接口名称、提供方、协议、开放时间，由采购人牵头协调在建平台承建单位确认。

**建议三：验收指标逐项量化，并分阶段设定。**

避免"智能化""准确"等无法验收的表述。重点是三类指标：视频识别的查准率查全率（分阶段）、研判环节的平均耗时（从天级到分钟级）、AI建议采纳率（衡量AI实际水平的最直接指标）。

**建议四：大模型API费用在运营预算中单独列支。**

按V5报告测算，正常运营约9000元/月，满负荷约3.6万元/月。若能依托江苏省政务云已有大模型资源，该费用可由政务云统一承担，本项目无需另行采购。

**建议五：方案报送时附"复用/深化/新增"对照表。**

本报告第四章已对67项功能逐条标注。建议将第五章汇总表和各模块的"与标书关系"栏一并纳入报送材料，主动说明与在建平台的边界，是应对重复建设质疑最有效的方式。
