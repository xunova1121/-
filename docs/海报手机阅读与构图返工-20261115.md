# 海报手机阅读与构图返工（2026-11-15，北京时间）

状态：用户已要求修复后统一发版。当前为候选，尚未发布；稳定通道仍为1.0.440。此文后续补实际CI与公开安装包核对结果。

## 原因与边界

用户附件《帮我写一个网页.md》显示，11月15日13:48的科技电商风海报已经产出`.design.json`，不能把问题说成没走分层。记录同时显示：未央多次误称不能自由布局，绕去手改SVG并因外链图片导出失败，最后将大主视觉与七条小字列表合成。用户截图还能看到空胶囊卡片，正文在手机上明显太小。

附件没有完整工具参数和源文件，不能宣称已核实该稿每处原始字号或具体生图提示。源码确认的缺口是：短追问省略海报关键词时不一定加载海报方法；缺少按观看宽度检查字号；视觉核验未专门检查缩图、空框和生硬拼接。原文/字体/几何/对比通过不等于设计效果合格。

## 修改

- `posterFollowup.js`：最近话题确为海报时，换结构/再做个类似的/没合成等短追问补本轮能力提示。原用户文字和历史不修改，新话题、禁止执行和问原因不承接；`agent.js`只接此入口。
- `imageCompositionPrompt.js`：准确中文海报/同稿视觉Demo调用生图时，执行层补`poster_art`用途，向原服务的一次请求追加禁文字、新闻列表、按钮和空卡片要求。明确让模型直接画字仍遵从原要求，不加生图次数，也不承诺服务必然遵守提示。
- 分层协议增加`campaign/timeline/newspaper`结构和`reading`场景，保留`free+layers`自由坐标，旧`.poster.json/.visual.json`不迁移。说明、技能和回执明确工具真实能力，换色不算换结构。
- `layeredStoryLayout.js`先按原文测行高，再分配栏目和插图空间，可在双栏/通栏间选择。放不下就说明需增高、减少主视觉或拆版，不删字、不无限缩字。时间轴/报纸原图可放页眉，资产不丢。
- `layeredDesignPresentation.js`：新竖稿默认phone，整张按390px宽度检查正文12px、主标题18px、标签8.5px、底注7px；正文ID不因误标caption逃避检查，整版背景图与独占大主视觉区分。横稿默认desktop，按不超过1440px宽度检查，可明确改阅读场景。旧稿未声明场景则not_checked，不冒称通过。
- 手机稿实际导出`.phone.png`，是原构图缩图，不用Demo另排卡片替代。同一次视觉核验可同时收到原图和缩图，检查空框、图文比例和可读性，仍只用一次模型额度。
- 阅读失败返回`DESIGN_PRESENTATION_UNREADABLE`，整体保持partial。候选保留、改稿另存，预览也参与输出名互斥，避免`foo.phone.png`与另一稿主PNG冲突。原图摘要、账号隔离、源稿/快照完整精度保留。
