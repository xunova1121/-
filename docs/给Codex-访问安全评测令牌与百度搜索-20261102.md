## 第一部分：登录安全加固（`server/serverMode.mjs`、`src/core/serverClient.js`、设置页）

### 现状问题（Claude 已读代码确认）

1. **凭证永久有效。** 登录凭证是 `tokenFor(password)`，即 sha256（固定前缀 + 密码），永不过期、不能单独收回。设备登录过一次就能永久使用；只能改密码让所有设备一起失效。
2. **凭证可放在网址里。** `authorized()` 接受网址参数 `?token=`，凭证可能进浏览器历史和 Nginx 日志。
3. **猜密码的限流可能被绕过。** 限流按 `x-real-ip` 请求头计数，这个头可以由客户端伪造：只要 Nginx 没有强制覆盖，就能无限次猜密码。
4. **没有总量限流，也看不到谁在登录。**

### 要改的

1. **每台设备一个会话令牌。**
   - 登录成功后发随机令牌（32 字节以上），服务器只存它的哈希。
   - 每个令牌记录：设备名（UA 摘要）、IP、创建时间、最后使用时间。
   - 令牌 30 天不用自动失效；有使用就顺延，但从创建起最长 90 天。
   - 设置页显示“已登录设备”列表，可以踢掉单个设备，也可以“退出所有其他设备”。
   - 访问密码（环境变量里的）改了之后，所有旧令牌全部失效。
   - **兼容：** 旧版客户端存的是 `tokenFor(password)`。升级后第一次请求时，用旧令牌换发一个新的设备令牌（只换一次，并记录日志）；旧格式令牌的这条兼容路径保留 14 天后移除。必须有测试：手机、电脑在升级后无需重新输密码即可继续使用。
2. **去掉网址里的令牌。**
   - 普通接口一律只认 `Authorization` 请求头。
   - SSE 和文件下载等确实需要放在网址里的，改用**一次性、60 秒有效、只对该资源有效**的短期票据，不能用会话令牌本身。
   - 逐个排查 `?token=` 的使用点，并加测试：会话令牌放在网址里一律返回 401。
3. **限流可靠。**
   - 只有当请求来自 127.0.0.1 / ::1（即本机 Nginx 转发）时才信 `x-real-ip` / `x-forwarded-for`；否则用 socket 地址。
   - 保留每 IP 10 分钟 5 次错误的限制；另加全局限制：1 小时内错误满 20 次，所有 IP 都锁 1 小时，并在设置页提示“有人在尝试密码”。
4. **新设备登录提醒。** 新设备登录成功后，给已登录的设备推一条通知（沿用现有任务通知通道）：“新设备登录：时间、IP、设备”，旁边带“踢掉”按钮。
5. **弱密码提醒。** 服务启动时如果访问密码少于 12 位或过于简单，在设置页显示红色提醒，教用户改 `/opt/jarvis/jarvis.env`。**程序不改密码。**

## 第二部分：评测专用令牌（`server/serverMode.mjs`、`server/taskRunner.mjs`、`evals/`）

1. **令牌管理。**
   - 设置页（仅主人可见）可以生成评测令牌，生成时设定：名称、有效期（默认 7 天，最长 30 天）、每日次数上限（默认 200）。
   - 令牌明文只在生成时显示一次，服务器只存哈希；可以随时作废。
   - 列表显示每个令牌的已用次数和最后使用时间。
2. **权限：只能发起评测会话。**
   - 能用：创建或读取带 `evaluationId` 的任务和会话，并看到它们的事件流。
   - 不能用：读取或修改设置、Key、记忆、用户的正常对话、文件、代码仓库，更新服务器，管理令牌，定时任务。
   - 以上每一类都要有测试，用评测令牌调用时返回 403。
3. **隔离。** 沿用现有评测隔离（`evaluationScope`、`memoryLookupStorage`、会话列表过滤 `evaluationId`）：
   - 用评测令牌发起的任务**强制**带 `evaluationId`，客户端不能去掉；
   - 不写入用户的长期记忆和缓存；
   - 不出现在用户的对话列表里。
4. **限额。** 超过每日上限返回 429 并写明原因；模型调用次数、搜索次数都计入。
5. **评测脚本。** `evals/` 下的服务器评测脚本改为从环境变量 `JARVIS_EVAL_TOKEN` 读令牌，不再需要访问密码。README 写清：令牌在设置页生成，填在跑评测那台机器的环境变量里，**不要提交、不要贴进聊天**。

## 第三部分：百度千帆搜索（`src/agent/webSearch.js`、设置、服务器配置）

### 接口

- `POST https://qianfan.baidubce.com/v2/ai_search/web_search`
- 请求头：`Authorization: Bearer <Key>`；Key 来自服务器配置。
- 请求体按官方文档：`messages`（用户查询）、`resource_type_filter`（只要 `web`，`top_k` 默认 10，可配 5～20）、`search_recency_filter`、`search_filter.match.site`、`search_filter.range.page_time`、`edition`。
- **字段解析以官方文档和真实返回为准。** 先在测试里写一份脱敏的结构样例，不放真实 Key；用户填 Key 后，在服务器上抓一次真实返回核对字段名，不一致就改，并把核对结果写进执行记录。

### 接入方式

1. **配置。**
   - 新增 `qianfanSearchKey`：服务器配置、本机配置和设置页都要有，标签“百度千帆搜索 Key”，说明“国内搜索，按次计费；只填在服务器设置里”。
   - 服务器返回配置时打码，并在 `keep()` 合并逻辑里保留旧值（照 `bochaKey` 的处理方式）。
   - 本机经网关时，加上游白名单 `qianfan: https://qianfan.baidubce.com`（参照 `EXTRA_UPSTREAMS`）。
2. **搜索顺序。**
   - 中文和国内问题：千帆 → DeepSeek Search → 博查 → 免密钥抓网页（Tavily 放最后，用户没用）；
   - 英文和国外问题保持现状，千帆放在 DeepSeek 之后。
   - 千帆出错（5xx、超时、401/403/429）时，熔断 3 分钟，并自动换下一家（照 `deepseekSearch.js` 的熔断写法）；401/403 在设置页提示 Key 有问题。
3. **时间与站点筛选（准确性的关键）。**
   - 今日新闻、实时比分、“今天/刚才/最新”类问题：`search_recency_filter` 设为最近一天（取值以文档为准），或用 `page_time` 卡北京时间当天范围。
   - 体育资讯、普通新闻：最近一周。
   - 一般问题：不限。
   - 用户点名某个网站（“直播吧上的”“新华网”），或现有来源注册表里有这一类的指定来源时，用 `site` 过滤。
4. **结果规范化。**
   - 统一成 `{ title, url, snippet, publishedAt, source: 'qianfan' }`。
   - `publishedAt` 换成北京时间；拿不到日期的，**不能**填当天，留空并标“日期未知”。
   - 按网址去重（去掉跟踪参数后比较）；摘要里的 HTML 实体、空白清理干净。
   - 回执标“（百度搜索摘要，未读原文）”，与现有的 DeepSeek 标注一致。

### 搜索结果准确性（用户最关心，验收最严）

1. **日期把关。** 用户问“今天”时，日期不是北京时间当天的结果，或日期未知的结果，不能当作今天的事实说出来。只能放进“可能相关、日期未核实”。原有今日新闻的筛选逻辑（`lookupDelivery`、`answerConstraints`）对千帆结果同样生效，要加测试。
2. **旧闻过滤。** 11 月 1 日真实问题：把台风延期的旧微博、其他轮次的赛果当成今天的结果。必须加测试：
   - 结果里混入一条去年和一条上个月的“比分”，问“今天中超比分”时都不能出现在答案里；
   - 带日期的标题（如“2026年8月10日”）与问的日期不符时要过滤。
3. **优先权威来源。** 同一件事有多条结果时，官方、主流媒体排在自媒体、聚合页、问答站前面。用现有的来源注册表和白名单打分，不新造一套。
4. **摘要不冒充原文。** 要核实的数字、表态，仍用 `fetch_url` 读原文后再说“已核实”。
5. **设置页“测试搜索”按钮**（现有 `/api/server/search-test`）。
   - 加上千帆。返回内容：用的是哪家、耗时、条数、前 3 条的标题、日期、域名。
   - Key 错、额度用完、网络不通要分别说清，不能都显示成“失败”。
   - 页面上显示的结果必须是真实返回，不能用缓存或假数据凑。

### 顺带修：DeepSeek Fetch 读原文只等 2.5 秒

`src/agent/pageReader.js` 里 DeepSeek Fetch 的超时是 `timeoutMs: 2500`，太短；DeepSeek 要先替我们打开对方网页。很可能是“原文链接均未能打开核对”的原因之一（推断，未在服务器验证）。

- 改为 8 秒；仍受本轮总时间和读预算约束。
- 加测试：DeepSeek Fetch 6 秒返回时能拿到正文，不再退回直接读取。

## 测试（只加不删）

**单元测试：**
- 会话令牌的签发、过期、顺延、踢除、“全部退出”，以及改密码后全部失效；
- 旧客户端令牌换发：只换一次，14 天后拒绝；
- 网址里带会话令牌返回 401；短期票据只能用一次、60 秒后失效、换个资源就无效；
- 只在 Nginx 转发时才信 `x-real-ip`；伪造的 `x-real-ip` 绕不过限流；全局锁；
- 评测令牌：每一类越权调用都返回 403；强制带 `evaluationId`；超额返回 429；过期、作废后返回 401；
- 千帆请求体：top_k、recency、site 是否正确；字段解析；日期换成北京时间；去重；熔断后换下一家；
- 日期与旧闻过滤（上面列的真实案例）；
- DeepSeek Fetch 8 秒超时。

**端到端（加入发布工作流）：**
- `e2e/server-auth.mjs`：
  - 真实浏览器登录；
  - 第二个浏览器上下文登录，第一台收到新设备提醒；
  - 踢掉第二台后，它请求返回 401；
  - 模拟旧客户端令牌，升级后无需重新登录；
  - 评测令牌发起评测会话成功，读设置返回 403，用户对话列表里看不到这次评测。
- 千帆用本地假服务器（拦截 `qianfan.baidubce.com`）跑一遍：设置页“测试搜索”显示正确；断网和 401 时显示正确的说明。
