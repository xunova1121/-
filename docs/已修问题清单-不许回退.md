## 一、动手前必须做的（硬规定）

1. **先拉最新代码再动手**：`git fetch origin claude/jolly-darwin-tijh97 && git merge origin/claude/jolly-darwin-tijh97`。
   不要在旧的本地副本上改完直接推，那会把对方这期间修的东西冲掉。
2. **只用合并（merge），不要变基（rebase）、不要强推（force push）。**
3. **不要整文件覆盖**：不要用“自己以前的版本”或“新写的整份文件”替换现有文件。只改要改的那几处。
   重写一个模块前，先把旧文件从头到尾读一遍，把下表里落在这个文件上的行为一条条带进新写法。
4. **提交前看一遍自己删掉了什么**：`git diff --stat`，再看 `git diff` 里所有以 `-` 开头的行。
   删掉的代码，如果属于下表某一条，必须保留或在新写法里实现，并说明原因。
5. **测试只许加，不许删、不许跳过、不许为了通过而改松。** 下表每条都有守护它的测试；测试挂了说明你把这个修复弄丢了，要修代码，不是改测试。
   确实是有意改变行为，在交接文档里写明改了哪条测试、为什么，并告诉用户。
6. **改界面时**：下表“界面”部分的行为（动画、转圈、按钮）不能因为换样式就消失。改完跑 `node e2e/mobile-theme.mjs`、`node e2e/mobile-ui.mjs`、`node e2e/smoke.mjs`。
7. 修了新 bug，**把它加到下表**（现象、原因、改在哪、哪个测试守着），并补测试。
