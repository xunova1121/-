# 交接给 Codex：过度核实、Excel 重复行、记忆自动核实（2026-10-21，Claude）

依据：用户导出的真实对话（南京亲子游行程表、Plan B 更新、“记住这个教训”）。

## 一、过度核实 / 口头完成
- `selfCheck.js`：待查、待补充、待确认、待定、TBD 改为 warn（如实标注，可交付）；XXX、TODO、此处填写 仍是 error。
- `executionReview.js`：
  - 失败回执只算改东西、跑测试的操作；查资料失败不算。后来同一工具又成功了，算已解决。
  - `verified(path)` / `rereadBlocked()`：文件验过可用后，只再放行一次读取；改过文件后作废重来。
  - 新增 `memory` / `memoryChecked`：用户要求记住时必须有成功的 remember 类回执；问“记住了吗”时必须先 recall。
- `agentToolExecution.js`：超过次数的重复核实不执行，直接返回“已核实过”。
- `agent.js`：非代码任务收尾核对最多 1 次（写代码仍 2 次）；核对消息开头注明“系统自动核对，不是用户说的话”。
- `taskContract.js`：“更新到 / 写进 / 填入… Excel”算要交文件；新增 `remembering` / `askingMemory`。

## 二、Excel 重复行
- `xlsxWriter.js`：
  - `duplicateRows` / `dedupeRows`：比较整行（序号列不算），也认“一行填了的格子另一行都有”；不按单列判断。
  - 重新生成时自动去重；表里有公式时不删行，只提示。
- `spreadsheetEdit.js`：局部改表后，改到的行和别的行重复就整批不保存，提示把多余行清空（Plan B 行数变少时会残留旧尾行）。

## 三、记忆：自己核实、自己转正、自己整理（用户确认的方案）
- `reflect` 要求模型给出用户原话（quote）。`saveFacts` 在用户原话里核对，核对上直接生效；没有原话的只当线索（pending）。
- 离线规则从原话直接抠出的直接生效；“我是……”容易误抓，仍只当线索。
- 线索在另一段对话里又被总结出来，自动转正，并取代冲突的旧值（`sessionId` 记在记忆上）。
- `maintain`：线索 30 天没再证实就归档；有模型时每天最多 `consolidate` 一次。
  - 合并：最多 5 组。
  - 矛盾替换：最多 5 条，必须是更新的那条取代旧的。
  - 钉住的、写作偏好不动；注入检查照旧。
- `revert(id)`：撤回自动替换或合并，恢复旧条目。面板去掉“核实并启用”，加“↶ 撤回”。
- `remember` 新增 category `lesson`，存进经验教训；`recall` 也查经验教训。
- 本机在 `background.js` 反思后调用 `maintain`；服务器在 `taskRunner.mjs` 反思后调用。
