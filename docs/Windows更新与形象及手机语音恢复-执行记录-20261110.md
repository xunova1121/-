## 现象与已确认依据

- 用户Windows截图显示1.0.382，检查更新访问`xunova1121/-/releases.atom`返回404；不是新版415已安装。当前代码虽然有公开仓库失败兜底，但安装包元数据仍是旧仓库，第一次请求仍先失败。
- 1.0.415官方Windows ZIP内app.asar的build/icon.png及EXE的7档内嵌图标已经是水蓝金色确认形象。旧logo.svg与本次从mascot-approved首格导出的RGBA逐像素相同，不能凭10月25日文件日期判断图标过旧。用户旧客户端本机快捷方式/任务栏缓存未直接检查。
- 电脑主页、全息/桌面陪伴确实引用mascot-companion；手机专用样式才覆盖为mascot-approved。旧默认尺寸还是3:4，会压扁4×3正方形图集。
- 手机“点开语音说话无反应”未在用户真机复现。代码可复现问题：系统识别连续空结果静默循环；系统服务存在但不回收音状态时长时间假等；恢复函数总创建RecordedVoice，遇Qwen实时配置会错误调用文件转写并报错；异步授权在挂断后返回可能重开采集。

## 最终改动

1. desktop/updater从第一次检查使用公开发布仓库，desktop/package.json同步安装包更新元数据。错误提示提供固定官方发布页入口，不输出GitHub原始鉴权提示或要求填写模型Key；原安装包校验和安装条件保留。
2. 三端共用已确认图集及动作位置；PC比例改为正方形。保留手机顶栏不移动的点击设计、减少动效、后台暂停、启动动画的独立节点。没有重新设计或生成角色。
3. make-icons从同一素材首格生成SVG和16张安装资源，--check只读比较解码像素及来源hash。部分PNG重新编码，不代表形象发生变化。
4. 识别器选择抽到voiceInputFactory。系统自动模式优先策略保留，系统失败后选择正确的实时/文件协议，只尝试一次云端恢复。听写也支持同样恢复。挂断先失效本次输入请求，迟到回调不能结束或重新开启新通话。
5. NativeVoice按真实ready/speech/processing回调显示阶段；8秒无启动回执、35秒无结果退出，连续3次空结果明示检查麦克风并按配置恢复。取消系统窗口、权限拒绝均不擅自重录。RecordedVoice增加无PCM和转写超时处理，不无限busy。
