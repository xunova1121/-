# 多用户绑定与并发对话执行记录（2026-11-04）

用户授权：先做稳定 ID 绑定、私有数据归属，支持多人同时对话。开发前已 fetch 并合并 `claude/jolly-darwin-tijh97`，基线为 `4879384`（1.0.395 发布记录）。已在分工文档登记需要修改的共享状态接缝。

## 本版行为

- 主人用原来的密码和设备登录；原数据仍在原目录，无批量迁移，不改 `jarvis.env`。
- 设置 → 服务器 → 用户绑定与数据归属：主人添加成员，得到只显示一次的个人访问码。本人手机和电脑在原密码栏填同一码，设备令牌不同、用户 ID 相同。访问码只保存 SHA256 摘要，随机熵为256位；界面关闭或进入后台清空临时显示。
- 成员不能管理其他用户、修改共享模型或更新服务器。主人可以停用、重新启用、重置访问码；停用/重置撤销旧设备和下载票据，停止该成员的任务，保留其数据。
- 模型与查询工具配置由管理员共享；模型能力表只读。GitHub 账户及仓库授权不共享，成员连接自己的账户。
- 成员数据位于 `users/<服务器生成ID>/`；对话、文件及版本、知识库、记忆、提醒、代码项目、任务日志/进度等以服务端认证身份选择存储。请求正文的 `userId` 或 `role` 无权改变归属。
- 工作区、缓存和后台整理同样按身份隔离。手机/电脑的本地附件数据库、模型配置、对话缓存按成员与服务器分开；主人旧缓存保持原位置。
- 管理员添加用户时可以设同时执行数，默认建议2，范围1～4，存在配置文件中；不改环境文件。未设置界面值时沿用已有 `JARVIS_MAX_TASKS`。每人同时执行1项，额外会话排队；用户之间轮流获得执行槽位。每人最多20项活动任务，任务内存记录总上限1000、完成记录2小时后清理。
- 第一期最多50个成员身份（停用身份保留）。不含团队共享空间、计费或公开自助注册。

## 根因与实现核对

旧服务把设备会话一律视为主人，多个设备共用数据目录；队列只按会话 ID 加锁，知识库、习惯等存在全局缓存。单加 `userId` 字段无法阻止串数据。

新 `userScope` 用 AsyncLocalStorage 绑定已认证用户，文件后端按身份选择；排队任务执行、停止与异常收尾重新进入任务自己的上下文。集合绑定返回真实后端对象，延迟刷盘不能随着当前请求换用户。评测空间沿用原来独立规则。

核对了：知识检索缓存、记忆模型/向量回调、习惯缓存、证据延迟写盘、成果队列、删除确认清单、架构恢复锁、查询健康/最近可用结果、图库缓存，以及项目工作副本、技能运行器和后台提醒。没有使用全局后端切换实现并发隔离。

下载票据新增了成员身份绑定，并统一查询参数编码：含目录斜杠/中文路径的下载，签发与核验保持一致。未知成员 API 默认拒绝。
