`jarvis/evals/joint-cases.mjs`（`joint-30-v1`）。

## 记什么
| 项 | 在哪 |
|---|---|
| 每次模型调用：用途（主回答 / 拿到工具结果后接着做 / 收尾核对 / 被核对拦下重写 / 时限整理 / 备用模型 / 工具内写作 / 推理 / 看图 / 文档审稿 / 后台记忆）、型号、耗时、Token | 服务器 `shared/taskTiming.js` 的 `calls`；Token 来自服务商返回，没给就是 null，不当 0 |
| 时间拆分：排队、模型、工具、整理上下文、其他 | 报告每次运行的 `metrics.split` |
| 重写是哪条核对规则触发的 | `rewrites`（style_claim、care_deferral…） |
| 后台记忆、重试、备用模型、分身 | 单独计数 |
| 费用 | 给了价格表（元/百万 Token，按模型名）才算；不编价格 |
| 每题跑两次 | 两次一过一不过、总分差 ≥4、某项差 ≥2 → 标“不稳定” |
| 4 维 1～5 分 + 检查点 + 失败主因 + “说做到没做到” | 自动评审员按 `evals/joint-rubric.mjs` 的样例打分 |
| 文件读回 | 告示 / 改字号 / PPT / Excel 题：下载文件量字号、横线、页数、表头加粗，和要求对照 |
| 按类型、按模型分组，和上一轮逐题比，失败原因归类，运行条件（版本、模型、时间） | 报告 `summary`、`comparison`、`conditions` |

## 怎么跑（在未央服务器上用 root）
```
cd /opt/jarvis/current && bash evals/run-joint.sh
```
- 跑完给出三个文件：`摘要.md`（白话结果）、`校准打分表.md`（抽 10 题给你打分）、`report.json`（完整报告，含回答原文，别外传）。
- 可选环境变量：`JOINT_PRICES=价格.json`（算费用）、`JOINT_JUDGE=服务商::型号`（指定评审模型；默认能力表“推理”那一项）、`JOINT_PREVIOUS=上一轮report.json`、`JOINT_BASELINE=老30题report.json`。
- 价格表格式：`{"型号名": {"input": 2, "output": 8, "cached": 0.5}}`，单位元/百万 Token，按服务商官网填。

## 注意
- 第 22 题建的提醒测完立刻删掉。
- 第 28、29 题（代码）：服务器在评测会话里不给代码工具，所以这两题用普通会话跑，**会出现在对话列表里**，报告标 `isolated:false`；只在新分支改、不推送。没连测试仓库 / 没配浏览器镜像的记“环境未就绪”，不计分。
- 评审模型默认挑配置里和答题模型不同、看着最强的；还是同一个时报告会标出来（自己评自己可能偏高）。
- 评测会话不读你的个人记忆、旧对话、持仓、知识库和文档偏好（1.0.330 起），结果可复现。
- 建议白天跑：凌晨“今天的新闻”本来就少。
- 校准：你按打分表打完分（直接在对话里报给 Claude 也行），运行 `node evals/joint-calibrate.mjs compare report.json 校准打分.json`；平均差 1 分以内、通过一致 ≥80% 就算自动评审可信，以后主要看自动评分。
