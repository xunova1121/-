# 第2批第一项：只排版时保留用户正文

在1.0.305之后按既定顺序推进。本项不把偏好查询、Word固定页数、文件模板完整重排等后续事项写成已经完成。

## 实现范围

- 新增`documentPreservation.js`。明确要求只排版/正文不变时，从本轮`sessionId`对应用户原话绑定正文；自动选择只接受最近正文的Markdown标题边界，其他情况使用`read_task_requirements`原文编号。不能从助手旧稿或压缩摘要补位。
- 原话最多检查最近400条；正文上限12万字符，超限报类型化`DOCUMENT_SOURCE`而非截断。明确选择旧编号必须在本轮原话中指明，不接受模型静默回用更早版本。
- 已绑定的正文确定性传入Word生成器，禁用会改变正文的模型审稿。长文/专业起草入口对明确只排版Word任务返回可执行路由提示，避免绕过保护。
- 写入目标前检查实际DOCX主文档：原文段落、表格单元及代码文字须按顺序完整读回；缺图也不覆盖原目标。检查报告只保存来源编号、会话编号、摘要和计数，不保存原文副本。
- 正常写作、PPT原生门槛、同稿图形输出和图形恢复上限沿用原实现；不动`writingRoles.js`、main/mount、依赖或应用标识。

## 验收与限制

- 9项新单测（虚构资料）：错误旧稿干扰、已落盘当前正文、标题前业务文字、归档编号与会话隔离、旧编号拒绝、来源缺失不覆盖、表格/金额缺改、其他起草入口、停止和大小边界。
- 新增真实`e2e/document-preservation.mjs`，已接入原CI：实际工具组生成Word，经LibreOffice生成PDF，两份产物读取核对表格/金额/正文；视觉状态仍是未由视觉模型验收。
- 本地定向4文件23项通过，lint通过。完整回归与原E2E的最终结果另补，不提前声称通过。
- 第一轮完整本地回归：192文件中190通过，1696项中1694通过；失败为未修改的MCP移除重连等待超时和preSearch耗时1498ms超过原1000ms门槛。保留全部断言并单独复测；不将此整轮记作全绿。最终来源指令的否定边界随后补充，最终代码仍须完整CI验证。
- 初次本地完整测试主动停止：检查期间发现当前已落盘原文编号的边界，补回归后重新冻结测试；不能把中断整轮记作全绿。
- 本地原Office E2E和文档质量E2E中Word/PPT转换成功，Excel转换45秒超时；不改时限、不删测试，须继续排查/在原完整CI验证。新增正文保留真实E2E已通过。
- 当前仅覆盖会话中的用户原文本；上传DOCX的无损结构重排、任意“按偏好重做”的意图、字体细分偏好及Word固定页数协调尚未完成，不冒称所有Word问题已解决。真实模型、用户原始成品和真机未测。

## 规范第7节自查（非Claude独立审查）

1. 原文只在生成期间读取；不新增对话/检查点/localStorage正文副本。报告仅短元数据。
2. 新来源扫描400条，正文12万字符，沿用现有16项/10分钟生成缓存；无额外长期缓存。
3. 不按事件写盘；生成器沿用既有检查点和文档报告写盘。
4. 读取的是工具第二参数`sessionId`；不引用界面当前会话。
5. 来源库错误不吞；停止信号在读取/检查边界透传；没有新联网/检索预算异常处理。
6. 没有新增自动重试或模型请求；只排版反而绕过正文改写审稿。
7. 无新联网请求或模型调用，无新增扣预算路径。
8. 使用`DOCUMENT_SOURCE`及现有控制类型；不按异常文字猜原因。
9. 逻辑放在agent文档模块，新模块低于500行；现有模块仅局部修改，无整文件替换。
10. lint/定向/新增真实E2E结果如上；全量、构建与原门禁待记录。用户服务器、真实模型、安卓/Windows真机未测。
