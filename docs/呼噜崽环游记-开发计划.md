# 呼噜崽环游记 · 开发计划 v1.0

> 立场：**依恋是手段，习惯是目的。** 所有设计与排期决策服从这一条。
> 一旦依恋本身变成目的，产品就从「自律工具」滑成「披着自律皮的养成游戏」——那个赛道竞争激烈得多，且放弃了唯一的差异化。

## 相对初版计划的五处修订

| # | 修订 | 原因 |
|---|---|---|
| 1 | 新增**第 0 期**（主体、类目、版号、数值、美术需求） | 版号周期长于开发周期，不前置会整体阻塞 |
| 2 | 第一期**砍掉睡眠打卡与金币系统**，只验证「专注 → 旅行 → 合成 → 解锁」单链路 | 初版第一期金币无消耗出口，经济循环是断的；睡眠日频仅 1 次，验证效率低于番茄钟 5 倍 |
| 3 | **埋点从第四期提到第一期** | 无埋点的 MVP 验证不了任何假设 |
| 4 | 惩罚机制（离家出走 + 付费召回）改为**重逢叙事** | 愧疚驱动的留存在自律品类效果差且伤品牌 |
| 5 | 成本追加**美术与版号**，MVP 工期修正为 **8 周到灰度** | 初版漏算美术，而美术是本品类成本大头且是开发前置依赖 |

## 第 0 期：开工前必须做完的四件事（第 0 周，与美术并行）

### 0.1 主体与类目路线决策 ★阻塞项

微信小程序「游戏」类目不对个人主体开放，且带内购的游戏需要版号。必须二选一：

| 维度 | 路线 A：工具 / 效率类目 | 路线 B：游戏类目 |
|---|---|---|
| 主体 | 企业或个体工商户 | 企业 |
| 版号 | 不需要 | 需要（软著 → 版号，周期以月计） |
| 上线速度 | 快 | 受版号制约 |
| 变现 | 仅广告 | 广告 + 内购 |
| 定位 | 自律习惯养成工具，游戏化是激励层 | 养成游戏 |
| 主要风险 | 被判定「实为游戏」而整改下架 | 版号不批或超期，整个商业化落空 |

**建议**：先按路线 A 上线 MVP 验证玩法，同时按路线 B 并行送审版号，拿到后再切换。两条腿走路的额外成本只有软著 + 版号代办费。

### 0.2 版号并行启动（若走路线 B）
第 0 周即启动软著申请，不等开发完成。这是排期上最长的一根杆子。

### 0.3 数值表先行 ★阻塞项
在写第一行代码前完成 `economy.xlsx`（内容见 3.4）。数值表比页面设计更早决定这个游戏好不好玩。

### 0.4 美术需求书冻结 ★阻塞项
美术是 W1 起的前置依赖。第 0 周不启动，整个排期后移。

## 一、设计铁律（写进代码评审 checklist）

### 铁律 1：强化物绑**自律行为**，不绑**打开 app**
- 番茄钟完成的那一刻给反馈 → 训练「专注」。
- 每日打开就签到发奖 → 训练「打开 app」。

**因此第一期不做每日签到奖励。** 日活必须完全由自律行为产生。

### 铁律 2：习惯回路**确定**，乐趣回路才**随机**
- 打卡奖励必须可预期（专注 25 分钟 = 固定 10 呼噜币）——习惯形成依赖稳定反馈。
- 随机性只放在「旅行带回什么食材」「有没有触发隐藏配方」上。
- 把随机塞进打卡奖励，用户会去赌，而不是去自律。

### 铁律 3：每日内容有**终点**，产品主动赶人
食材有限 → 合成 3-5 分钟做完 → 小狗说「今天够啦」。
一个专注类产品最强的品牌资产是「**唯一一个会主动让我关掉的 app**」。这同时解决了核心悖论：不能用一个吞噬注意力的合成游戏去奖励专注。

### 铁律 4：**被需要感**取代惩罚
| 反例 | 正例 |
|---|---|
| 「你断签了，小狗离家出走」→ 被惩罚 → 逃避 → 流失 | 「小狗昨天在门口等了很久」→ 被需要 → 想弥补 → 回归 |

把小狗的**记忆**做成依恋的材料：它记得你连续陪了多少天，记得上次去的是丽江。记忆是最便宜也最强的依恋材料——一张历史表加几句文案。

### 铁律 5：**永不出售呼噜币**
呼噜币只能靠自律获得。一旦可以购买，产品的全部前提消失。第四期的内购只卖皮肤与装饰。

### 护栏指标（第一期即埋点）
| 指标 | 定义 | 红线 |
|---|---|---|
| 空转会话占比 | 打开但无任何自律行为的会话 / 总会话 | 周环比上升 10% 即预警：培养的是 app 依赖而非习惯 |
| 娱乐/自律时长比 | （合成 + 图鉴停留）/ 专注时长 | **> 1 即红灯**，产品已背叛定位 |

## 二、第一期 MVP

### 2.1 范围

**做**：微信静默登录 · 番茄钟发币 · 3 站点旅行 · 3 层合成 · 站点解锁进度 · 图鉴 · 全量埋点

**明确不做**：睡眠打卡 · 金币与售卖 · 家园 · 好友 · 广告 · 内购 · 多地图 · 每日签到

### 2.2 页面清单（6 页）

| # | 页面 | 核心元素 | 关键交互 |
|---|---|---|---|
| P1 | 首页 · 小狗 | 小狗立绘与状态、羁绊天数、呼噜币余额、今日专注进度 `0/4`、旅行入口、「开始专注」主 CTA | 点击小狗触发互动动画 |
| P2 | 专注计时 | 全屏计时器、小狗趴在旁边、退出二次确认 | `onHide` 超阈值判中断 |
| P3 | 地图 | 成都 / 西安 / 丽江三站点，已解锁与未解锁态、消耗 30 呼噜币发起旅行、归来倒计时 | 发起旅行 |
| P4 | 旅行归来 | 开箱动效、本次食材清单 | 领取入库 |
| P5 | 合成台 | 背包网格、拖拽 3 合 1、成品栏、配方图鉴入口 | Canvas 2D 拖拽 |
| P6 | 图鉴 · 我的 | 已发现配方、旅行记录、羁绊时间线、设置与协议 | — |

### 2.3 数值表 v0.1（待实测校准）

**产出**

| 行为 | 单次 | 每日上限 | 说明 |
|---|---|---|---|
| 专注 25 分钟完成 | +10 呼噜币 | 4 次 / 40 币 | 确定奖励，不随机（铁律 2） |
| 专注中断 | 0 | — | 不扣币，不指责 |
| 新手首次登录 | +30 币 | 一次性 | 保证首日立刻能旅行一次 |

**消耗**

| 行为 | 成本 | 真实耗时 | 产出 |
|---|---|---|---|
| 发起一次旅行 | 30 呼噜币 | 2 小时 | 6-9 份食材（份数随机，种类按站点） |

**合成**

- `Lv1 ×3 → Lv2 ×1`
- `Lv2 ×3 → Lv3 成品串 ×1`
- 即 **9 份 Lv1 = 1 个成品**；一次旅行约产出 0.7-1 个成品

**解锁**

| 站点 | 门槛 |
|---|---|
| 成都 | 初始开放 |
| 西安 | 3 个成品串 |
| 丽江 | 8 个成品串 |

**节奏推演**：每日 40 币 → 约 1 次旅行 → 约 7 份食材 → 约 0.78 成品/天 → 累计 11 串约需 **14 天**。MVP 的内容纵深恰好覆盖 14 日留存观察窗口。

**关键旋钮**：`每日专注上限` 与 `解锁门槛`。调这两个即可整体拉伸或压缩节奏，其余数值不要动。

### 2.4 合成规则

- **3 层封顶**，第 3 层即可用于解锁的成品，不做无限层级。
- 每站点 3 种基础食材：
  - 成都：花椒 / 藤椒 / 兔丁
  - 西安：孜然 / 羊肉 / 白吉馍
  - 丽江：菌子 / 腊排 / 乳扇
- 同种同级 3 合 1。
- **隐藏配方**：跨站点的 Lv2 组合 → 特殊成品，计 **2 个**解锁进度并入图鉴。
  - 例：`羊肉Lv2 + 花椒Lv2 + 菌子Lv2 → 三城串`
  - 隐藏配方同时是第二期「收养流浪动物」的钥匙——第一期的图鉴收集已在为第二期埋线。
- 每次旅行的食材应在 **3-5 分钟内消化完**，会话有终点（铁律 3）。

### 2.5 文案与反馈规则表

这张表基本决定用户对产品的情感判断，且是最便宜的改动。

| 触发 | 小狗表现 | 给予 | 文案 | 推送 |
|---|---|---|---|---|
| 专注完成 | 摇尾，叼回一面小旗 | +10 | 「你专注的时候，我一直趴在旁边。」 | 无 |
| 专注中断 | 抬头看你一眼，趴回去 | 0 | 「没关系，我们再来一次。」 | 无 |
| 当日第 4 次完成 | 打哈欠、伸懒腰 | +10 | 「今天够啦，剩下的时间去忙你的事吧。」 | 无 |
| 旅行出发 | 背上小包跑出画面 | −30 | 「我去成都啦，两小时后回来！」 | 无 |
| 旅行归来 | 冲回来蹭腿 | 食材 | 「我在成都给你带了花椒！」 | 到点一条 |
| 合成成品 | 原地转圈 | 成品 | 「这串闻起来好香。」 | 无 |
| 发现隐藏配方 | 愣住后跳起来 | 成品 + 图鉴 | 「你把三个城市串在一起了。」 | 无 |
| 断签 1 天 | — | — | 次日打开：「你回来啦。」（**不提断签**） | 无 |

### 2.7 云函数清单

| 函数 | 职责 |
|---|---|
| `login` | 静默登录、建号、发放新手 30 币 |
| `focus_start` | 服务端记录 `startAt`，返回 `sessionId` |
| `focus_settle` | 校验 `serverNow − startAt ≥ plannedSec` 且无中断上报 → 发币；校验每日上限 |
| `focus_interrupt` | 客户端 `onHide` 超阈值上报，置为中断 |
| `travel_start` | 事务扣币、计算 `arriveAt`、**服务端掷食材** |
| `travel_settle` | 到点结算入库存 |
| `craft` | 事务校验 3 份同种同级 → 产出上一级；判定隐藏配方；支持批量提交 |
| `unlock_site` | 校验成品数 → 解锁站点 |
| `get_profile` | 首屏聚合，一次拉全 |
| `log_event` | 批量埋点写入 |

### 2.8 反作弊

- 所有时间以服务端 `Date.now()` 为准，**客户端上报的时间一律不信**。
- 专注：`start` / `settle` 双端记录，中断由 `onHide` 上报与 settle 时间差**交叉校验**。
- 食材随机在服务端掷，结果落库后才返回客户端。
- 币的增减只在云函数事务内发生。数据库安全规则：**客户端零写权限**，仅可读自己的记录。

### 2.9 埋点清单

| 类别 | 事件 |
|---|---|
| 基础 | `app_open` · `session_end(duration, hasDisciplineAction)` |
| 自律 | `focus_start` · `focus_complete(duration)` · `focus_interrupt(reason, elapsedSec)` |
| 玩法 | `travel_start(siteId)` · `travel_settle` · `craft_action(from,to)` · `recipe_discovered` · `site_unlocked` |

**必须能出的 6 个派生指标**：次日/7日/14日留存 · 专注完成率 · **空转会话占比** · **娱乐/自律时长比** · 首日到首次旅行转化率 · 断签后自然回归率（无推送情况下）。

### 2.10 验收标准

- 功能：6 页跑通，所有云函数均有服务端校验
- 数据：埋点全量可查，6 个指标能出日报
- 性能：首屏 < 1.5s，主包 < 2MB
- 稳定：连续 3 天灰度无 P0

## 四、后续三期

### 第二期：家园与伙伴（6-8 周）
- 极简家园：狗窝 3 级 + 装饰位
- 金币系统正式引入，**家园是金币唯一出口**
- 流浪动物收养：用第一期的隐藏配方喂养
- 离线收益（伙伴自动产出）
- 地图扩展 +3 站点

**决策点**：金币是否引入，取决于第一期「解锁进度」是否已提供足够目标感。若已足够，可推迟金币，避免过早引入双货币。

### 第三期：社交与重逢（6-8 周）
- 好友、蹭饭（随机奖励）、点赞加速旅程
- 重逢叙事完整化（铁律 4）
- 旅行明信片分享

**明确剔除**：离家出走 + 付费召回。
**决策点**：社交可能稀释自律定位。需在第二期数据中先看「有好友 vs 无好友」用户的专注时长差异。

### 第四期：商业化（4-6 周）
- 激励视频（看广告翻倍**食材**，不翻倍呼噜币）
- 皮肤与家园装饰内购
- 未成年人消费限制（依赖第一期建立的 `ageTag`）
- 数据看板完善

**前置**：路线 B 须已拿到版号；路线 A 只做广告。
**铁律 5 在此生效**：不卖呼噜币。

## 五、技术架构

### 5.1 选型
- **小程序**（非小游戏）为壳，保留类目灵活性与分享能力
- 合成台单独用 **Canvas 2D** 实现拖拽（WXML 做拖拽合成手感很差），其余页面用原生 WXML
- 微信云开发 CloudBase：云函数 + 云数据库 + 云存储
- 美术资源走云存储 + CDN；主包只放框架与首屏，其余分包（主包上限 2MB）

### 5.2 写库策略（成本与性能）

养成类产品的高频读写会把云开发费用打上去。策略：

1. 客户端持有本地状态（Storage），只在**关键节点**写库：`focus_settle` / `travel_start` / `travel_settle` / `craft` / `unlock_site`
2. 合成过程中的中间态**不写库**，一次会话结束后批量提交
3. 首屏用 `get_profile` 一次聚合拉取，禁止各页面自行拉取
4. 埋点本地缓冲，每 20 条或 30 秒批量上报
5. 云开发控制台配置调用量与费用**告警阈值**
