## 要做的 6 项（建议顺序：3、4、5、6 一批 → 2 → 1 单独一批）

1. **PPT / 长文档并行写（中）**
   - 在 `src/agent/professionalDocumentTools.js`、`src/agent/longDocumentTool.js` 里，把逐页、逐节的 helper 写作改成有上限的并发（2–3 路），保持页序和原有逐页检查。
   - 先查清 `write_professional_document` 第一次为什么失败（第三轮两次运行各 1 次），修根因，不靠重试兜底。
   - 目标：PPT 降到 50–70 秒，长文档少 30–40 秒。
2. **减少动手前的来回（中）**
   - 追问修改刚生成的文件（“字大点”“去掉横线”）时，直接用本对话最近一个产物，不再 find_files / read_file / read_task_requirements / execution_capabilities。
   - 短任务（单文件、单步）不调 update_plan。
   - 能并行的只读工具同一轮发出。
   - 相关位置：`src/agent/agent.js` 的工具循环和提示；`documentFileFormat.js` / `documentGenerateTool.js` 的产物定位。
   - 目标：文档修改类每题少 5–15 秒。
3. **网页读取更快（小）**
   - `fetch_url`（`src/agent/tools.js` 约 608 行起；`readPage`）单页上限 8 秒。
   - 多个候选页面并发读，资料够了就停。
   - 政务指南（`readGovernmentGuide`）的子页同样处理。
   - 目标：查询类从 40 秒左右降到 20 秒左右。
4. **克隆仓库不死等（小）**
   - `server/codeGit.mjs` 的 `createGitRunner` 默认 `timeoutMs=120000`，加上 `gitRetry` 重试，最坏要好几分钟。
   - clone / fetch 设一个总时限（约 60 秒），超时直接报清原因（服务器连 GitHub 不稳）。
   - 已有 `bare.git` 缓存时只 fetch，不重新克隆。
   - 目标：最坏情况从 7 分钟降到约 1 分钟。
5. **日常聊天更轻（小）**
   - `src/llm/router.js` 的 `isSmallTalk` 只认寒暄词。
   - 把明显不需要工具的短句（情绪倾诉、问“你能不能……”、只要澄清的请求）也走轻量模式，或者只带很小的工具集。
   - `agent.js` 的 `needsActionTools` 判定和中途升级逻辑保留。
   - 不能误伤要查资料、要动手的话。
   - 目标：每句快 0.5–1 秒。
6. **少一次多余的收尾检查（小）**
   - 已有有效产物回执和读回证据的单文件任务（海报、单页 Word），不再追加 finish_check + rewrite。
   - 重写规则仍然只在真有问题时触发（参考 `answerRequirements.js`、`SOFT_ANSWER_RULES`）。
   - 目标：每题少 3–6 秒，两次结果更稳定。

## 约束

- 照 CLAUDE.md 和 `docs/已修问题清单-不许回退.md`：
  - 动手前拉最新代码并合并，不整文件覆盖；
  - 测试只加不删、不放宽，阈值不改；
  - 修了的写进防回退清单。
- 质量门槛不降：
  - 文档逐页检查、架构图逻辑、联网来源要求、评测隔离、回收站、副本接续都不动；
  - 不能为了快跳过读回。
- 不引入新依赖、新收费接口。保存提交带 `[skip ci]`，发版前按惯例另提交运行时固定清单。
- 每项加测试，例如：
  - 并发写作保持顺序、单页失败只重写那页；
  - fetch 超时；
  - clone 总时限；
  - 轻量判定的正反例；
  - 有产物回执时不追加 finish_check。
