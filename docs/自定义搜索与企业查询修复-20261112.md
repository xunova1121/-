# 自定义搜索与企业查询修复（2026-11-12）

用户在只读排查后明确授权新增OpenAI兼容查询接口，并把企业查询问题一起修复、统一发版。本批沿用已有结构，不改jarvis.env、不替换旧Key、不用业务服务器中转安装包。

## 已确认原因

- 普通公司简介被判为快查。deep_research的规划、逐页摘录、核对、成文共用普通查询3次辅助调用上限，两个可用合成来源也能复现第4次调用中断。
- 企业工具只查询政府及巨潮来源，企业过滤在聚合搜索返回后执行，首选源的通用命中可能全被企业规则过滤而不再尝试备用引擎。
- 空企业JSON被执行器记为成功，review却认为没有资料，两处判定不一致，阻断无资料后的自主接续。

## 本批改动

- 新增独立自定义搜索地址、Key、模型、协议、启用状态。默认关闭，本机和云服务器分别保存；Key留空保留旧值，服务器只返回末四位掩码，并核对保存读回。复制聊天模型不顺带复制搜索Key。
- 支持OpenAI Responses原生web_search及Chat Completions搜索模型。单请求、20秒、2MiB；只接受结构化来源或引文，普通模型正文自报链接/JSON不冒充搜索结果。有引文的摘要与网页原文明确区分。
- 电脑网页POST独立代理，避免原读网页代理丢掉请求体及Key；服务器登录令牌与上游Key分离，公网HTTPS/DNS检查、禁止重定向、断开取消。安卓原生网络在明确redirect:error时禁用自动重定向。
- 企业基本简介在官方检索无有效资料时最多补一次全网查询，严格主体匹配，股权/投资/高管来源规则保持。只有链接时作为待读线索，不算已取得事实。
- 聚合器在任务相关性过滤之后才决定是否收尾，空结果继续备用引擎；取消、预算及评测额度信号立即传播，不被其他源成功掩盖。
- 深度调研仅在实际调用工具时获得一次有界额度，保留已耗次数，重复调用不续期。quick/standard/deep分别90/180/300秒及6/11/18次辅助调用；严格核验和调用方更短期限保持。中断时保留最多1800字的已有来源要点，仍标调研未完成。
- 自救依据实际检索回执，不把tool_search或企业空JSON当作拿到资料。

## 配置位置

设置 → 模型 → 云服务器（或本机） → 服务商与Key → 自定义联网搜索（OpenAI兼容）。按服务商说明填写地址、搜索模型和协议，保存后测试。API GET公开模型Base URL是https://api.apiget.store/v1，但模型ID及其支持的搜索协议须以实际账户说明为准，不预填猜测型号。

## 验证与发布边界

新增协议、配置HTTP读回、UI、企业换源、预算、网关及原生重定向回归；旧测试只增加不删除。发布继续执行原三端完整门禁、原安卓签名及公开更新索引核验，未通过前不把草稿称正式版本。

本环境没有API GET账号Key，协议测试使用合成上游；真实付费接口、用户服务器、Android/Windows真机没有实测。发布完成与服务器实际升级、真机验收分别报告。最终测试及版本结果待收尾记录。
