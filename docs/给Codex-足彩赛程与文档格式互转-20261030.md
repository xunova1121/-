## 一、直播吧足彩赛程：正在进行 + 前后两小时

### 用户原话

> 直播吧足彩赛程，呈现进行中和未开始的比赛，以当下前后两个小时赛程展示为主，数据以直播吧为主。

### 现状

- `src/agent/sportsScores.js` 的 `get_sports_scores` 工具已经接了直播吧比分列表（`src/agent/sportsZhibo8.js`，`bifen4pc.qiumibao.com`，无密钥），比分 / 赛程以它为主。
- 时间筛选在 `src/agent/sportsWindow.js`：
  - `period` 只有 `all`、`upcoming`、`remaining`、`afternoon` 四种；
  - `upcoming` 只要**未开赛**的（state `pre`/`1`），`window_minutes` 最多 360；
  - **没有“进行中 + 前后 N 小时”窗口**。
- `inferSportsWindow` 按用户原话推断时段；“马上 / 接下来”走 upcoming。

### 要做的

1. **新窗口 `around`**（名字自定）：
   - 时间范围：当下（北京时间）前 2 小时到后 2 小时，可调；
   - 包含**进行中**（含中场）和**未开赛**的比赛，已完场的不进主列表；
   - 进行中的排最前（显示比分、第几分钟 / 半场），未开赛按开球时间排；
   - 说“足彩赛程”“现在有什么球”“前后两小时的比赛”时默认用它。
2. **足彩（竞彩足球）字段**：
   - 先查直播吧有没有竞彩场次编号（如“周四001”）和停售时间的公开接口或页面；
   - 有就并进来；没有就说明，只展示普通赛程，**不编编号、不编赔率**；
   - 赔率只在直播吧数据里有时才显示，并注明来源和获取时间。
3. **呈现**：
   - 对话里给一张紧凑的赛程卡（手机 320–412 宽也要好看）：联赛、对阵、开球时间（北京时间）、状态（进行中 xx' / 未开赛）、比分；
   - 卡片可以点“刷新”；
   - 文字回答也要能单独看懂（语音朗读时用）。
4. **数据以直播吧为主**：
   - 直播吧取不到时，可退回现有的备用来源，但要标明“直播吧暂时取不到，以下来自 xxx”；
   - 不把空结果说成“没有比赛”（`formatScores` 现有的措辞要保留）。

### 验收

- 单元测试：
  - 窗口边界：前 2 小时开球、仍在进行的要包含；
  - 已完场的不进主列表；跨午夜正确；
  - 竞彩编号缺失时不编造。
- 用直播吧真实返回存一份脱敏样例做离线测试，不在 CI 里联网。
- 手机和电脑各截图核对卡片。

## 二、文档格式互转

### 用户原话

> 文档之间的格式互转功能要具备，比如 PDF 完美转 Word，等等。

### 现状

- 读取：`src/agent/docs.js`（PDF 用 pdf.js 分页读，Word / Excel / PPT 能读文字）；扫描件可用已接入的 GLM-OCR 识别文字（`src/llm/ocr.js`）。
- 生成：自有 Word / Excel / PPT 生成器（`docxWriter.js` 等），按内容重新排版，不是“原样转换”。
- `server/officeRender.mjs` 能调服务器上可选的 LibreOffice（`soffice`）渲染检查，目前只用于验收。
- **没有面向用户的格式转换工具。**

### 要做的（先做常用、能做好的，再做难的）

| 优先 | 转换 | 建议做法 | 预期质量 |
|---|---|---|---|
| 1 | Word / Excel / PPT → PDF | 服务器 LibreOffice headless | 高 |
| 1 | 图片 → PDF（多张合一） | 纯 JS（如 pdf-lib，MIT） | 高 |
| 1 | PDF → 图片（逐页） | 已有 pdf.js 渲染能力 | 高 |
| 2 | PDF → Word（文字型 PDF） | 先评估开源方案（LibreOffice 导入、pdf2docx 等，**先看许可**，Python 的只能放进 Docker 技能运行器）；对比版面、表格、图片、页眉页脚的还原度 | 中，要实测 |
| 2 | PDF → Word（扫描件） | GLM-OCR 识别后按段落 / 表格重建 Word，标注“由识别生成，请核对” | 中低 |
| 2 | PDF 表格 → Excel | 识别表格结构，读回核对行列数 | 中 |
| 3 | Word ↔ Markdown / HTML、Excel ↔ CSV、PPT → 图片 | 现有解析和生成器 | 高 |

### 要点

- **“完美”要说实话**：PDF 本质是版面描述，复杂排版（多栏、浮动图、公式、特殊字体）转 Word 不可能每份都完美。转完要读回核对：
  - 页数、段落数、表格数、图片数和原件对比；
  - 有差异的地方在回答里列出来，不空说“已完美转换”。
- 一个工具 `convert_document`（名字自定），参数是源文件和目标格式。不支持的组合直接说明，不假装。
- 在哪运行：
  - 优先服务器（有 LibreOffice / Docker）；
  - 电脑版能本地做的（纯 JS）本地做；
  - 手机走服务器。
- 原文件不覆盖，输出另存为新文件。
- 安全：LibreOffice 宏关闭；限制单文件大小和页数；转换超时有上限。

### 验收

- 每种转换都放一份虚构样例文件，做离线测试（不提交客户材料）。
- PDF → Word 至少测三类：纯文字、带表格、扫描件；把读回核对结果写进报告。
- 服务器没装 LibreOffice 时，要提示怎么装，或退回能做的方案，不崩溃。
