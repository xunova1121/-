## 原因与修复

- 安装器会把较大文本附件存成在线引用，而旧运行器准备源文件时直接跳过这些引用。当前 Archify 上游其实已提交 generated-validators / generated-brand-marks，但它们很大，仍可能没送进容器；不能只归因于上游没提交。现在按安装清单补齐 GitHub raw 文本附件，有单文件2MB/合计20MB/90秒和来源限制，不读用户工作区，安装身份变化后重取。
- 原依赖逻辑只看普通 dependencies，也不执行生成步骤。新增独立 `skillBuild.mjs`，识别根/唯一子目录 package.json 的标准 prepare/generate/build 或技能内现存的 Node 生成脚本；不自动运行仓库外的 viewer/文档站点脚本，也不运行 test 充当构建。
- 构建在独立副本、非root/只读根/无特权容器内装开发依赖并运行明确脚本。npm默认 npmmirror，有锁用 ci，无锁用 install，安装生命周期禁用，只显式执行所选步骤。安装中的技能包不写；成功后只读挂载构建副本。原普通技能路径和 Python 依赖规则保留。
- 全内容指纹包括二进制尾部；同稿并发共用构建，内容变化重建。每技能最多2版本，单版本128MB/12000文件，最多8个准备/活跃版本。准备和使用期间保护版本，不能删正在用的缓存。构建5分钟/1GB，失败不缓存，取消确认容器消失；清理无法确认时保留副本并暂停后续构建。
- 补了明确文件/目录权限，避免 systemd umask 077 让容器nobody读不到技能。新并发测试还暴露镜像inspect未返回就缓存false导致误报“没安装”，已修。
- 普通架构图仍走原内置工具；技能执行接缝在普通架构图未点名技能时拒绝擅自改用技能。没有修改 `agent.js`、`diagramPlanning.js`、`diagramTool.js`、`diagramRepair.js`，原视觉/PPT门槛保持，技能输出防伪造清单守护保持。
