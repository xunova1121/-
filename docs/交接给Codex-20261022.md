## 一、手机“模型”页错版（用户 07:40 截图）——已由 Claude 修好，你不用再做

**现象**：手机 App →“模型”页 →“云服务器”，配置从 d.leing.top 读取后，整页往左偏，左边被切掉；卡片右边缘只到屏幕约六成处。“模型分工 · 文档审查”下拉框一直伸到屏幕右边以外。看起来页面被一个过宽的元素撑宽，可以左右滑。

**最可疑的原因（还没确认）**：`src/ui/modelLibrary.js` 的 `renderDocumentReviewer()`。
- 里面那个 `<select>` 没有 class，`modelLibrary.css` 里只有 `.ml-search-row select`、`.ml-add-select` 有 `max-width: 100%; min-width: 0`。
- 下拉框的宽度会按最长的选项撑开。选项文字是“服务商名 · 型号”，服务器上的型号名一长，就超出屏幕。
- 本机默认配置下只有“沿用写作模型（同模型自查）”一个短选项，所以复现不出来。

**我做过的检查**：用 build:mobile 产物、412px 宽度、默认配置打开“模型”和“设置”，`#panel` 里没有超出视口的元素（scrollWidth = 412）。没能连真实服务器复现。

**请你**：
1. 先复现：在测试里造出服务器配置，常用线路里放一个很长的型号名，让审查下拉框出现长选项，量出 `#panel` 和页面的 scrollWidth。
2. 修：给这个下拉框加 class，宽度不超过容器（`width: 100%; max-width: 100%; min-width: 0`）。顺带查同一页其他控件，包括“联网搜索 · DeepSeek Search/Fetch”（`deepseekSearchPanel.*`）、“写作偏好”、长型号名的卡片。整页不能有横向滚动。
3. 加回归测试：可以写进 `e2e/model-library.mjs` 或 `e2e/mobile-ui.mjs`，在 390px 和 412px 宽度下，“模型”页本机、云服务器两个标签都要满足 `scrollWidth <= clientWidth`，用长型号名的数据。
4. 跑 `npm run lint`、`npx vitest run`、`npm run build:mobile && node e2e/mobile-ui.mjs`、`node e2e/model-library.mjs`。
5. 推送时加 `[skip ci]`，**先不发版**，等用户说。

不要联机改用户服务器上的配置；需要真实数据时用假数据。
