# Claude 接手架构图（2026-10-29）

## 判断
Codex 的严格流水线（build_architecture / director，36 个文件约 2900 行）要求模型先把项目写成带类型、方向、用途、数据的关系网（实测 40 对象 58 关系），程序逐条校验通过才画图。真实模型写不出零错误的关系网，连续五六次一张图都没出。用户要的是 GPT 那种“层次全、内容具体、好看”的总体架构图，不需要每条关系形式正确。

## 改了什么
- 路由：普通“做总体架构图”由主模型直接 `create_diagram`（Codex 前四步的图标卡片 / 带字箭头 / 网格 / 通栏 / 分栏 / 政企蓝）；只有用户明说“逐条核对需求原文 / 严格审查 / 业务审查”才进严格流水线（`diagramPlanning.js` 的 `strictArchitecture`，`agent.js` director 入口、`tools.js` create_diagram 的 requireArchitecture='strict'）。严格流水线代码一行没删，原测试只改了一处：集成测试的请求补“逐条核对需求原文”（行为有意改变，已告知用户），并新增“普通请求走主模型入口”用例。
- 提示词：`DIAGRAM_PLANNING` 改写为先读原文 → 按展示 / 业务应用 / 平台 / 感知 / 基础设施 / 安全排层 → 数量和系统名逐项写进图 → 报错按提示删减再画一次，一定交图。
- `.doc` 后缀的新版 Word 文件可读（parseFile 按内容识别）。

## 验证
- 用用户的真实招标文件（长江流域重点水域禁捕执法装备设施建设项目），Claude 扮演模型填 create_diagram，走真实出图流程：一次成功，1.6 秒导出 SVG / PNG / PDF / PPT，渲染检查通过。图交给了用户，没有提交进仓库（客户材料）。
- 单测 1937 全过，lint 通过。
- 没测：真实模型（DeepSeek / 中转站）自己读文件、填结构的效果——这需要用户更新服务器后实测一次。
