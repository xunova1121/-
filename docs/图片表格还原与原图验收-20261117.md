# 图片表格还原与原图验收

用户已授权开发并统一发版。本批解决照片转 Excel 丢失结构的问题；发布前记录，正式版本和验收结果在文末追加。

## 根因与改动

用户附件实际有 48 列，11 列为空白样式列；仅 7 个整行合并，缺少表体跨上午/下午合并，月份与签字字段也改了。原通用生成器接收 Markdown/CSV，随后套台账配色与自动列宽；原静态检查返回 0 错误，不证明与照片一致。

1. `create_document(format=xlsx, source_path=原图, content="", requirements=用户原话)`进入专用流程。不能退回 Markdown 台账，其他新建 Excel 保留原行为。
2. 视觉模型提取摆正后的网格、原图四角、行高列宽、合并关系、固定原文及填写内容类别。程序按要求清空姓名/勾叉/填写值，保留印刷月份、序号、上下半天及图例。不引入固定考勤模板。
3. ExcelJS 写原生可编辑单元格。颜色、字号、边框和合并直接来自受限结构，不推断公式、不自动换日期、不新增多余空列。原图及旧 Excel 不覆盖。
4. 读回实际 XLSX，逐项核对行列数、合并、全部原文、空白范围、字号、边框、列宽、行高及打印设置。字号从实际 XML 校验，绕开 ExcelJS 读字号取整的缺陷。
5. 独立采样原照片像素与识别网格是否吻合。可用时实际 Office 转 PDF，再将原图与真实打印页面交给视觉模型独立核对；不是拿 JSON 自评。单页、原文、留空、可读性、布局与独立计数均需通过。
6. 未通过时保留待核对稿，最终回执和回答守护不能报“原样还原”。只显示一个 Excel 成品；结构 JSON、报告及预览存 `.workflows/spreadsheets`。每次至多两次视觉调用，调用前计入原预算，不自动重试/联网/重新生成。

边界：PNG/JPEG/WebP 原图最大 10MB/2400 万像素；80 列、180 行、12000 格、2000 个显式单元格；识别 JSON 最大 180KB；单次视觉 60 秒。同账号最多 4 个在途目标，取消/切换工作区停止后续写入。没有视觉配置拒绝假造；没有真实 Office 能力只交待核对稿。

## 本地验证及发现

- 新单测 27 项；加上原 Office 写入、Excel 四风格、图片区域参数、回执测试，共 71 项通过。
- 真实 PNG 解码、原图网格采样、XLSX 读回、Office PDF 单页已跑通。正向与旋转 90 度样张均含 37 列、11 个人员两行合并、复合合计表头；另有 6 列检验表，避免生产代码硬编码考勤表。
- 实际查看第一轮 PDF 发现双位日期折行：OOXML 列宽误减了 5px 内边距。修正后再次打开真实 PDF，1～31 日期同一行、表体框线和签字框正确；新增 PDF 坐标/日期顺序断言，禁止去掉所有空白后把两行的“1/0”当成“10”通过。
- 用户上传的旧错误 XLSX 用新读回器检测，明确报行列数/合并/固定原文不符，不再因 0 公式错误放行。
- 未更改原测试断言、免费/付费预算、1000 文件上限、Android 签名、分享返回、前台恢复或原三端发布方式。
