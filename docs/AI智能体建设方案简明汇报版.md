# 长江流域重点水域禁捕执法装备设施建设项目

## AI智能体建设方案（简明汇报版）

---

## 一、为什么要建智能体

在建的平台正在解决"**看得见**"的问题——摄像头、雷达、AIS、北斗把水面情况传回来，屏幕上能看到。

但平台建成后，还有三件事解决不了：

**第一，看见了，但要靠人去看懂。** 平台弹出一条告警，是钓鱼还是路过、算不算违法、该罚多少，全要人打开视频一帧帧看、翻法条、查案例。标书里"预警分析研判"这一条，原文写的就是"进行**人工**初步研判"。一条线索从预警到出警，耗时按"天"计。

**第二，模型建完就不动了。** 现在的AI识别模型训练完就固化，一线遇到新手法——夜里钓、多人蹲守、跨湖区流窜——模型不会自己学。运行两三年后，识别精度提不上去，反而越来越跟不上。

**第三，查个数要跨好几个模块导表。** 想知道"上个月洪泽湖夜间违规比去年多多少"，得从几个子系统分别导出再人工拼。

**一句话概括：** 平台解决了"看得见、传得回、流程能走通"，智能体要解决的是"**看得懂、判得准、派得对、越用越准**"。这是上下两层的关系，不是同一件事的两种做法。

---

## 二、建设思路：不推翻、不重构

**明确一条底线：现有平台一行代码不推翻，一个模块不重建。**

具体做法是三个"不"：

- **不重建底座**——报表引擎、图表组件、移动端、GIS地图、船艇轨迹、算法仓库、案件评分，标书已经建好的，全部直接调用；
- **不重复采购硬件**——标书已配32台内置GPU的录像机（明确支持导入视觉大模型和第三方算法插件）、32台双光谱云台、12台雷达，视频识别的算力和设备条件已经具备；
- **不改变现有流程**——"预警→研判→签收→处置→审核"这套流程壳保持不变，智能体是接在既有节点上，把原来人工做的环节换成AI辅助。

风险上也留了退路：**AI能力可一键停用，随时回落到现在的人工流程，业务不中断。**

## 三、10个模块分别是什么、干什么用

### 3.1 新增模块（6个）——标书完全没有的内容

| 模块 | 一句话说清干什么 | 对工作的实际改变 | 可量化指标（建议作为验收依据） |
| --- | --- | --- | --- |
| **一、多智能体协作框架** | 给平台配一个"AI执法专班"：一个班长带五个专业组员（看视频的、做研判的、派任务的、审案卷的），班长负责拆活派活盯进度 | 现在一条线索要在门户、预警、指挥调度、办案四五个模块之间来回切换；以后这些动作在后台自动串起来 | 单条线索跨模块人工切换次数：从6-8次降到0次 |
| **二、任务规划与自主决策** | 让系统听得懂人话、拆得开活、拿得准主意，**拿不准会举手** | 领导说一句"这周末重点盯洪泽湖夜钓"，系统自己理解成一组任务安排下去；把握不足的自动交回人工 | AI自动处置占比目标≥60%；低于阈值转人工比例100% |
| **三、记忆管理系统** | 给AI装"记事本+档案柜"，让它记得这条船、这个人以前干过什么 | 现在每条预警都是从零处理，系统不知道这个人是三次违规的老面孔；有了记忆，孤立事件能串成线索 | 重复违法人员自动识别率；关联历史案件召回率 |
| **四、知识库与RAG** | 把法条、案例、裁量基准做成AI能查能引的"电子法律顾问" | 研判不再靠人翻法条；**AI下结论必须引用查到的原文，查不到就说"无依据"，不许编** | 法条引用准确率100%（硬指标）；研判结论有据可查率100% |
| **五、工具调用与执行** | 让AI从"只会说"变成"能动手"——能转云台、放无人机、发工单、起草文书 | 发现目标后不用人工再去点云台、再去派单；**高风险动作（无人机起飞、正式文书）必须人工点头** | AI可自动完成的操作类型数；高风险动作人工确认率100% |
| **九、人机协同与安全合规** | 回答领导最关心的三个问题：AI说错了怎么办、AI凭什么这么说、出事了谁负责查不查得到 | AI每一步用了什么数据、查了什么法条全部可见可回放；**AI只出建议，处罚决定仍由执法人员签字负责** | AI决策全过程可追溯率100%；AI建议采纳率（衡量AI真实水平） |

### 3.2 深化模块（4个）——标书有基础，本次做增强

| 模块 | 标书现在能做到 | 本次增强后能做到 | 可量化指标 |
| --- | --- | --- | --- |
| **六、视频智能识别与模型能力** | 已有"人员捕捞钓鱼AI识别算法"，靠坐姿＋遮阳伞＋钓竿＋渔具桶＋滞留30分钟组合判定 | 升级到**动作级**（持竿、抛竿、收线分别识别）、**夜间**（热成像通道，标书无此算法）、**多人聚集**、**跨点位追人** | 查准率：试运行期≥85%，运行6个月后≥90%；夜间识别从0到可用 |
| **七、执法调度与派单** | 流程壳、移动端、签收计时都已建，但**任务由人创建、等级由人判** | 等级AI自动判、力量AI自动荐、工单AI自动派，人从"创建者"变成"确认者"。**新增处置结果回流训练——这是"越用越准"的唯一实现路径，标书零覆盖** | 预警到派单时长：从天级到分钟级；处置闭环率≥95% |
| **八、NL2SQL与智能报表** | 报表引擎、近30种图表、驾驶舱都已建，查数要人工配置 | 加一层"说人话查数"的入口和AI自动解读，图表渲染和导出**直接复用标书能力，不重建** | 常用统计出数时间：从小时级到分钟级 |
| **十、智能巡查** | 船艇轨迹已建（112台北斗船载主机）、巡查路径可预设、任务可归档 | 新增**执法人员**巡查轨迹自动采集、现场影像自动水印归档、巡查质量AI自动打分（三项标书均无） | 巡查记录自动生成率；轨迹覆盖率可核验 |

> **说明：** 上表中的量化指标为建议的验收目标值，非当前实测数据。建议在合同中逐项约定，避免"智能化""准确"这类无法验收的表述。

## 四、哪些必须先做，哪些可以往后放

### 4.1 必须做的：6个新增模块 + 回流训练（智能体的骨架）

**判断标准很简单：没有这六个模块，剩下的四个就还是传统的图像识别加报表，构不成"智能体"。**

- **模块九（安全合规审计）必须第一批建。** 标书里的审计条款有四处，审的都是"人操作了系统"——谁登录、查了哪张表；**没有一条能回答"AI调了哪个模型、传了什么数据、为什么这么判"**。AI进执法环节，这个缺口不补上，前面做的东西都没法真正投用。
- **模块四（知识库）必须第一批建。** 它是研判Agent的输入源，没有它AI无据可依。
- **模块一、二、三、五**是骨架，缺一个智能体就转不起来。
- **模块七第50项（处置结果回流训练）建议从模块七拆出来，跟视频识别配套做。** 这一项标书零覆盖，是"越用越准"这个核心卖点的唯一落地点；不做的话，模型训练完还是固化，方案的核心论证立不住。

### 4.2 可以往后放的：4个深化模块

| 模块 | 为什么可以缓 |
| --- | --- |
| 十、智能巡查 | 与标书重叠最多（船艇轨迹、巡查路径、任务归档都已建），去重后真正的新增只剩影像水印和AI质检两项；与其他模块耦合最低，晚建不影响别的 |
| 八、NL2SQL智能报表 | 图表和导出标书已有；落地依赖前期的语义层建模准备，仓促上马准确率不达预期反而砸口碑；属"锦上添花"，不影响执法闭环跑通 |
| 七、45-49项派单流程 | 现有流程壳和移动端能用，AI接入只是把人工换成自动；且强依赖在建平台开接口，接口不到位建了也用不上 |
| 六、视频智能识别 | 可缓但**建议在非紧急项里排第一位**——它是真正提升发现能力的部分，且样本积累越早开始越好 |

## 五、要真正达到智能体的要求，建议再补三件事

这三项不在原来的10个模块里，但业内做智能体是标配，不做会留下明显短板：

| 补充项 | 为什么需要 | 人天 / 金额 |
| --- | --- | --- |
| **场景评测集与回归测试** | 现在10个模块里没有一项是"怎么证明AI做得对"。建一套渔政场景评测集（100-200条标注好的真实案例），模型或提示词一改就跑一遍回归。**没有它，模型升级后是变好还是变差，谁也说不清** | 15人天 / 3万元 |
| **模型网关（可插拔抽象层）** | 直接对接某一家大模型，将来换模型要改代码。加一层网关统一接口后，**换模型只改配置不动代码**。这一项同时也是下一章"会不会被推翻"的答案 | 10人天 / 2万元 |
| **提示词注入安全测试** | 智能体接了工具就能动手（转云台、发工单）。要防止有人通过构造内容诱导AI执行不该做的操作，需要一轮专项红队测试 | 5人天 / 1万元 |

**合计 30人天 / 6万元。** 建议并入第一批。

另有一项不花钱但必须明确：**处置结果回流训练需要有人做标注复核**。建议明确1名兼职标注复核岗和月度评审例会，写进运维方案。没有人管，回流闭环转不起来。

## 六、算力怎么配

视频识别的算力标书已经解决了——32台录像机内置GPU，明确支持导入视觉大模型和第三方算法插件，**这部分不用新买卡**。

需要新增的只是大模型推理的算力。给三个方案：

### 方案A：调用政务云大模型（**推荐**）

**算力卡采购：0元。** 江苏省政务云如已提供大模型服务，直接调用，数据在政务云内网不出域，同时满足信创要求。只产生Token运营费：

| 使用强度 | 月费用 | 年费用 |
| --- | --- | --- |
| 低频试点（5个湖区，每天10次） | 约1,800元 | 约2.2万元 |
| 正常运营（每天50次） | 约9,000元 | 约10.8万元 |
| 满负荷（每天200次） | 约3.6万元 | 约43.2万元 |

**若政务云统一承担Token费用，本项目这块可为零支出。这是最省钱也最合规的路径，建议优先确认。**

### 方案B：本地轻量部署（政务云无大模型资源时的备选）

| 项目 | 配置要求 | 说明 |
| --- | --- | --- |
| 主推理模型 | 32B参数级国产大模型，INT8量化 | 权重约32GB，加上运行时缓存开销，需**48-64GB显存** |
| 向量模型 + 重排序模型 | 检索用，体量小 | 约4-6GB显存，可与主模型共卡 |
| **加速卡** | **国产加速卡（64GB显存级）× 2张** | 一张跑推理、一张保并发与冗余。国产卡满足信创要求 |
| 推理服务器 | 2卡整机，国产CPU + 国产操作系统 | 与标书信创要求一致 |
| 网络与存储 | 部署在政务云内网，数据不出域 | 满足等保三级 |

**投资量级：40—70万元。** 国产加速卡近两年供货和价格波动较大，**上述为量级参考，须以采购时的实际询价为准**，不宜直接写入预算。

### 方案C：完整本地部署（含微调能力）

在方案B基础上增加训练卡，4—8卡规模，量级100—200万元。**不建议本期采用**——微调训练是低频动作，可在需要时租用算力或依托厂商环境完成，不必自购。

**结论建议：先按方案A推进，把Token费在运营预算中单列；只有确认政务云无大模型资源时，才启动方案B的询价。**

## 七、以后AI发展了，现在做的会不会被推翻

这个问题要分两半回答，因为答案不一样。

### 会过时的部分（但影响可控）

具体的**大模型型号**和**编排框架版本**一定会迭代——今天用的模型，两三年后必然有更好的替代。这是行业常态，躲不掉。

**应对办法就是第五章讲的模型网关**：所有对大模型的调用走统一接口，换模型只改配置、不动业务代码。有了这一层，模型换代对系统的影响，相当于换一个供应商的服务，而不是重做一遍。

编排框架同理——建议采用轻量自研编排加标准协议的做法，不深度绑定某一个开源框架，避免框架停止维护时被动。

### 不会被推翻的部分（这才是真正的资产）

以下这些一旦建成，不随模型换代而贬值，而且时间越久越值钱：

| 资产 | 为什么不会贬值 |
| --- | --- |
| **法规库、案例库、裁量基准库** | 整理好的知识资产，换任何模型都能直接接着用 |
| **重点人员画像、船舶行为指纹、违规行为模式库** | 数据资产，越积累越准 |
| **处置结果回流积累的标注数据** | **这是最值钱的一块**——每一次执法处置都在给系统攒训练样本，攒得越多，将来换更强的模型时提升越明显 |
| **审计日志结构、工具定义规范、权限体系** | 制度性资产，是"AI怎么被管住"的规则，与用哪个模型无关 |

**打个比方：这次建的是一座图书馆。** 馆藏（法规、案例、画像、标注数据）是资产，会一直增值；借阅系统（大模型）会换代，但换代时馆藏原样搬过去就能用。

**只要坚持"知识与模型分离、工具定义与实现分离、模型可插拔"这三条设计原则，后续AI再怎么发展，本次建设的核心成果都不会推倒重来。** 建议把这三条写进技术方案作为约束条款。

**另需单列的持续性支出：**

- **大模型API调用费**：按方案A测算约2.2万—43.2万元/年（取决于使用强度），属运营成本，不在本次建设采购范围；若由政务云统一承担则为零；
- **算力卡采购**：按方案A为0元；仅在政务云无大模型资源时才需启动方案B（量级40—70万元，须按采购时实际询价）。
