# 海报重复预览与云端源文件返修（2026-11-17）

本轮用户反馈：同一海报在聊天显示三张，工作区的SVG和可编辑PPT没有内容。截图实际显示“源文件（0）/历史稿（0）”。附件是对话记录，没有原始SVG/PPTX，因此不能断言用户的文件字节本身为空。

已统一发布[1.0.455](https://github.com/xunova1121/weiyang-release/releases/tag/desktop-v1.0.455)，公开时间2026-11-17 01:36:25 UTC。构建`c90eac85a163f4ac0b83ca027e9cc99038340d34`，运行源码冻结`6a7f8e7f4a36c6523b1ff1a2da1bd2362c9d0e85`，清单999项。[正式完整CI43993709345](https://github.com/xunova1121/-/actions/runs/43993709345)全部必需任务成功；APK、Windows及服务器包已公开，不能等同于用户设备或服务器已安装。

## 查明的原因

1. `posterDeliverySession`每次可交付试排会通知主PNG；`Transcript.fileLink`已按海报ID替换文件按钮，但`image`仍逐张追加。`toolbox`和`remoteTask`把图片路径丢掉了，渲染层无法判断三张来自同一任务。异步下载还有旧稿晚到覆盖新稿的风险。
2. 云端工具把PNG、SVG、PPTX和源稿全部保存到服务器，但客户端只收到主PNG事件。工作区列表和预览却一直读取本机IndexedDB；虽然成果索引来自服务器，源文件列表仍与本机文件相交，因而显示0。原单份交付浏览器验收事先把所有源文件写入本机，未覆盖这种真实分布，属于测试覆盖缺口。

## 修改

- 图片事件携带实际文件路径，同一轮同一海报ID只有一张预览；按尝试编号比较，重复通知替换，不让慢到的旧稿盖住新稿。释放被替换或丢弃的Blob URL。不同任务和独立配图继续保留；文件历史不删除。
- 工作区跟随当前运行端：本地模式读原工作区，服务器模式读当前授权服务器的完整目录元数据。打开、下载和分享按需读取原字节，不批量下载源文件、不用本机同名文件冒充云端原件。已有云端成果无需重生成便可找回配套格式。
- SVG等旧记录的通用MIME按格式补全，字节不变；真正零字节文件明确报空。切服务器、账号或本地目录后，迟到的文件读取不能更新新视图。云端模式不提供本机永久删除入口；已有主人的收藏键保持。
- 源文件按钮前置格式标签，长文件名不会把PPTX/SVG标识挤没。预览、原文件下载、分享、HTML依赖读取和桌面PDF导出使用同一运行端，云端导出的PDF也写回该服务器。
- PC已连接本地文件夹时，下载缓存可能被另存为“(2)”。云端视图的聊天按钮仍用服务器原路径；本地视图保留实际另存路径，避免修好源文件后又引入404。
