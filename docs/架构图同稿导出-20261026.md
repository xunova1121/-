# 架构图：一份设计，多格式导出

## 行为

- `create_diagram`先确定读者、主结论、层级、重点与关系；程序计算坐标和逐行文字，保存`.diagram.json`。三种配色是沉静蓝、青绿、石墨；不是让Image2代画精确文字连线。
- `diagramScene`是唯一布局描述；SVG序列化和原生PPT只能读取坐标，不能再调用模型另画。原SVG选择器、节点完整性、文字溢出报错、正交避让、底层支撑方向不变。
- SVG实际渲染一次为PNG。展示PPT原样嵌入这张PNG且只生成一页；PDF使用同一张图的RGB像素，避免Office字体替换。PDF为图片页，不提供可搜索文字；展示PPT不冒充原生可编辑。
- 换格式使用`export_diagram`读取明确的设计文件。设计摘要、预览摘要均匹配时复用PNG，不重复调用视觉模型；改了设计或PNG就重新渲染/检查。旧SVG也能导出展示格式，但没有结构化源稿时不能声称原生PPT已编辑化。
- 每份派生文件关联相同`designHash`，`.exports.json`留路径、文件摘要、各格式结果与一致性来源；检查点只留短摘要，不放设计内容和像素。
- `pptxMode: editable`另存原生形状与文本。服务器有现成Office和Poppler时真实转PDF/PNG再比对；宽高比差<0.01且均值像素通道差≤1.2%才交付，未通过的留在“文档检查/”，默认展示版仍保留。此指标只核对画面，不替代内容与视觉审稿。
- 普通PPT入口对独立架构图返回`USE_CANONICAL_DIAGRAM`，要求转统一入口。多页建设方案/汇报PPT仍沿原流程；其中架构图须先生成同稿图片再引用，此项是调度约定，未声称已对所有任意手工PPT代码强制改写。

## 模块

`diagramModel`排层与节点 → `diagramScene`生成绝对场景 → `diagramSceneSvg`序列化 → 原`diagramReview`实际PNG与视觉检查 → `diagramExport`同稿派生与读回。`diagramPptx`、`diagramPdf`只做转换；`diagramPng`用浏览器自带压缩流读有界RGB/RGBA PNG；`server/diagramCompare`做可选真实Office对照。

没有新增npm包、Python运行时或收费接口。CI增加Poppler系统验收工具；运行端缺少Office/Poppler不影响展示PPT/PDF导出，只会阻止未核实的原生编辑版交付。浏览器/本机未注入对照能力时同样明确未检查。

## 边界与安全

- 目前布局专门面向分层架构，不等于已有任意拓扑/ER/时序图专用布局。复杂图应拆成总体与细节，不删关系凑好看。
- SVG仍为原生文本，跨设备字体可能不同；PNG、展示PPT和图片版PDF共同冻结字体。原生PPT在实际验收环境通过也不保证所有Office软件像素完全一样。
- 设计文件2MB、元素2000/分组16层/路径200点；画布2500万像素，PNG420万像素/12MB；单份产物20MB。固定字体、十六进制颜色、正交路径和有界坐标，沿原静态SVG安全子集。并发对照2，进程超时可停止；未加付费重试。
- 视觉失败停止派生，源稿与已完成预览保留。停止及预算信号向上抛；模型视觉调用前先扣预算。

## 验证

新增`tests/diagramExport.test.js`覆盖同稿摘要、PNG原字节入PPT、一页PDF原RGB、预览复用与失效、原生版门禁、控制信号、旧SVG、恶意源稿和普通PPT阻断。`e2e/diagram-export.mjs`实际SVG→PNG→PPT/PDF，再经Office/Poppler核对，不用真实模型或联网。

本地真实样例：展示PPT通道差0.4543%，PDF0.5416%；原生PPT1.2082%超线，按规则保留待验，不调松阈值。长江禁捕用户原图只在本地用于对照，不提交私有原始材料。
