# 未央代码规范（Claude 和 GPT 共用）

改代码前先读这一份；改完按最后的“互相审查清单”自查，并在交接文档里写清改了什么、为什么。
规范和 `CLAUDE.md` 冲突时以 `CLAUDE.md` 为准（命名、发版、测试那些规定不变）。

## 1. 结构

前端入口 `jarvis/src/main.js` 只做“组装”：按顺序创建各模块、恢复设置、启动。功能都在 `jarvis/src/app/`：

| 文件 | 管什么 |
|---|---|
| `context.js` | `app` 上下文：共享状态和各模块的函数挂在它上面 |
| `env.js` | 运行环境和小工具：`$`、`toast`、`DESKTOP`、`COMPACT`（手机）、`storage`…… |
| `stage.js` | 主视觉：光核舞台、情绪、仪表盘、轨道 HUD、建议标注、顶栏“执行中 / 完成” |
| `models.js` | 模型与网关、服务器模式连接与模型同步、辅助模型、记忆引擎配置 |
| `modelWorkspace.js` | 本机／服务器模型配置隔离、模型库与常用线路；旧高级表单仅修改本机 |
| `conversations.js` | 对话管理：切换、打开、从服务器刷新、导出、编辑重发、标题 |
| `voice.js` | 朗读、语音识别、语音对话、听写、唤醒词及语音生命周期 |
| `voiceDevices.js` | 语音自检、人脸跟随、已授权设备恢复 |
| `turn.js` | 一轮调度、朗读分段、插话、打断、后台继续和收尾 |
| `turnInputs.js` | 附件与可见历史、两条图片缓存、模型选择、斜杠技能展开 |
| `turnEvents.js` | 一轮事件到原气泡、进度和状态的显示 |
| `background.js` | 记忆整理、长对话压缩、主动问好、习惯学习、定时任务、系统通知 |
| `toolbox.js` | 智能体工具组装（基础工具 + 电脑操作 + MCP） |
| `remoteTask.js` | 服务器模式：接上服务器上的任务、取回生成的文件 |
| `composer.js` | 输入框、附件、引用 / 朗读按钮 |
| `panels.js` | 右侧面板的切换和创建 |
| `view.js` | 欢迎页、命令面板、主题、更新提示、设置开关、开机动画 |
| `sessionLists.js` | “对话”面板、手机左侧抽屉 |
| `sync.js` | 服务器模式设置面板（OSS 多设备同步已去掉） |
| `recovery.js` | 启动时接回上次的对话 / 没做完的任务 |
| `shortcuts.js` | 键盘快捷键 |

规则：
- 新功能放进对应模块，**不要往 `main.js` 里加**。没有合适的就新建 `app/xxx.js`。
- 模块写成 `export function createXxx(app) { …; return { 对外的函数 }; }`，在 `main.js` 里 `mount(app, createXxx(app))`。
  `mount` 发现重名会直接报错。
- 模块之间只通过 `app.xxx` 调用，而且**用到时再取**；不要在创建模块时把别的模块的东西取出来存着，因为那时它可能还没创建。
- `main.js` 里模块的创建顺序有讲究（后面的模块创建时会用到前面的），不要随意调换。
- 共享状态只放在 `app` 上：`app.session`（当前对话）、`app.active`（正在回答的一轮）、`app.gateway`、`app.llmConfig`、`app.liveBubble`。
  `app.history` 永远等于 `app.session.messages`，是只读的；换对话只改 `app.session`。
- 一个文件尽量不超过 500 行，一个函数尽量不超过 80 行，超过就拆。
- 后端（`server/`）和智能体（`src/agent/`）沿用现有结构；同样不要把新逻辑堆进 `tools.js`、`taskRunner.mjs` 的大函数里。

文档工具在 `src/agent/documentTools.js` 组装，新建、长文、定点修改、方案与验收分别放对应的 document / longDocument / spreadsheetEdit / pdfQuality 模块；不要再向 `tools.js` 的大函数堆生成细节。具体边界见 `docs/交接给Codex-文档制作-20261021.md`。

文档专业工作流 V3 的纯业务模块放在 `src/app/doc/`，由 `createDocumentWorkflow(app)` 注入工作区和模型；前端及服务器复用同一份，不在 `main.js` 新增业务或改变 mount。智能体入口在 `src/agent/professionalDocumentTools.js`，与原生成器分开；前后端辅助调用共用 `src/llm/helper.js`，须透传搜索与重试上限。详见 `docs/文档专家工作流V3.md`。

## 2. 写法

- 用中文注释，写清“为什么这样做”；跟周围代码的命名和写法保持一致。
- 一行只做一件事，不把整段逻辑压成一行。
- `src/app/` 和 `main.js` 用 Prettier 统一格式（`npm run format`）；老文件改到哪里就格式化哪里，不要一次全改。
- 不要直接用和浏览器全局变量同名的名字（`history`、`prompt`、`status`、`name`……）。
  漏改名字时不会报“没定义”，而是悄悄用到浏览器的那个。真要用浏览器的，写 `globalThis.prompt`。lint 会拦。
- 重命名只改标识符，不要全局替换DOM选择器、协议字段或提示文案；搬移后核对字符串字面量及相对导入路径。
- 动态 `import('…')` 的路径相对于当前文件写。从 `main.js` 搬进 `app/` 时，要把 `./` 改成 `../`。
- 新依赖要发布满两周，版本写死（不加 `^`）。

## 3. 数据和状态

- 大块内容（网页正文、文件、图片）不放进对话记录、检查点或 localStorage。要单独存、有编号、按需取，参考 `src/agent/evidenceStore.js`。
- 任何缓存或会增长的数组都要有上限（条数、大小或时间），上限写进注释。
- 用对话 id 时，用这轮任务自己带的（`tool.run` 第二个参数里的 `sessionId`），不要用“界面上当前打开的对话”。
- 写盘要合并（防抖），不要每个事件都重写整段对话。但**会改东西的操作开始前，检查点要立即写完**，服务器重启后要靠它判断那个操作是否做到一半。

## 4. 出错与重试

- 抛错时带上类型：`status`、`code`、`name`，或者直接写 `kind: 'timeout' | 'api' | 'network'`。判断失败原因用 `errorKind()`，不要按报错文字去猜。
- 不要悄悄吞掉错误。尤其是控制信号：用户停止（`AbortError`）、检索预算用完（`RETRIEVAL_BUDGET`），必须往上抛。
- 重试要满足三条：有次数上限；等待时间随机错开（`retryWait`），服务商给了 `Retry-After` 就照它；等待期间用户点停止要立即生效。

## 5. 预算

- 联网和模型调用要在**发请求之前**扣预算（`retrieval.consume`），不要等结果回来再扣。
- 模型自带的联网搜索，在发请求前就按剩余次数限住（`maxWebSearches`）。

## 6. 测试（在 `jarvis/` 下）

- `npm run lint`：检查有没有用了没定义的变量、浏览器同名全局，以及格式。必须通过，CI 也会跑。
- `npx vitest run`：必须全部通过；新功能要加测试；不许跳过或删除测试。
- 构建：`npm run build`、`npm run build:standalone`、`npm run build:mobile`。
- 端到端（改了界面或流程必须跑）：
  - `node e2e/smoke.mjs`（先开 `node server/server.mjs`；跑完关掉，否则 standalone 会因端口冲突误报）
  - `node e2e/standalone.mjs`
  - `node e2e/server-mobile.mjs`、`node e2e/mobile-ui.mjs`、`node e2e/conversation-flow.mjs`（需要 `dist-mobile`）
  - `node e2e/server-mode.mjs <目录>`
  - 桌面版：`xvfb-run -a node e2e/hologram-desktop.mjs`、`xvfb-run -a node e2e/pc-control.mjs`（先在 `desktop/` 下 `npm ci && npm run prepare-app`）
- 没测过的（真机、用户服务器）要明说。

## 7. 互相审查清单

每次改完，另一方按这张表看一遍，结果写进交接文档。清单里的每一条，都是之前真实出过的问题。

- [ ] 有没有把大块数据塞进对话记录、检查点或 localStorage？
- [ ] 新加的缓存或数组有没有上限？
- [ ] 是不是每个事件都写一次盘？该不该合并？
- [ ] 用的是哪个对话 id？后台任务切换对话时会不会串？
- [ ] 错误有没有被吞掉？停止和预算这类信号有没有往上抛？
- [ ] 重试有没有次数上限、随机退避，能不能被停止？
- [ ] 预算是在发请求之前扣的吗？
- [ ] 失败原因是按类型判断，还是按文字猜的？
- [ ] 新代码放对模块了吗？文件、函数长度超了没有？写法和周围一致吗？
- [ ] `npm run lint`、`npx vitest run`、相关 e2e 都过了吗？没测的写明了吗？
