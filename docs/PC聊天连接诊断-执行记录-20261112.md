用户先反馈 PC 智能体列表 Failed to fetch，后又反馈普通聊天、健康检查及“立即更新服务器”均连接失败。列表问题已在 77c9d95 定位：已鉴权资源的跨域路径漏列。普通聊天的 `/api/tasks`、任务事件流、`/api/server/pc-model` 原先已允许跨域，不能把列表漏洞当成全部聊天故障的根因。

用户提供域名后的匿名探测：健康接口出现过 HTTP 200/`ok:true`，聊天预检出现过 204，受保护状态接口按预期返回 401；同时也有诊断代理返回 503/upstream connection timeout。公开 DNS 有两个 IPv4 记录，无 AAAA。分别探测两条地址时均曾收到正常 HTTPS 健康结果，HTTP 80 表现不同；不能仅凭这些结果删除 DNS 记录或断定用户服务器宕机。没有发送用户令牌、读取配置、登录用户服务器或修改反向代理/DNS。已请用户在同一台 PC 的浏览器查看健康页，结果待回传。

## 确认并修复的问题

1. **接收回答断线后静默无限重连。** 旧正式构建收到半句后切断临时服务器，16 秒后仍转圈，没有断线说明；事件流重连失败 10 次。新增观察测试先复现旧问题，再限制连续失败默认最多 5 次。第二次失败显示重连，恢复后显示继续原任务；一次瞬断仍透明恢复。
2. **观察连接与服务器任务分开处理。** 达到上限只暂停观察，不重发 POST 任务、不自动取消原任务；提示服务器可能仍在执行，给“查看原对话”和“检查服务器连接”入口。提交阶段网络/超时没有回执也不能断言服务器未收到任务，同样先查原对话，停止自动发送排队新请求。用户明确停止仍停止原任务。登录失效、越权、任务不存在立即结束观察，迟到轮询不能再恢复连接。
3. **断线提示被覆盖或重新转圈。** `setTask` 会刷新气泡活动，连接状态必须在其后设置。打开运行中会话时，观察失败后不再用旧历史覆盖提示；结束观察清理后台集合并标记结束，切换会话不修改另一会话状态。观察丢失时排队的另一件事放回输入框，不自动启动新任务。
4. **服务器登录错误与模型 Key 错误混淆。** 根据本地请求回执显示固定阶段、HTTP 状态或未收到响应。服务器 HTTP 401 指向服务器登录；模型桥 SSE 中模型返回的 401 仍指向模型凭据。诊断不含完整 URL、查询、任务编号、Key、请求或响应正文；不凭 Failed to fetch 认定一定是 CORS。

没有修改 dsh、模型路由、用户凭据或服务器环境文件。
