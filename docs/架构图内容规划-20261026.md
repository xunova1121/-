# 架构图升级第1块：画前内容规划

目标是用户指定的第二张蓝色总体架构图；本块先解决内容遗漏，不宣称视觉已经达到目标。后续依次补业务卡片/流程箭头、平台布局/网格/通栏、视觉审查与定点修复。原先更大范围的设计循环WIP仍在stash，未混入本块。

## 本块行为

- 图形相关任务注入同一份规划规则：读原始材料，再按展示/用户、业务闭环、平台能力、感知数据、基础设施、安全和标准分类。缺失层不硬造项目事实。
- create_diagram新增可选contentPlan：facts逐条填text/source/excerpt，recommendations单独列建议。user来源绑定本轮rawRequestText；文件来源必须匹配本次实际读取的确切路径。
- 每条事实必须在指定原文摘录中，并完整进入节点标题或说明；不成立在画图前抛DIAGRAM_CONTENT_PLAN，要求补齐，不静默删掉。
- 规划完整正文只存工作区“文档检查/架构内容/<随机ID>.json”，工具返回仅路径、覆盖状态和条数。只核对显式登记的事实，不声称自动识别全部遗漏或业务真实性。不登记的旧调用保持not_checked，旧scene与四格式导出不变。
- 最多80事实、20建议，事实160字、摘录240字、来源400字；无新增模型请求、搜索、依赖或付费接口。模型仍负责选取关键事实，不能把这一道确定性检查描述为自动研究引擎。

## 第7节自查（Codex自查，无独立Claude审查结论）

1. 完整规划仅在工作区，回执只留短指针；原文只作本轮内存核对，不进检查点/localStorage。
2. 数组和文字均有限额；沿原来源4文件、每文件10MB/提取12万字，不扩大。
3. 每次调用最多写一份规划，不逐事件写盘；副作用前原执行器检查点保留。
4. 原话用工具运行参数rawRequestText，不取界面当前对话；规划使用独立随机路径。
5. 来源读取及停止信号沿原入口向上传递；不捕获后伪造成功。
6. 不增加重试、后台循环或付费重提。
7. 本块不调用模型/检索，无新增预算扣除点，原视觉扣费逻辑不动。
8. 新校验失败为带code/kind的输入错误，不按错误文字判断网络或额度。
9. 新规划模块独立；agent及diagramTool局部新增；未动writingRoles、main/mount、scene、导出门槛或旧测试，客户图片未入仓库。
10. 测试结果另记交接顶部；真实付费模型/视觉、用户服务器及安卓/Windows真机未测。
