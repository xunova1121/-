# 智能体升级第一批：需求原文与上下文保护

基线：Claude 发布的 1.0.119，提交 `59a941f2934e89d84bd0870d0933a3793d382740`。

## 目标与实际范围

对应总计划 B1/B4/B5 的第一部分：多轮修改不只依赖滚动摘要，能够找回用户的完整原话；工具结果缩短后有明确的回读入口。没有重写现有架构、改首页样式、增加依赖或引入运行时；Claude 的公式检查、PPT 检查、流式网络、诊断和技能均保留。

## 已实现

- 会话保存前采集用户原话，保存在同一会话的 `requirements` 字段。记录原文、时间和稳定编号，包含原话中的附件路径；不把助手、网页、工具结果转成用户要求。
- 先采集原文再保留最近400条消息。升级旧会话时从仍存在的消息补建；无法找回升级前已经丢失的历史，也不声称可以恢复。
- 主循环独立带上需求索引，包含最早记录、最近记录及与当前任务相关的摘录。明确摘录可能不完整、后续明确修正优先、话题变化不要套用旧要求。
- `read_task_requirements` 支持原话子串检索、编号读取、索引分页和原文字符分页。尾部要求可以继续读取；附件路径并不等于附件内容已读过。
- 普通入口、保存关闭时的当前会话和团队执行共用记录；团队规划、审核、汇总收到同一索引，执行角色可回读原文。团队自动生成的步骤不写成用户原话。
- 早期工具结果缩短前，最多缓存256,000个UTF-16字符（正文约512KB）；`read_tool_result` 按编号分段读取，保留工具名、调用编号、失败标志。缓冲仅限当前运行、不落盘、不复制截图，超出上限或过期就明确要求重读来源。
- 主循环只修改自己的消息副本，避免压缩改变调用方历史。
- 回答长度按任务调整，不再强制所有问题只用2–5条、3–8行；需要详细计划时可以完整说明。
- 增加验证分支的发布隔离：各分支仍执行原有完整验证和打包，只有指定开发分支或明确版本标签可以更新正式安装包。

## 限制与下一步

- 这次先保存有来源的原话，不会自动判定每一条硬约束是否已经满足。结构化目标/约束/验收状态、文件内容版本证据和任务检查点尚待后续批次。
- 不承诺永久记忆、自动跨设备合并每条冲突、跨进程恢复工具原文缓冲。会话删除会一起删除账本；整条会话的JSON备份/同步携带新字段，现有Markdown导出仍按消息列表输出。
- 原文记录仍需模型正确阅读和执行；JSON数据边界和提示不能证明已解决所有提示词注入风险。
- 没有配置可供评测的真实模型密钥，本批不声称测得模型智力、真实任务成功率或达到Codex水平。
- 没连接用户Windows/HarmonyOS4.2真机；不宣称修复了所有渲染崩溃或完成真机稳定性验收。
- 后续依次推进实际模型/接口探测与耗时、平台能力登记、持久任务检查点、受控执行环境，再接Office真实成品检查和工程测试。

本批是总计划的第一项完整改造，不能将其标记为37项能力升级全部完成。
