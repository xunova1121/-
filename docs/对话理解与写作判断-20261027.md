基于正式分支 ac7422f，新分支 codex/dialogue-care-20261027。未改 writingRoles.js、界面入口、依赖、模型配置和已有测试。用户原始医疗对话、图片和数值不入仓库。

## 判断依据与实现

历史导出显示表达偏好被口头确认、短改写曾约一分钟中断。代码中可复现短改写进入普通查询时限、关键词检索漏掉原话题表达偏好、短医学解释默认低推理、长文档规划鼓励惯常结构。没有生产日志，不能断言每个现象的唯一原因，也不能确认当时偏好实际写库；没有原报告图片，不复核原医疗结论。

- responseRevision 从最近12条消息定位实质回答和原问题，跳过记忆确认及错误提示；只对明确改写/指代追问继承话题，普通新问题不串题。纯改写不走查询60秒时限、不自动联网；明确要求查新资料仍保留搜索。未全局放宽超时。
- communicationPreferences 识别用户明确表达要求，仍由原 remember 工具实际保存并给回执；不根据情绪推测长期事实。按关怀/写作/一般三个范围读取最新偏好，支持更正、删除；不将人名或无关事实当风格。不放松原有其他偏好的证据要求。
- responseGuidance 在本机、服务器共享主循环的普通/轻量/常识路径中工作。结合可见内容解释、不虚构用户情绪、不保证医疗安全；用户要求不安慰时尊重。看图时只条件式读取表达偏好，不能据此推断图中是孕检。图片缺失不得声称重新看过原图。
- router 保留医学解释和改写任务所选模型的默认思考配置；闲聊仍走原快速路径，没有强制换模型或 high 档。
- writingJudgment 复用既有规划、起草、审查、修订调用：读者要做什么判断、主张有什么证据、备选与取舍、异常和行动。取消固定惯常目录暗示；情感文章基于用户具体细节，不捏造经历。没有新增逐回答审查调用，原分节并行和修复上限保留。

## 20题真实评测入口

`jarvis/evals/communication-cases.mjs` 全部为虚构情境，覆盖报告解释、改写、偏好纠正、宠物、人际倾听、紧急风险、任务切换和判断型写作。`node evals/communication.mjs` 只预览，不联网。

实际执行须已登录的服务器令牌通过原安全流程注入环境变量，不能发送到聊天或提交仓库：

```sh
node evals/communication.mjs --live --label=after-same-config --out-dir=/tmp/weiyang-care-after-unique
```

沿用 JARVIS_EVAL_URL / JARVIS_EVAL_TOKEN，不改服务器模型/服务商设置；要求服务器空闲、支持隔离评测。每题独立评测记忆，同题多轮同会话；报告目录必须全新，权限700、文件600。stdout只显示题号和状态用时，完整回答保留私有报告。

记录服务器版本、当前配置、调用和计时；回退或分工标记为混合模型。前后对比须固定相同模型、路由和题目；如比较更强模型另开标签，不混算。按每题检查点人工比较理解是否准确、证据是否够、关怀是否具体、是否遵循当前指令、建议是否可执行，保留回答依据；不靠“温柔”词出现自动判通过。

当前环境没有生产服务器登录和真实模型凭据，未运行真实20题，不能声明共情/深度或耗时已达到某个分数。模拟测试只验证工程路径。真机、用户服务器和真实医学图片未测。
