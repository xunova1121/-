# 后续优化建议：以真实任务交付为目标

本批先补文档工具与验收，不把单元测试数量当成智能水平。后续按收益和风险分批推进，不同时推翻所有模块。

## 第一优先：在真实模型线路上建立交付基线

- 用用户实际服务商、实际运行位置测试普通对话、资料核验、代码修改、三种文档和断线恢复。分清模型线路耗时、工具耗时、整理耗时、客户端观察耗时。
- 保留执行成功与任务完成的区别，记录首字、总耗时、实际工具次数、已知Token/费用、可恢复性。服务商不返回用量时留未知，不估成零。
- 文档按事实正确、要求覆盖、结构、可编辑性、视觉、公式/重算分别验收。前三个交付案例先用脱敏真实资料；本批合成样例只验证机制。
- 固定验收资料与评判表，按版本对比，不把模型自己的一句“很好”作为唯一评分。

## 第二优先：完整企业模板与视觉修订

- 为PPT母版、Word整页结构、Excel模板区域分别建立导入契约，明确哪些对象必须保留，哪些区域允许重排。
- 引入模板预览与选择入口；模板资源存工作区或独立文件库，只给模型短索引，不把二进制放入对话。
- 在真实PDF页面图上做有界视觉审查，并定位到页/对象；修改后重渲染，再比较是否引入新问题。保留人工打开预览的入口和成本上限。
- PPT单页重新设计和Word章节重排使用结构化源稿/修订记录；文件被外部编辑后先校验指纹，不能覆盖用户的新改动。

## 第三优先：资料与数字可信度

- 为关键数字建立来源、期间、单位、原值、计算式和核实状态，输出时区分事实、假设与推断。
- 把跨表勾稽、权重合计、口径一致性变为确定性检查；来源冲突保持可见，不能用一个看似完整的数字盖过去。
- 计算、时间日期、行情与动态事实继续走确定性工具或专门接口；检索失败不能升级成“已经核实”。

## 第四优先：代码与长任务交付

- 代码任务把“发现项目规则—定位—修改—运行项目测试—读回产物—总结风险”连成闭环；失败保存修改与测试回执。
- 项目执行器进一步限制CPU、内存、网络和写入范围，给用户看资源/依赖能力边界；不能把已有受限执行器宣称成任意系统的完整开发环境。
- 恢复以任务ID、证据/文件索引和明确状态接续，不重放结果未知的副作用。

## 第五优先：按证据扩展模型路由

- 先实测每条“服务商+型号”线路的对话、工具、长文、看图和代码表现，再提供任务推荐；不能仅凭模型名字宣称擅长某项。
- 用户默认模型保持明确；备用有顺序、有次数上限，已有半截输出时谨慎切换。不因网页失败就盲换模型。
- 每批只推进一个可验收能力，保留回归与失败样例。目标是常见任务稳定交付，而不是功能列表越来越长。
