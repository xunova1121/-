# App真机密度与启动首帧修复

本轮依据用户1.0.264真机截图调整，不把此前浏览器通过当作真机验收。

- 正文默认14px；标题16px；首页建议13px；辅助10—12px，均用rem保留用户字号缩放。
- 首页收紧角色高度、建议行、间距；在320×640、390×740、412×740的可用视口检查完整建议、文件入口及输入框，不只检查横向溢出。
- 天气改为轻胶囊，图标、城市温度归组，倒三角保留独立点击；天气详情与切城行为不变。
- 模型选择回到输入框第二行，与＋、语音/停止、电话/发送对齐；空输入保持紧凑，长输入自然增长，长型号省略且可点击完整选择。
- 用户气泡正文也显式改14px；收紧内边距、时间与操作栏，短句不再占大块空白。保留复制、引用、编辑与正文完整内容。
- 首帧保护放在HTML head，不依赖主JS返回。启动样式单独作为首屏样式加载；初始化/图片解码完成后才揭开主界面，避免原生桥等待时露出旧光核骨架。
- 角色图片解码等待上限1500ms，失败或卡住时使用原静态标志，避免透明空头像；若随后恢复加载则恢复新图集。不改用户头像配置或应用签名。
- 启动8秒看门狗改为浅色页提示与重试按钮，不再删除遮罩露出旧骨架。减少动效/兼容渲染仍按原设置处理。

测试断言变更理由：用户明确要求小字号、小角色、框内模型布局，因此更新与旧版尺寸/框外模型绑定的视觉断言，保留全部功能断言；增加双方正文14px、短句气泡高度、低可用视口一屏完整及延迟主JS时的真实首帧断言。首帧延迟模拟原生桥等待，不冒充Android真机。

未添加第三方依赖或收费服务，不修改搜索、模型路由、语音协议、会话/文件数据；main.js与mount顺序不动。正式结果和规范第7节自查在交接顶部记录。
