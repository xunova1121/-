# 模型与服务商怎么配置

设置页先选本机或云服务器：这里选的是**正在编辑哪份配置**，不改变当前任务的运行位置。页面会写明“正在修改本机／服务器配置”。

1. 添加服务商。官方服务商直接选名称；中转站选一条自定义线路，再改成你认识的名称，例如“供应商 A”。不同中转站使用不同线路槽，地址和密钥分别填写。不要把两家供应商的同名模型合成一条。
2. 保存后点“拉取模型”。本机配置由本机拉取，服务器配置由服务器拉取。服务器真实密钥不会传回手机；拉取不会改变默认模型。
3. 在“管理全部模型”搜索型号。分类依据型号名称识别，只供筛选，不是能力实测。每次显示12条，点“显示更多”继续。接口不支持列表时，在服务商配置中手动输入完整模型ID。
4. 给经常使用的模型点星标，对话选择器只展示常用和默认型号。设默认会关闭自动分工，写作、代码、对话都用这个综合模型，直到自己切换。
5. 需要故障备用时点“设备用”，最多两条，按标出的顺序尝试。不会轮流调用；已有部分回复时不无条件换模型。可点“关闭自动切换”只保留一个默认模型。未迁移的旧配置明确显示沿用旧规则，不会静默修改原有分工。

对话框显示“本机 · 型号”或“云端 · 型号”。点开后按服务商分组选择常用模型；这里的运行位置开关会重新加载对应位置的会话，正在执行任务时不允许切换。服务器模式开启高级分工时显示“云端 · 自动分工”，可在模型管理页统一使用默认型号。

本机运行是指本机调用模型API、执行任务，不等于模型权重在手机或电脑里。只有明确部署Ollama等本地推理服务，才是本地模型；服务器上的Ollama指服务器自己的本地推理服务。

“从本机复制模型配置”先展开查看影响，再点击复制。会复制本机填写的模型密钥，不复制声音和搜索密钥；本机网关环境变量里的密钥不能自动复制，服务器仍需单独配置。两套配置不会自动互相覆盖，服务端掩码也不能当成真实密钥复制回本机。

App和服务器都要更新，服务器旧版本没有新的模型目录接口时需要先升级服务器。未连接服务器时，先到“设置 → 服务器模式”登录。本文描述配置流程，不代表已在用户真机、生产服务器或真实模型线路验收。
