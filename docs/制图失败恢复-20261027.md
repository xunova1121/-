# 第一批：制图失败恢复（2026-10-27，已发布1.0.305）

用户授权先按BUG计划逐批修复。本批基于1.0.300后正式9d6dc3c，仅处理制图重复失败、错误定位和确切版本；不扩展新制图引擎、不动writingRoles/main/mount、不改依赖和已有测试断言。没有用户服务器登录、原始招标文件或真实模型凭据，不能宣称客户同材料已验收。

## 原因与修复

- 执行器原先按工具名+完整参数计数，改标题/摘录或格式就能继续失败；新增本轮局部恢复器，同目标同阶段最多3次确定性失败（首次+两次修复），整轮最多6次，换路径也不能无限消耗。原相同参数两次执行门槛保留，第三次图形重复立即结束。
- 只对图形工具的类型化输入错误计数，不把网络、停止、预算或未授权当成材料错误。不自动重试网络，也不改变原适配器重试/退避。读取普通文件不会清空次数；对应制作真正成功后清除该目标连续失败，整轮总额度仍保留。只有真实用户插话才重置本轮恢复状态。
- 原文事实检查保持严格：区分来源未读、摘录不在原文、事实不在摘录、事实未入图，提供facts数组下标、字段与修复动作，不输出整篇材料。最多8条、字段120字/动作180字；同一code继续兼容旧调用，不把建议改成事实。
- 明确来源读失败提供材料阶段诊断，不借另一份同名材料。原底稿、原文与源稿摘要检查、四格式同稿、原生PPT对照门槛保持。
- 用户明确用反引号/Markdown链接指定文件时，按完整文件名核对；“图.svg”不能因是“旧图.svg”的子串而误用旧预览。普通路径兼容原行为，未假装解决所有自然语言指代歧义。
- 达到恢复上限立即结束当前模型循环，给出当前阻塞点，不再额外调用模型解释/重试。已排队的后续副作用不执行；工具响应配对补齐，用户同时补充新要求仍能继续，不丢插话。已有文件保留，不因失败自动删除或改动。

## 验收与边界

新增tests/diagramRecovery.test.js覆盖字段诊断、同目标变参数/换格式、换路径总上限、成功/普通读取的恢复边界、明确旧路径、失败后修正并实际生成SVG、同批副作用不执行及用户插话协议配对。材料全部虚构。

新增e2e/diagram-recovery.mjs：错误摘录阻断→修正摘录→真实SVG/PNG/PDF/PPT同稿导出→原材料/旧材料字节不变。新增到原完整CI，不删除原门禁。已在本环境执行通过，visual=not_checked；真实四格式不等于真实主模型/视觉模型的业务与美观验收。旧架构原生可编辑PPT的强对照测试仍按原流程运行，本例展示PPT不冒充原生编辑。

初轮相关33项及实际四格式通过；完整回归、三端构建和原端到端最终结果后补。没有拿模拟模型说“专业水平提升”。本批不解决Word丢正文、足球状态、云端提醒等后续问题。

## 第7节逐项自查（开发者本人，非Claude独立审查）

1. 恢复状态仅本轮内存，不放原图、正文、完整参数或模型提示；诊断只含有界字段和动作。
2. 计数表最多24项、目标400字，实际整轮6次失败即停止；诊断最多8条，无无限缓存。
3. 不增加事件写盘次数，复用原操作前检查点与成果账本；副作用前写盘不变。
4. 恢复器由本轮runAgent创建，按实际sessionId记录；后台切换对话不共用状态。
5. 原AbortError/RETRIEVAL_BUDGET继续上抛，未授权不计恢复失败；插话不丢。
6. 首次加最多两次同阶段修复；没有新增自动网络重试或等待，原退避保留。
7. 不新增模型请求，恢复终止反而少一次模型收尾；原请求发前预算扣减保留。
8. 错误按code/kind分型，不按报错文字猜。来源失败保留cause。
9. 恢复独立模块，小范围接执行器/规划器；不整文件覆盖，不搬大架构。
10. 原断言不删/不跳/不松，新增单测和真实产物E2E；最终检查与未测范围据实补记。
