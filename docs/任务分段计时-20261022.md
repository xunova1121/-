# 任务分段计时

本轮增加诊断口径，不承诺实际提速。数据沿用服务器任务的 timing 快照、最终消息、检查点和服务器“任务耗时”日志返回；原字段与 measurementVersion=2 保持兼容，新增 breakdownVersion=1。

| 字段 | 含义 |
|---|---|
| queueMs | 创建到实际执行的等待 |
| contextMs | 主循环上下文准备累计 |
| modelMs | 主循环模型请求累计，含适配器内重试等待 |
| modelWaitMs | 每次模型请求开始到应用首个可观察输出；完全没有输出则计到请求结束 |
| modelOutputMs | 首个可观察输出到请求结束 |
| modelFirstOutputSamples | 实际观察到首个输出的请求数 |
| lastAnswerModelMs | 最近一次成功返回答案的完整主模型请求耗时；新请求开始后清空，失败或工具调用不当答案 |
| searchMs | web_search 工具耗时，同类并行区间取并集 |
| readMs | fetch_url 工具耗时，同类并行区间取并集 |
| researchMs | fact_check / deep_research 复合工具耗时，可能包含搜索、阅读和辅助模型 |
| otherToolMs | 其他工具的区间并集 |
| toolMs | 所有工具的区间并集，保留原定义 |
| phaseOverflow | 超过128个同时在途工具时为true，该轮分类计时不完整 |

## 口径限制

- 首个可观察输出不是网络首包。流式文字/原生搜索事件可立即观察；工具参数只在完整返回时提供的接口，观察点在请求结束。没有服务商网络时序，不能据此拆分供应商排队与模型推理。
- 不同工具分类可能重叠，所以 searchMs+readMs 等不能直接相加当作 toolMs 或 totalMs。
- 原生搜索发生在模型服务内部，目前只有调用次数，不能将模型请求时间整体冒充搜索时间。searchMs仅指应用工具，零不证明原生搜索耗时为零。
- 辅助模型保留原有 helperModelCalls / helperInputChars 计数；其耗时可能在 researchMs 内，未并入主循环 modelMs。不能把这些指标当全部服务商账单或Token用量。
- 最后一次成功答案仍可能是解释失败的答案；时长不是语义质量或业务完成的证明。
- 只保留数字、布尔值和短状态；在途编号最多128个，结束即移除。不保存问题、网址、工具参数、文件正文或密钥，不新增模型请求、不逐事件新增写盘。
- 真实性能对照必须在同服务商、同模型、同题目与相同配置下完成。当前环境无生产登录/真实模型凭据，自动测试使用假响应，不代表真实提速。
