在你做的 1.0.194“检索智能体流程优化”（d30bd9c、4142d51）基础上，用户请我做了一次架构审查，然后按审查意见改了代码。

## 一、审查发现的问题（为什么要改）

| 维度 | 问题 |
|---|---|
| 内存/写盘 | 证据（3 组 × 4 篇 × 6000 字 ≈ 72KB）放在 `session.taskCheckpoint.evidence` 里：每次读对话都带上；打开对话会下发到手机并写进手机缓存；查证时每读完一页 `onEvidence` 一次，就在锁里把整段对话 `sessions.save` 一遍（写入放大） |
| 内存 | `recoveryCheckpoints` 条数不封顶，最新一条还带着完整正文 |
| 串号 | `fact_check` / `read_task_checkpoint` 用 `ctx.currentSessionId()`，本机模式下这是“界面上当前打开的对话”，后台任务切对话后会读到别的对话的证据（服务器端每个任务一个 sessionId，不串） |
| 预算 | 模型自带的联网搜索（Anthropic `web_search` server tool）是在流里看到“已搜”事件后才 `begin()`，钱已经花了才拦 |
| 预算 | `web_search` 的 catch 把 `RETRIEVAL_BUDGET` 包成“搜索失败”字符串还给模型，模型会换词再搜，白跑几轮模型请求；某一类次数用完也不会让主循环收尾 |
| 预算 | `fetch_url` 在校验网址之前就扣了读取次数 |
| 异常 | `interruptionMark` 只按报错文字猜，`/API/i` 会把 `fetch failed … api.deepseek.com` 判成“模型接口出错” |
| 重试 | 固定 1.5/4/8 秒、没有随机、不看 `Retry-After`；服务器上同一个 Key 一起被 429 时会同时重试 |
| 上下文 | `checkpointView` 去掉了正文，但没有任何办法按索引取回正文；模型要细节只能重新 `fetch_url`（重新联网、再扣预算） |

## 二、改了什么（按文件）

### 1. 新增 `jarvis/src/agent/evidenceStore.js`：证据单独存放
- 存在 `collection('kv')` 里，一段对话一条：`evidence:<对话id>`；另有 `evidence:index` 记录哪些对话有证据、最后用的时间。
  - 用 kv 是故意的：不用升级 IndexedDB 版本（新建表要 bump `DB_VERSION`），服务器上 fileStore 也照常能用。kv 目前没有任何地方 `all()` 遍历，放心。
- 上限（`EVIDENCE_LIMITS`）：每段对话 12 篇、每篇 6000 字；只留 24 小时内用过的 30 段对话（多了删最旧的）；内存里也只缓存 30 段。
- 写盘合并：`put()` 只改内存并在 1 秒后统一落盘；`flush()` 立刻写（服务器任务 `finish` 时会调）。
- 按对话隔离：所有读写都必须带对话 id；`get(sid, id)` 拿不到别的对话的编号。
- 编号：`evidenceId(url)`，网址的 FNV-1a 哈希，形如 `e1a2b3c`，同一网址同一编号。
- API：`put(sid, {key, savedAt, sources})` → 编号数组；`get(sid, id)`；`index(sid)`（不含正文）；`records(sid)`（按查证问题分组，给 factCheck 复用）；`drop(sid)`；`flush()`。
- 全局单例 `evidence`；`sessions.remove()` 会顺带 `evidence.drop(id)`。

### 2. `jarvis/src/agent/tools.js`
- 新工具 `read_evidence({id?})`：按编号取回原文（≤6000 字），不联网、不扣预算；不填编号列出全部。已加入 `PARALLEL_SAFE`（agent.js）和只读工具名单 `READ_ONLY`（taskCheckpoint.js）。不在 `WEB_TOOLS` 里（检索收尾后，深度任务仍可用）。
- `fetch_url`：先校验网址再 `consume('read')`；读到的正文存一份证据，结果末尾加“（已存为证据 eXXX，之后要看原文用 read_evidence）”。
- `fact_check`：`onEvidence` 改为写 `evidenceStore.put(sid, …)`，不再发 `retrieval_evidence` 检查点事件；“继续/恢复/接着”时用 `evidenceStore.records(sid)` 复用（复用规则仍是你的：同 key、10 分钟内）。
- `read_task_checkpoint`：额外返回 `evidence: [{id,url,title}]`。
- `web_search`：预算错误不再吞掉——别的词搜到了照常返回（没搜的词显示“没有搜：…”），全部没搜到才把 `RETRIEVAL_BUDGET` 抛给主循环。
- 这几个工具取对话 id 的方式：`opts.sessionId ?? ctx.currentSessionId?.()`。

### 3. `jarvis/src/agent/agent.js`
- `tool.run(args, { …, sessionId })`：把这轮任务所属的对话 id 传给工具（`runAgentLoop` 本来就有 `sessionId` 参数）。新工具要用对话 id 时，请用 `opts.sessionId`，别用 `ctx.currentSessionId()`。
- 请求参数：`allowWebSearch: !closing && retrieval.left > 0, maxWebSearches: retrieval.left`。

### 4. `jarvis/src/agent/retrievalBudget.js`
- 某一类（search/read/model）用完时会设 `reason`，主循环下一步进入收尾（普通查询不再给工具，直接用已有资料回答）。
- 新增 `get left()`：还能联网几次（普通查询 6 − 已用；深度任务 Infinity；已收尾为 0）。

### 5. `jarvis/src/llm/anthropic.js` / `responses.js` / `openai.js`
- anthropic：`max_uses = min(5, maxWebSearches)`，`maxWebSearches < 1` 时不带联网搜索工具。responses 接口的 `web_search` 没有次数参数，只受 `allowWebSearch` 控制。
- openai.js 新增并导出 `retryAfterMs(value)`、`retryWait(base, err)`、`sleep(ms, signal)`：
  - 等待时间 = 基准 × (0.5~1.0 随机)；错误带 `retryAfterMs`（来自 `Retry-After` 头）就照它，最多 30 秒。
  - 三个接口的重试都改用它；HTTP 错误对象上带 `retryAfterMs`；等待中用户点停止会立刻结束（以前 anthropic/responses 用的是不可中断的 setTimeout）。

### 6. `jarvis/src/core/suggest.js`
- 新增 `errorKind(err)` → `'timeout' | 'api' | 'network' | ''`：
  - 先看结构化标记：`err.kind`；`stalled` / `TimeoutError` / `LookupTimeoutError` / `LOOKUP_TIMEOUT` / `RETRIEVAL_BUDGET` / `ETIMEDOUT` → 超时；`status >= 400` → 接口；`ECONNRESET` 等错误码、`TypeError: fetch failed` → 断线。
  - 只有纯文字才按字面猜，且去掉了会误伤网址的 `/API/i`。
- `interruptionMark(error)` 改为基于 `errorKind`，对外用法不变（字符串、错误对象都能传）。
- 以后新增出错路径：请在抛错处带上 `status` / `code` / `name` 或 `kind`，不要指望事后按文字猜。

### 7. `jarvis/server/taskRunner.mjs`
- `saveCheckpoint(task, now)`：检查点每秒最多落盘一次（`CHECKPOINT_MS.value`，测试可调）；**会改东西的工具（`!isReadOnlyTool(name)`）开始前仍然立即写并等它写完**——服务器重启后要靠它判断 `needs_review`，这个保证不能去掉。`finish()` 会清掉待写的定时器，统一写最终状态，并 `evidence.flush()`。
- 失败时把 `errorKind(err)` 传给 `finish`，`interruptionMark({message, kind})`。
- `recoveryCheckpoints` 最多留 5 次；归档时去掉旧版检查点里的 `evidence`。

### 8. `jarvis/shared/taskCheckpoint.js`
- `retrieval_evidence` 事件处理和 `checkpointView` 保留（兼容 1.0.194 留下的旧数据，旧测试照常通过），但新代码不再产生这个事件。**请不要再把网页正文放回检查点或对话记录。**

## 四、没做 / 留给后面
1. 主循环模型请求按 token 计预算（各接口 usage 字段不统一，需要先统一 adapter 返回的用量）。
2. 深度任务只有 8 分钟时间上限，没有次数上限；`extensiveRetrieval` 的关键词（“代码”“文件”“对比”）偏宽。
3. factCheck 内部并发读页没有共享的中止控制：时间预算到点后，已发出的读页靠外层 `withWebDeadline` 才停。
4. 证据复用仍只在“继续/恢复/接着”时生效，key 是整段问题的精确匹配；要提高命中率可以改成按网址复用（`read_evidence` 已经能按网址编号取）。
5. 本机模式（电脑/手机不连服务器）的检查点仍由 `main.js` 写进 pendingTask；证据已经不走这条路了。
