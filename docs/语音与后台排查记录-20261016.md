# 语音与后台排查记录

设备信息来自用户：鸿蒙 4.2，型号表述为“Pro70”，尚未确认完整型号。无法连接用户真机，以下区分代码中确认的问题与尚需实测的服务兼容性。

## 在代码中确认的问题

1. 系统识别器在部分手机只能以独立识别窗口工作。该窗口让未央进入不可见状态，旧的 visibilitychange 处理随后关闭通话、取消识别。修复：识别窗口事件与真正离开应用分开；音频立即静音，取消录音延后核对前台状态，处理 onResume 与 WebView 可见性回调先后差异。
2. 原生识别的中间结果、收音状态和音量没有交给界面；遇到厂商服务异常只重试并关闭，没有明确的识别链路回退。修复：显示原生回调，先尝试系统窗口；继续失败且配置了转写服务时切换轻量云端转写。系统窗口被取消不反复重开。
3. 云端音频通过安卓原生网络回退时，没有要求二进制响应。它可能按文本构造 Response，导致音频解码失败。修复：语音合成请求显式使用 binary，原生插件返回字节；失败显示实际服务错误。
4. 自动音色选择优先尝试非官方免费朗读，失败后改用系统声。Edge 外部协议当前版本也已变化，旧链路不应被视为已验证的固定音色。修复：更新到 v2 连接签名，安卓和网关共用签名实现；与独立协议参考的固定时间向量一致。用户暂无语音服务，自动模式在手机继续优先免费晓伊女声；已有正式语音服务密钥时优先对应服务。模型中转语音只作为显式选项或无免费渠道时的后备，不因聊天密钥存在就优先付费语音。增加可选 Azure 晓双 / 晓悠配置，但不要求用户购买。失败显示实际服务和系统回退，不承诺非官方免费渠道长期可用。
5. 旧“检测语音”只测试系统 TTS，无法证明当前选中的云端女声可用。修复：检测实际配置的引擎，完成合成、解码与播放后显示引擎、声音名；记录阶段和错误，不记录录音、识别文本或密钥。
6. 任务没有安卓前台服务保护，WebView 可能在后台被降优先级；语音队列也可能继续播放。修复：正在运行的任务使用静音前台通知和有期限的唤醒锁，结束后释放；任务与朗读分开控制，后台清空语音播放队列，不取消 agent 请求。

## 必须分开的能力

- 聊天接口可用 ≠ 转写接口可用 ≠ 女童音色合成可用。现有中转密钥可以尝试相应接口，但服务商必须实际支持。
- 晓伊 / Shimmer 属于年轻女声，不声称它们是固定女童。真实女童使用 Azure 晓双等服务音色，需要用户在 App 填写自己的语音服务密钥和区域。
- 已开始任务的常规后台执行可以做保活；系统强制停止、清理应用、厂商后台限制仍可能终止进程。前台服务不等于服务端托管，不能据此保证被强杀后继续执行。

## 尚需真机证据

鸿蒙系统识别是否可发现、系统窗口是否返回中文结果、服务商是否开放语音接口、实际音色是否符合用户听感，以及切换其他应用和锁屏时后台任务的持续性。自动化测试只能验证代码与控制流程，不能代替这些结论。

## 10 月 16 日渲染进程连续异常

用户的 1.0.88 截图：WebView 114.0.5.302，可用内存 5090MB，lowMemory=false。此证据不能把原因归为系统内存不足，也不能排除渲染进程自身的内存或绘图问题。

代码中确认的放大因素与处理：

- 一次渲染异常后，原生层强制软件绘制 24 小时；移除此逻辑，保持平台默认绘图路径，改用减少动画、滤镜与合成层的兼容显示。
- 原来每次渲染异常都 recreate，可能循环重开；现在 5 分钟内最多自动恢复一次，同时开启兼容显示。再次异常停留在原生恢复页，允许手动重试、复制诊断或退到后台；不清理用户数据。
- 异常处理器重复安装、日志完整读入：改为进程内只安装一次、日志有界轮转、只读取尾部。
- 手机原来重放整段历史且每条消息都触发布局；改为标准显示每页 24 条，兼容显示每页 12 条，批量绘制后统一滚动。翻页不删除记录，不改变模型上下文或导出。
- 兼容显示开关位于设置，可即时切换；任务执行时不重绘当前消息，后续轮次再应用条数限制。后台任务与音频策略保持分开；若整个渲染进程已退出，停止保活服务并明确要求检查未保存任务，不声称进程崩溃后任务仍可继续。
- 新增 didCrash、退出优先级、Java 堆、设备及连续异常次数诊断，辅助下一步区分系统回收与实际崩溃。界面进程原生崩溃的最终触发点仍需真机日志，以上不能表述为已在鸿蒙上永久根治。
