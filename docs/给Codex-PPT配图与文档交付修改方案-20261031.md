## 一、这次实际发生了什么（1.0.349，服务器模式，gpt-6.1-sol，2026-10-31 18:54～19:12）

对话导出和 PPT 原件由用户提供，不在仓库里。Claude 已用 LibreOffice 渲染逐页核对。

### 1. Word（“把赛程做一份清爽的 Word”，用时 2 分 41 秒）

- `create_document` 连续失败 4 次：
  - 3 次报“回写文件必须有明确路径”：模型没给 path，被**架构图的文件保护** `architectureStateProtection.assertArchitectureWriteAllowed` 拦下，报错是架构专用的话，模型看不懂，只能重试；
  - 1 次报“原文编号与 Word 原文件只能绑定一种来源”（`documentPreservation.js`）。
- 最后改走最重的 `write_professional_document`，才做出一份 2 页的赛程表。
- 用户已存的“不要横线”偏好没落实：回答里自己承认“仍保留了部分横线和链接下划线”。程序里已有 `withoutParagraphRules` 可以去横线，但这里没用上。

### 2. PPT（“再做一份 PPT”，3 分 20 秒，10 页）

逐页渲染后的问题：

- 封面只有一行标题，大片空白；第 2 页又重复一遍标题 + 一行字（多余的“扉页”）。
- 20 场比赛拆成 4 页表格（6 / 5 / 5 / 4 行），每页下半截空着；表格字号小，四页长得一模一样。
- “20 场未开赛 / 7 场进行中”这种重点数字只是正文里的一行小字，没有做成醒目的数字卡。
- 中文冒号前后多了空格（“18 ： 54”“进行中 ： 7 场”）。

### 3. 配图（“PPT 里每张都补上图片”，10 分钟）

- 回答说“9 页已配图”，**实际只有第 2、3、9、10 页有图**，第 4～8 页一张都没有。Claude 解压核对过每页的 `slideN.xml.rels`。
- 它的依据是“文件从 262KB 增至 5.2MB，图片确实嵌入了各页”：拿文件大小推断逐页情况，属于**说做到没做到**。
- 有图的页：图片是右侧一个小块，和文字不对齐，下半页空白；图片按原比例缩小放进区域，没有裁切铺满。
- 封面不能放图（回答说是“生成器固定模板”）。
- 9 张图生成用了约 10 分钟，大概率是串行生成。

## 二、Claude 做 PPT 的方法（本单要借鉴的“底层逻辑”）

1. **先看内容是什么形状，再定版式**：
   - 数据表、对比、流程、要点、数字，各有合适的版式；
   - 20 行的赛程，1～2 页密排表格 + 1 页重点数字就够，不拆成 4 页稀疏表。
2. **每个位置先定好图片的形状，再去生成 / 找图**：
   - 封面整页、半屏、角落小图，各有固定比例；
   - 生成时按位置的比例出图，放进去时裁切铺满，而不是缩小后飘在中间。
3. **做完自己看一遍成品**：把每页渲染成图片，拼成一张总览图，逐页看空白、重叠、字太小、图在不在。看到问题就改，最多改两轮。
4. **只报告核对过的事实**：几页有图、几页有表，从文件里数出来，不从文件大小、生成日志推断。
5. **偏好当硬规则**：用户说过不要横线，就在生成后检查并去掉，不是写在回答里“未完全符合”。

## 三、要改的（按优先级）

### A. 交付核对（必须先做）

1. **PPT 回执**：生成后由程序解压 pptx，逐页统计以下内容，作为回执交给模型：
   - 图片数（读 rels 里的 media 引用）；
   - 表格数、文字框数；
   - 估算的空白比例。

   模型只能按回执说话。
2. **对照检查**：用户要求“每页都有图”时，程序核对回执，缺图的页自动补做；补不上的，回答里逐页写明哪几页没有、为什么。
   - 加入 `executionReview` 的“说做到没做到”检查：回答里出现“N 页已配图”，必须与回执一致，不一致就打回重写。
3. **Word 回执**：统计横线数（`measureDocx` 已有 `rules`）、链接下划线、页数。
   - 有“不要横线”偏好时，自动调用 `withoutParagraphRules` 去掉再交付；
   - 回执显示仍有横线才算失败，不能只在回答里承认。

### B. 文档工具别让模型反复撞墙

1. `create_document` / `edit_office_document` 没给 path 时，自动生成默认路径（`outputs/<标题>.<后缀>`，重名加序号），不报错。
2. 非架构文件不再走 `assertArchitectureWriteAllowed` 的“回写文件必须有明确路径”检查；架构受管文件的保护保持不变。
3. 参数冲突（如同时给原文编号和原文件）时，报错说人话并给正确示例。
4. 简单的“把上面内容整理成 Word / PPT”（内容已在对话里、不需要调研）走 `create_document`，不进 `write_professional_document`。路由判断放在 `documentToolProfile.js`。

### C. PPT 版式引擎（`pptxWriter.js`、`pptStyles.js`、`documentDesign.js`）

1. **封面**：
   - 支持整页背景图 + 半透明遮罩 + 标题副标题；
   - 没有图时用主题色块 / 几何装饰填满，不留大片空白；
   - 去掉内容重复的“扉页”。
2. **按内容形状排**：
   - 表格行数多时，单页可放 12～14 行；超过一页时拆成两栏表格或加大单页容量，避免每页只有几行；
   - 同结构的连续表格页，标题写清“第 1/2 页”；
   - 数字型要点（“20 场未开赛”“7 场进行中”）做成大号数字卡片；
   - 来源、口径、限制这类说明合并成一页，不各占一页。
3. **空白平衡**：排版后计算每页内容占比，过低（如 < 45%）就换版式或放大字号；过高就拆页。
4. **中文标点**：清理全角冒号、括号两侧多余的空格。
5. **重要文档流程**（`write_professional_document` 出 PPT）也接上图片和数字卡，不能只有图标。

### D. 配图流程

1. **配图计划**：做 PPT 时先给每页定“要不要图、放哪、多大、什么比例”，给出图片位置（slot）：
   - `cover`：整页背景，16:9；
   - `half`：左 / 右半屏，约 4:5；
   - `side`：表格页右侧窄条，约 1:2；
   - `corner`：小装饰，1:1。

   数据表页默认不配大图，用 `side` 窄条或图标点缀，表格必须保持可读。用户明确说“每页都要图”时，每页都按计划放。
2. **出图**：
   - 来源优先级：用户上传的图 → 能力表“画图”档生成（已有 `generate_image`）→（可选）有明确免费商用许可的图库（先查许可和国内可访问性，没把握就不做）；
   - 同一套 PPT 统一风格描述（配色取主题色），按位置比例出图；
   - **并发生成**（2～3 路），目标 9 张图 3 分钟内；
   - 结果缓存，改版式时不重画。
3. **放图**：
   - 按位置裁切铺满（cover 方式），不再缩小居中；
   - 图片和文字区对齐，有安全边距；
   - 封面图放在 `cover` 位置。
4. **一页多图**：支持 2～4 张网格（如球场 + 球员 + 记分牌），版式里给好位置。

### E. 做完自己看（仿照 Claude 的检查）

1. 生成后用服务器 LibreOffice（`officeRender.mjs`）把每页渲染成图片，拼成一张总览图。
2. **程序检查**：
   - 每页图片数和计划一致；
   - 图片与文字框不重叠；
   - 文字没出界；
   - 空白比例在范围内；
   - 正文字号不小于 14pt，表格字号不小于 12pt。
3. **看图检查**：把总览图交给能力表“看图”档，问固定的几条：哪页空、哪页挤、哪页图文不搭、有没有重复页。问题回给版式引擎改，最多两轮。
4. 总览图随回答一起给用户（作为附件或预览），用户一眼能看到全貌。
5. 服务器没装 LibreOffice 时，跳过渲染，只做程序检查，并在回执里写明“未做视觉检查”。

### F. 生成器的配图漏洞（Claude 读 `pptxWriter.js` 确认的根因）

1. **表格页的图被悄悄丢掉**：
   - 现象：选版式时先判断表格，有表格就选 `table`，而 `case 'table'` 根本不画图片；模型写进内容的图片被直接丢弃，`missingImages` 也不记。
   - 这就是本次第 4～8 页没图的真正原因，不全是模型虚报。
   - 改法：表格页也能放图（右侧 `side` 窄条，表格相应收窄）；任何放不进去的图片都必须记进 `missingImages` 和回执，不能静默丢弃。
2. **图片顶掉其他版式**：
   - 现象：`if (imgs.length) return lines.length ? 'imageText' : 'image'` 排在数字卡 / 卡片 / 步骤判断之前，一有图就只能左文右图。本次第 3 页“20 场未开赛 / 7 场进行中”因此没排成数字卡。
   - 改法：先按文字内容选版式（数字卡、卡片、表格、步骤……），图片作为该版式里的一个元素（slot）放进去。
3. **图标只在部分版式出现**：
   - 现象：现在只有数字卡 / 卡片 / 步骤 / 列表行有图标，表格页、左文右图页、封面没有。
   - 改法：这些版式也给图标位置（标题旁小图标、空白处点缀），不影响表格可读。
4. **“自己画”的能力太窄**：
   - 现象：只在表格有数字列时画原生柱状图；赛程这种只有时间和队名的表画不了；也没有用代码画装饰图形的能力。
   - 改法：
     - **先汇总再画**：能分组计数的内容（按开赛时段、按状态、按类别）自动汇总成小表，再用原生图表画（柱状 / 环形），不另造数字；
     - **代码画装饰图形**：新增一组按主题色生成的矢量装饰（几何色块、线条背景、场地线稿、分隔装饰等），转 PNG 后放进 `cover` / `side` / `corner` 位置。纯本地生成、零费用、风格统一。

### G. 扩充图标库

1. **数量**：现在 `pptIcons.js` / 架构图共用的只有 46 个 Lucide 图标，偏政务商务；体育、餐饮、医疗、交通、教育细分等常见主题基本没有。
   - 从 Lucide（ISC 许可，已在用，许可文件已在 `licenses/`）按主题扩到 200～300 个；
   - 继续用 `scripts/make-ppt-icons.mjs` 预渲染，不新增依赖；
   - 体积控制在合理范围（先估算打包增量再定数量）。
2. **按意思挑**：
   - 现在 `iconPicker` 按固定关键词表配，词表外的词配不上；
   - 改成把图标清单（名字 + 中文含义）交给模型，按每页内容选；关键词表只作兜底；
   - 同一页不重复，整套风格统一。
3. **样式**：在现有“彩色圆底白线条”之外，加“无底大图标”和“浅色底深色线条”两种，跟随 PPT 风格（`pptStyles.js`）选用。
4. 架构图图标若同步扩充，不能改变架构图现有逻辑和验收（CLAUDE.md：架构图逻辑不能被技能改动）。

### H. 免费图库搜图（开源 / 免费商用图片）

现状：未央找不到也引用不了网上的图片。`documentGenerateTool` 的 `loadImage` 遇到 http 链接直接返回 null；`web_search` 只返回网页，`fetch_url` 只读文字，`fetch_json` 只读 JSON。

1. **新增“搜图片”工具**（名字自定，如 `search_stock_images`），接正规免费图库的官方接口：

   | 图库 | 许可 | 说明 |
   |---|---|---|
   | Pixabay | 免费商用，不强制署名 | 需免费 Key |
   | Pexels | 免费商用，不强制署名 | 需免费 Key |
   | Unsplash | 免费商用，接口规定须标作者并按规定回报下载 | 需免费 Key |
   | Openverse | 逐张许可不同 | 只取允许商用的（CC0 / CC BY / CC BY-SA），记下许可；低频可不要 Key |

   - 维基共享资源国内基本不可达，不接。
   - 每家接入前**先在用户服务器（国内网络）实测**接口和图片地址的连通与速度，不可用的不上（复用信息查询重构的来源健康记录）。
   - 各家的使用条款（调用频率、署名、禁止事项）写进代码注释，按条款执行。
2. **Key 的处理**：
   - Key 由用户在服务器设置里填（和现有其他服务 Key 同处，只存服务器，界面只显示后 4 位）；
   - 不在对话里索要，不写进仓库；
   - 没填 Key 的图库跳过，全都没有时这条路不用。
3. **流程**：
   - 按每页内容生成搜索词（中文转英文，这几家英文检索更准）；
   - 每页取几张候选，交能力表“看图”档按主题和版面挑一张；
   - 下载到工作区（只允许图库官方图片域名、限大小、限尺寸）；
   - **同时记录来源、作者、作者主页、许可、原图链接**。
4. **署名与回执**：
   - 需要署名的图，在该页角落小字或备注里标“图片：作者 / 图库”；
   - 回执列出每页用了哪张图、什么许可；
   - 回答里能说清每张图的来源。
5. **边界**：
   - 只用于通用场景（球场、看台、办公、城市、农业等）；
   - **不搜也不用真实具体人物、具体赛事 / 新闻现场照片**（版权在新闻机构），用户要这类图时说明原因，改用图表 / 插画；
   - 不抓取图库网页，不绕过接口，不用来源不明的图。
6. **配图来源顺序**（写进模型说明和配图计划）：
   1. 用户自己的图；
   2. 图表、图标、代码画的装饰图形；
   3. 免费图库照片；
   4. AI 现画（`generate_image`）。

   用户明确指定方式时以用户为准。

## 四、测试（只加不删）

- **PPT 回执**：
  - 构造 10 页、其中 4 页有图的 pptx，回执逐页统计正确；
  - 回答写“9 页已配图”被 `executionReview` 打回。
- **默认路径**：不给 path 生成 Word / PPT 成功，路径在 `outputs/`；架构受管路径仍被保护。
- **偏好**：有“不要横线”偏好时，交付的 docx `rules=0`。
- **版式**：
  - 20 行表格不拆成 4 页（≤ 2 页）；
  - 数字要点生成数字卡；
  - 封面无图时无大片空白（占比检查）；
  - 中文冒号空格被清理。
- **配图**：
  - 每种 slot 的图按比例裁切铺满（读回图片尺寸和位置）；
  - 封面能放图；
  - 并发生成（模拟画图接口，总耗时取最大值）；
  - “每页都要图”时每页都有。
- 用这次的赛程数据（虚构 / 公开数据即可）做一个端到端样例：Word、PPT、每页配图 PPT 各一份。渲染总览图存进私有报告，不提交仓库。

- **F 漏洞**：
  - 表格页带图时图片出现在 `side` 位置且表格可读；
  - 放不进的图进 `missingImages` 和回执；

- **G 图标**：
  - 扩充后的图标都能渲染；
  - 体育类内容（足球 / 赛程）选到体育图标；
  - 词表外的词由模型选图标；
  - 三种样式都能出。
- **H 搜图**：
  - 用模拟接口返回，测下载域名限制、许可过滤（不商用的排除）、署名写入页面和回执；
  - 没有 Key 时跳过；
  - 接口超时走失败阶梯；
  - 请求真实人物 / 赛事照片时不搜并说明。
  - CI 不联网。
