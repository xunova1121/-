# 文档专家工作流 V3：第一批

本批范围：任务底稿和业务推演、起草、内容审查、最多一次定点修订与复核。保留原文件生成、公式检查和渲染能力，不新增视觉引擎、联网研究或多智能体循环。没有引入依赖，没有复制闭源产品代码。

## 使用

重要方案、研究报告、决策PPT和复杂Excel优先调用 `write_professional_document`，传完整用户要求、材料或 `material_files`。`generate_task_brief` 只生成底稿；其返回的 `state_file` 可以继续。简单邮件等可用 simple 或原 create_document。自动分级是有限规则，不宣称完整语义识别；明确的重要任务应指定 expert。

专家流程通常三次模型调用：底稿与推演合并一次、正文一次、审查一次；需修订时最多再调用修订和复核两次。默认同一写作模型，不擅自使用另一个服务商；显式配置 documentReviewer 时才使用该审查函数。未增加用户设置页。

无自动重试。每次调用前扣本轮 model 资源预算并保存阶段，单次120秒可取消；显式恢复后累计最多8次调用。这些是逻辑辅助调用次数；底层协议兼容降级仍可能产生额外HTTP请求，不当作完整计费计数。每任务最多40个状态文件、每份最多2MB，原始要求16000字、材料48000字、正文64000字，超限直接报错，不静默删要求。Token未知为null，不作零费用宣传。阶段调用数不含既有生成器的公式/视觉修复。

## 需求与质量

需求必须摘录输入原话，编号追踪；审查同时读取完整原始要求，不能只信底稿。用户事实、带前提建议、未知事项分开。业务推演根据文种调整，不硬编码水产业务。

内容审查必须提供覆盖结果、正文证据和具体问题；缺需求编号、重复编号、无法回查的支撑片段不能算通过。程序不能证明模型语义判断正确，因此 `model_reviewed` 不等于人工或事实验收通过。修订只接受唯一匹配的片段，冲突整批拒绝，原稿保留；一次修订后仍有严重问题标 needs_revision，不无限循环。

若生成器的后续公式或版面修复改变正文，内容状态降为 needs_recheck，避免沿用旧结论。生成、转换、视觉和内容结果独立；第一批不新增渲染和看图修订。

## 存储和恢复

底稿、正文、初稿、审查、修订及耗时保存在工作区 `文档流程/<唯一任务编号>/`；不是对话正文、检查点或localStorage缓存。检查点只保存阶段、恢复路径，每次写文件前沿用tool_start即时保存。恢复严格核对任务sessionId，不读取界面当前对话。失败保留上一阶段，显式传state_file后继续；不是自动重放外部操作。文件夹模式采用不可变状态文件，不依赖覆盖写。

只读原始资料、原模型线路，生成器遵循原有工作区版本备份与改名机制。已生成文件再次交付仍可能另存新版本，需要先核对产物，不宣称自动幂等。

## 验收

机制测试使用明确测试替身，验证时序、预算、取消、唯一匹配、恢复隔离；真实文件集成测试核对工作区产物及报告，不能代替模型质量评测。

真实验收脚本 `node evals/document-live.mjs` 默认只预览；在有配置的服务器上显式传 `--live --data-dir=... --task-file=... --out-dir=<新目录>` 才调用真实模型。原始需求由私有文本提供，不把用户文件或商业沟通原文提交公开仓库。输出底稿、初稿、问题、终稿和调用耗时，未测过不能写已验收。

水产方案验收：保留用户给出的养殖区、合作核心区及周边农户边界，不把面积擅自相加；保留自动称重、快检、暂养冷鲜、银行清分与业财、设备管理及AI分析；提出明确推荐流程并解释筐重、水重、净重、货权、损耗、成本归集及结算，减少重复待确认。具体推荐仍需业务人员核对，不能靠关键词命中自动认定专家水平。

## 本批不作的承诺

不承诺生成即专家、不承诺固定评分或省时比例。完整需求审查仍有模型判断风险；没有真实模型语义验收不能宣称质量已达标。独立审查目前是受控注入接口，默认生产调用仍为同一写作模型，尚无新的配置界面。私有知识库、引用核实、联网研究和视觉修复属后续批次。
