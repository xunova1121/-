# 海报与 Demo“先想后做”（2026-11-17）

用户反馈三件事（导出 404、海报硬拼、历史稿太多）修完后，又和 Claude 讨论了海报和 Demo 的做法，要求“全部做，统一发版”。本文记录做了什么、怎么判断、哪些还没验收。

## 讨论结论：分工原则

**AI 负责好看，程序负责不出错。** 模型自由构图，不套固定样式；程序只做保护，不管风格。保护包括：文字不溢出、看得清、不超出画布，以及颜色、对齐线、字号层级的体检。

| 内容 | 谁做 |
|---|---|
| 图表、数字 | 程序画（chart 图层），绝不让生图模型画 |
| 照片、插画、氛围图 | generate_image（poster_art） |
| 图标 | 内置矢量图标 |
| 文字 | 程序用真实字体排 |
| 交互 | 离线网页（搜索、分类、详情、快照切换） |

## 本批改动

| 项 | 做法 | 文件 | 守护测试 |
|---|---|---|---|
| A 叠加版式 | 文字压在照片上时，先去掉文字渲染一遍，按真实像素量对比度。不够才在字后加横贯图片的渐变压暗，最多三档 | `layeredDesignScrim.js` | `layeredDesignScrim.test.js` |
| B1 构思 | `design.concept`：一句话创意、图文关系、第一眼看什么、气质 | `layeredDesignSchema.js`、`layeredDesignInput.js` | `posterDesignThinking.test.js` |
| B2 草图对比 | `make_poster.sketches` 收 2～3 个草图，图片位置用灰块代替；真实渲染后一次看图比较选优。不算试排 | `posterSketch.js` | 同上 |
| B3 出图后自审 | 与成品核验同一次看图，额外返回主次、融合、留白、构思四项和改法。第 1、2 次试排不达标要求重排，第 3 次只提示 | `layeredDesignQuality.js`、`layeredDesignDelivery.js`、`posterDeliverySession.js` | 同上、`posterDeliverySession.test.js` |

| D Demo | 指引写明分工；程序体检颜色、对齐线、字号层级，并从主图取主色（只给建议）；手机卡片布局出一张预览，和电脑整图一起自审 | `layeredDesignLint.js`、`layeredDesignHtml.js`、`visualSceneRouting.js` | `layeredDesignLint.test.js` |

## 代价

- 草图比较每次多 1 次看图调用。
- 出图后自审和原来的成品核验是同一次调用，不额外增加；但不达标会触发重排，最多再排两轮。
- 叠加遮罩和主图取色各多渲染几次，都在本机或服务器完成，不调用模型。

## 未验收

- 真实模型能否按构思、草图的方式工作，自审意见是否中肯：只有协议测试和合成图验证，没有真实模型对照。
- GPT 是否会按卡槽计划留白：只测了“计划位置平整才采用、不平整不硬套”的程序逻辑，没有真实生图验证。
- 手机卡片预览是排版近似，不是浏览器截图。
- 用户原稿、安卓和 Windows 真机、服务器实际更新：未验收。
