# 检索收尾、对话排队与搜索型号说明（2026-11-13）

用户要求：读取上限到了直接整理结果，不显示一串红叉；运行中可明确补充当前任务，或排队独立问题；核实 API GET 的联网搜索型号。基于 e8138f0（已发布 1.0.431）开发，不改 DSH 专项、模型配置归属、签名或服务目录。

## 原因与实现

1. `RETRIEVAL_BUDGET` 原来与工具故障一起生成“错误：预算已用完”，前端和服务器把它存进回答失败记录；已有收尾和 begin 拒绝甚至没有类型。现在统一控制信号，模型收到正常整理指令，原原因保留在有界诊断事件，检查点保留 code；不计真实失败、不显示失败卡片、不虚增执行步数。普通读取次数及发请求前扣预算保持，未读取网页仍不得当已核实。真实网络、鉴权、参数和付费额度错误继续显示。联网收尾后生成文件的旧例外保持。
2. 原来 `turn.later` 会把多条问题用换行合成一次请求。现在独立内存队列逐条 FIFO，每条在开始时才进聊天历史，不污染正在执行的要求；明确选择“补充当前任务”继续使用原 inbox / appendTaskNote，选择“排队新问题”独立发送。队列可编辑、移除、暂停和继续；停止、观察失联、切到其它对话收尾均暂停，不替用户重复提交不明状态任务。队列按登录客户端和会话绑定；最多 10 条，每条 8000 字、12 个附件，附件仅记工作区路径，开始前重建看图输入，不把图片正文留在队列。队列目前只在本次应用运行内保留，关闭/重启不会自动恢复待发送请求；不是服务器持久任务队列。
3. API GET 公开价格页 `https://apiget.store/models-and-pricing` 仅公布 WebSearch 工具按次计费，没有给独立搜索模型 ID 或足够的请求契约。FAQ 的 `https://api.apiget.store/v1` 是 WorkBuddy 的 OpenAI 兼容入口，不能据此推断 Responses `web_search` 可用。设置页新增协议说明：Responses 要填执行搜索的 model，WebSearch 是工具名称；Chat Completions 要填供应商实际支持的搜索型号。明确提醒从登录后的 WorkBuddy 配置/客服脱敏示例确认 model、tools、路径；不猜型号、不借用聊天密钥、不在打开设置时发付费请求。
