# 需求上下文去重与账本归档

协作基线：`43cc84ce487a8c78d9fead4ea9160f3a1af306fc`（正式版1.0.122之后的交接提交）。用户确认由Codex实施；Claude待本批推送后再同步开发。此批只处理需求上下文与账本存储，不涉及模型回退、项目规则文件、长任务提醒、Office渲染、PPT预览或公式检查。

## 改动

1. 普通对话中，原话已在实际发送的history/当前消息里时，不再注入需求索引。实际历史缺失原话时才按相关性补充，最多4条、每条400字符；没有相关原文就不注入。指代追问仅提供简短回读提示，问候不带旧任务。
2. 去掉第一条和最近四条必选，过滤“继续、修改”等泛化词，避免泛化词挤掉真正的PPT/预算要求。没有summary但确实裁掉消息时仍能补充，不能只看summary字段判断。
3. 账本只保存已不在持久化400条messages里的用户原文；消息内用requirementId保留编号。读取时合并归档与当前消息，既可读旧原话，也可读当前消息。v1账本迁移去掉双份正文，不删原话，不设五万字自动删除。保留version:1兼容旧版读取，用mode:archived标记存储布局。
4. 团队规划按其真实收到的最近4条截短消息去重，已展示的前200字符不重复补充；执行角色按其实际history去重。团队生成的步骤仍不写入原话账本。
5. 常驻“修改任务先找回要求”缩为两句；现有读取工具保留完整操作说明。斜杠命令使用展开前原话匹配，避免展开造成误判。

## 实测请求体与存储

`node jarvis/scripts/benchmark-requirements.mjs`：同一OpenAI适配器实际序列化请求体，固定相同两个读取工具，无图片/MCP。默认拦截fetch，**不联网**；下面是合成固定样本，不能冒充真实服务延迟或所有任务的节省比例。基线源码/提示固定在`jarvis/tests/fixtures/requirements-v122.json`，报告见`需求上下文请求体实测-20261017.json`。

| 场景 | 原请求字节 | 新请求字节 | 原重复原文字符 | 新重复原文字符 |
|---|---:|---:|---:|---:|
| 未压缩长对话 | 72,156 | 52,040 | 6,169 | 0 |
| 已压缩长对话 | 41,418 | 26,678 | 2,483 | 0 |
| 项目对话中问候 | 27,964 | 21,233 | 1,846 | 0 |

重复字符仅统计需求索引中、同一原话来源已经在可见消息里的摘录，不把系统规则/工具定义的通用词算作需求重复。

900条用户原话样本：持久化JSON从2,019,429降到1,401,460字节；其中500条归档、400条在messages，合并仍为900条，未丢弃任何原话。这个方案消除双份保存，但不承诺会话永远不会增长。
