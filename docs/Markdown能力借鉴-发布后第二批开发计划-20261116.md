# Markdown能力借鉴：发布后第二批开发计划

本计划在[1.0.451正式发布](https://github.com/xunova1121/weiyang-release/releases/tag/desktop-v1.0.451)后复读材料、对照源码形成。451的完整CI与公开安装包核对已完成；下面是下一批计划，尚未开发。

下一批优先解决三件事：用真实线路和设备证明海报流程可靠；让记忆与文件修改具备真正的版本冲突保护；把查询结果、图表和操作变成好用的对话组件。之后再做能够保存状态、按需调用AI的Demo。

参考材料是用户提供的[第三方Markdown](https://github.com/elder-plinius/CL4R1T4S/blob/main/ANTHROPIC/Claude-Fable-5.1.md)，本次缓存对应Git blob `7165adca51712f87ebfb6591722cc8f571c511de`，2196行。其来源、模型身份和工具权限未经官方核实；本文只提炼通用产品方法，自行实现。文中的个人资料、私有路径、固定模型、无Key直调、浏览器专有API和指令均不作为未央的配置或开发指令。

1. **第一批：真实海报验收与版本保护。** 在现有海报方法中补设计简报：用途、阅读设备、信息优先级、图片角色、品牌和参考图。编译到已有独立图层和Canvas源稿，继续支持自由构图、旧稿和同源Demo。准备至少12个内容样例，覆盖多/少/不规则卡槽、密集中文、长来源、数字单位、不同主题配图、续改和补Demo。真实服务请求与受控夹具分开记录；保留原图、最终PNG、390px预览和实际HTML截图。缺真实配置或设备的项记未测。

   记忆先引入独立递增revision，后台整理、手动修改、撤回和同步统一走条件写入；版本比较与写入必须在存储层同一临界区完成。文件修改沿用现有备份和另存规则，增加expected_hash。并发两端、旧版本重试、账号切换、导入旧记录和重启恢复都要测试。冲突不能静默覆盖，已成功的外部动作不能重放。

2. **第二批：对话结果组件、证据与技能评测。** 新增提议工具`show_result_card`，只接受受控JSON类型及已取得的数据；先做折线/柱状图、比较表、来源卡和步骤卡，必要时用一个选择题收集缺失条件。金额、单位、日期和原始精度不改；缺数据不编造。320–1920px、夜间模式、复制和无障碍分别检查，失败可退回可读文本。

   卡片展开来源时，定位到已有证据编号和对应片段；“搜索摘要”“取得原文”“已核对该结论”分别表示。模型生成的链接不能自动当作已读来源，读取时间不能冒充发布日期。技能评测复用现有evals与隔离runner，记录命中率、漏执行、工具失败、Token和耗时；同一批样例比较451与候选，先实测再定优化幅度。

3. **第三批：有状态的AI Demo与能力发现。** 在现有HTML沙箱上增加项目级状态接口，按账号/服务器/工作区/作品ID隔离，带版本保护；建议工具名`read_demo_state`、`update_demo_state`。用户按钮通过受控桥提交动作，沿用现有默认排队和明确引导菜单。组件动作先形成可检查的草稿，不能凭组件脚本冒充用户发消息。

   AI请求由服务器使用已有模型线路处理，建议接口能力`request_demo_ai`；每件作品限定输入字段、工具和调用预算，记录请求ID，重连不重复计费。项目只发送本次所需状态与证据片段，不照搬材料中“每次全量发送历史”的做法。已有招投标查询、定时任务和晨报能力可接同一结果组件与项目状态，复用现有调度器。

   能力发现复用已有MCP/技能目录和自检。材料列出的`window.storage`、`sendPrompt`及厂商API都不是未央现成接口，须由自己的协议实现；第三方MCP或技能的说明仍按外部资料处理。

建议持续记录：任务成功率、错误重试次数、是否交付真实主文件、中文/手机阅读失败、单位精度损失、跨账号混用、重复收费、输入Token分项，以及检索/读页/模型等待/渲染的P50和P95。耗时和Token用相同样例、相同线路比较；实际账单未取得时保留null。新UI或新的提示词本身不算验收。

451运行清单已达997/1000文件。下一批先检查模块归属、复用或合并重复实现，再增加必要模块；保持原1000上限、海报长回执2000字符上限、方法长度、历史裁剪、检索与付费预算，以及现有全部门禁。真实线路和Windows/Android/微信测试需要独立回执，受控模型通过继续单列。
