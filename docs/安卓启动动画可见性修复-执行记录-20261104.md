# 安卓启动动画可见性修复

用户确认入口为安卓APK，授权修复并发版。基于 `f01a809` 拉取 `claude/jolly-darwin-tijh97`，与远端一致；先读开发约定、代码规范及不回退清单，协调记录已登记。未读取或修改用户模型密钥、访问密码、jarvis.env。

## 原因与复现

`initMobileStartup` 原先在图片解码和两帧布局完成后立即加 `out`，180毫秒淡出、240毫秒移除；角色帧动画本身为1.6秒，水滴/入场动画只在资源等待期间展示。APK加载本地资源很快，出现“页面可用了，启动层已经淡出”的时序。兼容显示和减少动效另有明确跳过机制，不能据此断言用户设备开启了它们。

新增浏览器验收对原1.0.399构建复现：不拖慢JS或图片，在主界面就绪时观测启动层 `present=true, opacity=0.916246, leaving=true`，可见性断言失败。证据 `/tmp/weiyang-startup-before.log`、`/tmp/weiyang-startup-before/startup-ready.json`。测试使用APK同份dist-mobile并模拟原生boot已经写入的mobile-app标记，没有运行安卓设备，也没有伪装成真机验收。

延长可见期后的真实页面继续发现第二处根因：initMascots会给.as-logo加wy-brand，通用 `.wy-brand { background:none!important }` 将background-position一并设成!important，压住图集关键帧。旧mobile-theme手动创建的预览节点没有wy-brand，所以该测试未覆盖实际初始化后的冲突。此次只将独立启动角色排除出通用头像选择器，其他位置的角色不变；新增e2e直接观察完整初始化后的CSS帧随真实时间移动。

## 修改

- 原生boot完成的APK入口，在图片解码和布局就绪后把既有CSS动画回到第一帧，播放一轮1.6秒，然后沿用原淡出与240毫秒清理。只使用已打包图集和CSS，不请求模型/网络视频。
- 新增可直接点击的“跳过”；隐藏页面、切换减少动效、内存压力可提前结束，监听和计时器随结束清理，恢复前台不重播。
- 兼容显示、系统/应用减少动效、后台启动、资源失败跳过额外播放；非原生浏览器仍按原规则就绪立即进入。旧WebView动效API异常不阻断首页。
- 主界面已就绪时清除8秒慢启动看门狗，避免播放期间误报“启动较慢”；真实资源等待与原静态回退不变。

本次用户要求显示APK启动动画，明确限定调整旧规则中“资源就绪无最短等待”的原生入口；网页和原测试继续保留原行为。没有删改旧测试和断言。新增e2e接入原发布工作流，安装包仍直接上传草稿再转正式。
