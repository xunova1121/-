# 未央对话 UI 讨论方案（仅策划，未开发）

范围：只讨论下一版对话界面的整体排版。本轮技能适配、文件分类、图片查看、后台静音和语音故障修复属于已授权的功能改动；不把本方案的大改版混入发布。

## 参考案例与取舍

均先核对开源许可，只借鉴交互思路，不复制组件、样式或代码，不引入新框架。

| 案例 | 已核对的资料 | 可借鉴的思路 | 在未央里的用法 |
| --- | --- | --- | --- |
| [assistant-ui](https://github.com/assistant-ui/assistant-ui) | [MIT LICENSE](https://github.com/assistant-ui/assistant-ui/blob/main/LICENSE)、README 的流式消息 / 工具调用 / 审批示例 | 回答、工具进度、需要用户确认的动作分开呈现 | 回复保持干净；工作进展默认一行；确认操作以清楚的按钮呈现 |
| [NextChat](https://github.com/ChatGPTNextWeb/NextChat) | [MIT LICENSE](https://github.com/ChatGPTNextWeb/NextChat/blob/main/LICENSE)、README 中响应式界面、流式输出和独立作品预览说明 | 手机与电脑保持相近结构；结果预览不挤占长对话 | 手机保留底部输入区；文件和网页在单独预览层打开 |

## 两个可讨论方向

| 方向 | 具体表现 | 好处 | 代价 |
| --- | --- | --- | --- |
| A：对话优先（推荐） | 主屏是清爽的浅色对话，顶部小未央；点击头像才打开居中陪伴面板 | 阅读、办公、文件任务更清楚；动画负担小 | 平时角色不占据大块画面 |
| B：陪伴优先 | 角色常驻对话上方，留约 1/4 屏幕给状态和表情 | 更强调陪伴和情绪 | 手机可读消息更少，键盘打开时需要收起角色 |

建议采用 A，保留现有蓝金角色和淡紫点缀。头像互动层是独立入口，对话主屏不持续放大角色。

## 推荐方向的手机排版

从上到下四层：

1. 顶栏：菜单、未央头像和名称、当前状态、更多操作。头像点击区域至少 44px，头像本身不让点击区域跟着移动。
2. 对话区：用户用浅紫气泡，未央回答以正文阅读为主。单独显示段落、代码、表格、来源和文件卡片；名称和时间弱化，同一组消息不用重复堆叠头像。
3. 任务状态条：只有正在执行 / 等待确认 / 失败时出现。平时一句“正在查阅资料 · 3 步”，点开才看细节。不要一直占据多行，也不把模型参数、工具原始参数混进正文。
4. 输入区：上面是可增长的文本框，下面保留附件、拍照、语音、发送。其他选项收进“更多”，不用把一长排模型和操作按钮挤在一起。

首页空态：问候 + 适量角色 + 3 条建议。内容超过屏幕时优先保证输入区可见；角色和光环不得压到问候文字。

## 语音交互

- 点击后先明确显示“正在申请麦克风 / 已开始收音 / 正在识别 / 正在思考 / 正在回答”，没有真实识别回调时不显示“已经听到”。
- 声音服务、识别服务分别显示，聊天模型可用不代表语音服务也可用。
- 系统识别窗口结束后回到原对话；切换到其他应用后立即静音，不积压待播内容，返回后不突然补播旧回复。
- 音色试听必须经过实际配置的服务。真实女童音色与年轻女声明确区分，服务失败不能默默换成系统声并继续标注为女童。
- 错误有“重试 / 检测语音 / 设置服务”入口；权限拒绝时说明去哪里开启，不反复弹同一个申请。

## 文件与图片

- 上传图片先显示小图，点击看原图；正文只显示“已上传工作区”，内部完整路径保留给模型和工具，不让用户读长串文件名。
- 生成结果显示一张紧凑成果卡：类型、短标题、打开。多个文件能展开查看，分类和最新排序交给工作区。
- 预览层支持关闭、安卓返回键和键盘 Escape；关闭后回到原来的阅读位置。

## 滚动、性能和可访问性

- 正在看旧消息时不强制拉到最底，显示“有新回复”；回到最新位置后再跟随流式输出。
- 键盘弹出后输入区和最新消息保持可见，收起键盘不跳到中间。
- 角色只用二维动作，后台暂停视觉动画；避免大面积持续模糊、多个无限旋转图层。
- 支持减少动画、较大字号和 360px 窄屏。错误、成功、录音状态不只靠颜色区分。

## 开发前验收清单（本轮不执行改版）

- 360 / 390 / 430px 手机宽度，以及 Windows，检查长回复、表格、代码、图片、多个附件、中文长标题。
- 键盘开关、上下滚动、流式输出、任务等待确认、错误重试、后台返回，不遮住发送和结束语音按钮。
- 语音模式至少核对鸿蒙 4.2 真机；需要真实识别结果与实际发声，不能用按钮测试代替。
- 把 A 或 B 及输入区布局确定后，再单独开发整套对话视觉改版。
