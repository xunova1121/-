# 未来创梦 · AI 短剧工作台

把小说、剧本变成分镜和成片的 Windows 桌面应用。**内置第三方 API 联调台**，
以及一套让角色和场景前后不脱节的**一致性引擎**。

参考了 [alibaba/lumenx](https://github.com/alibaba/lumenx)（Studio 流水线形态）、
[HBAI-Ltd/Toonflow-app](https://github.com/HBAI-Ltd/Toonflow-app)（Agent 分层、供应商可编程）、
[ArcReel](https://github.com/ArcReel/ArcReel)（参考资产沉淀），
但在**一致性**和**联调**这两件事上做得更进一步 —— 具体差在哪见下文。

---

## 为什么不是直接把 lumenx 搬过来

lumenx 是 Next.js + Python/FastAPI + FFmpeg 的网页平台。在 Windows 上落地，
用户要先装 Python 3.11、跑 pip（碰上要编译的包还得装 VS Build Tools）、装 Node、
再构建前端、再配 FFmpeg。四道关，任何一道卡住就劝退。

这个版本换了形态：

| | lumenx | 未来创梦 |
|---|---|---|
| 运行时 | Python 3.11 + Node 18 | **只要 Node 18+**（打包成 exe 后连 Node 都不用） |
| 依赖安装 | pip + npm 两套 | **零第三方依赖**，后端只用 `node:` 内置模块 |
| 前端 | Next.js，需要构建 | 无构建，浏览器直接跑 ES 模块 |
| 启动 | 起两个服务 | 双击 `启动.bat`，或装成桌面应用 |
| 密钥 | 环境变量 / .env | **Windows DPAPI 加密**，绑当前用户账户 |
| 数据 | 项目目录 | `%APPDATA%\FutureDream`（不往 Program Files 里写） |

## 装和跑

### 方式一：下现成的安装包（本机什么都不用装）

GitHub Actions 每次推送都会用 Windows 机器打好包，发到 **Releases**：

- 日常构建 → [`snapshot`](../../releases/tag/snapshot) 预发布，**链接固定**，永远指向最新一次
- 打了 `v` 开头的 tag → 另出一条正式 Release

挑一个下，不用都下：

| 文件 | 大小 | 前提 | 说明 |
|---|---|---|---|
| `FutureDream-Lite-NodeOnly.zip` | **约 0.2 MB** | 装了 Node 18+ | **嫌下载慢就下这个。** 解压双击 `启动.bat`，功能一模一样 |
| `FutureDream-Setup-*.exe` | 约 90 MB | 无 | 安装版，可选目录，自动建桌面快捷方式 |
| `FutureDream-Portable-*.exe` | 约 90 MB | 无 | 免安装版，双击即用，可放 U 盘带走 |

两个 exe 大，是因为里面塞了一整个 Chromium（Electron 外壳）。
应用自身零运行时依赖，全部源码加起来才一百多 KB —— 所以已经有 Node 的话，
Lite 包是**快几百倍**的那条路，往后每次更新也只下这 0.2 MB。
没 Node 就一句 `winget install OpenJS.NodeJS.LTS`，装一次管到底。

> Lite 包和 exe 的区别只有外壳：exe 里密钥用 Windows DPAPI 加密（绑当前用户账户），
> Lite 包用本机 AES-256-GCM。功能、界面、流水线完全相同。
>
> **两边换着用要注意一件事**：DPAPI 那份 Lite 包读不出来（它没有 DPAPI），
> 反过来 AES 那份 exe 是读得出来的。所以先用 exe 存过密钥、后来改用 Lite 包打开时，
> 密钥会显示"未配置"—— 应用照常能进，「服务商与密钥」页顶部会说清楚原因和两条出路：
> 换回 exe 打开，或者就地重填一次（重填后存成 AES 格式，两边都能读，旧文件自动备份）。

首次打开 exe 时 Windows SmartScreen 会拦一下（包没做代码签名），
点「更多信息 → 仍要运行」即可。Lite 包不会被拦。

**下载还是慢**：GitHub 在国内时快时慢，把下载链接前面拼一个公共代理前缀通常会好很多
（如 `https://ghfast.top/` + 原链接）。这类是第三方公共镜像，可用性和内容都不由本项目控制，
介意的话就直连或自己挂代理。

> 为什么不用 Actions Artifacts：那份存储有独立配额，满了就传不上去
> （这个仓库踩过一次）。Release 附件不占那份配额，链接也更稳定。

### 方式二：源码直接跑（改代码时用这个）

1. 装 Node 18 或更新版本：`winget install OpenJS.NodeJS.LTS`
2. 双击 **`启动.bat`**

浏览器会自己打开。端口被占用时会自动顺延，不用管。
这一步**不需要 `npm install`** —— 后端只用 Node 内置模块。

### 方式三：自己打包

```powershell
npm install          # 只装 electron 和打包工具，应用本身没有运行时依赖
npm run dev          # 开发模式跑起来
npm run build:win    # 出安装包和免安装版，产物在 dist\
```

> 装成桌面应用后（方式一/三），密钥会自动升级为 **Windows DPAPI 加密**
> （绑定当前用户账户，文件拷到别的机器解不开）；
> 方式二的命令行模式下退化为本机 AES-256-GCM。

### FFmpeg（只有最后合成那步需要）

三选一，探测顺序也是这个顺序：

1. 在「设置」里直接填 `ffmpeg.exe` 的完整路径
2. 把 `ffmpeg.exe` 丢进本应用的 `bin\` 目录（绿色版就这么办）
3. `winget install Gyan.FFmpeg`

没装也能一路跑到「视频生成」，只是合成那步会给出明确提示，不会跑到一半才报错。

### 自检

```powershell
npm run selftest
```

会起一个本地打桩服务，把密钥脱敏、SSE 分片解析、异步任务轮询、
整条流水线（含一致性重试）、Windows 专属的 ESM 加载陷阱、文件名规则、目录穿越防护跑一遍。
**不碰任何真实厂商，不花一分钱。**

## 一、一致性引擎

这是和同类工具差别最大的地方。

常见做法是把角色外貌写进每一镜的提示词，指望模型记住。这条路走不通 ——
扩散模型没有跨次调用的记忆，同一段描述两次采样出来就是两张脸。

这里用四层叠加，把"碰运气"变成"可复现"：

| 层 | 做什么 | 为什么有用 |
|---|---|---|
| **① 设定冻结** | 角色/场景/道具的外貌由模型生成**一次**，之后冻成结构化字段，人工可改 | 每次重新发挥就漂一次。冻住才有基准 |
| **② 种子锁定** | 每个角色派生一颗稳定种子（项目 ID + 名字哈希），全片复用 | 把采样随机性摁住；镜号做偏移，保风格又留构图变化 |
| **③ 参考图引用** | 先出角色设定图 / 场景基准图，后续镜头走图生图、参考图生视频把它带上 | **效果最大的一层**。像素级参照比任何文字描述都稳 |
| **④ 视觉复核** | 出图后把成图和设定图一起交给多模态模型比对打分，低于阈值换种子重试 | 别人做到 ③ 就收工了。这一层把"错了没人发现"变成"错了自动重来" |

提示词的装配顺序也是刻意的：

```
风格锚 → 角色设定 → 场景设定 → 道具 → 镜头内容 → 镜头语言 → 主色调
```

越靠后越容易被稀释。把角色设定排在最前面，人设才压得住。

复核不过、重试到头仍不达标的镜头会被标成**「待人工确认」**，卡片上挂一道琥珀色警示条，
不会静悄悄混进成片里。

> 在「设置 → 一致性引擎」里可以调分数线和重试次数，也可以整个关掉换速度。

## 二、API 联调台

大多数工具的"接口测试"页是另写一套请求代码，测试过了生产照样翻车。

这里**联调台和流水线走的是同一条出站通道**（`core/http-client.js`）——
在联调台调通了，生产就是调通了。

能做的事：

- **改完就发**：服务商 / 模板下拉带出起手式，URL、Header、Body 全部现场可改
- **密钥不落界面**：写 `{{ARK_API_KEY}}` 占位符，发送时才展开；界面、历史记录、
  导出的 cURL 里始终是占位符
- **流式实时看**：SSE 分片逐条落在事件流里，OpenAI 风格的 `delta` 自动拼成正文
- **异步任务自动轮询**：国内视频模型清一色"提交 → 轮询"，勾一下就跟到终态，
  每次轮询的状态都可见
- **导出 cURL / PowerShell**：PowerShell 那份是给 Windows 用的，不用先装 curl
- **连通性自检**：一键判断这家配通了没，顺带量延迟
- **错误翻译成人话**：401/403/404/429 会给出具体该查什么，而不是把原始报文一甩了事

配套的「请求记录」页留着每一次出站调用的完整请求与响应（已脱敏），
生产跑挂了先来这里翻。顶部有近 100 次的成功率和 P50/P95。

## 三、接的模型

能力是**分开路由**的 —— 剧本、复核、出图、视频、配音各选各的服务商。
各家强项差得远，绑死一家处处将就。

| 服务商 | 协议 | 能力 |
|---|---|---|
| **OpenAI（标准接口）** | 原生 | 对话、视觉、出图 |
| **火山引擎 方舟 Ark** | OpenAI 兼容 + 原生任务 | 豆包对话/视觉、Seedream 出图、SeedEdit 图生图、Seedance 视频 |
| **FloatAI Router** | OpenAI 兼容 | 中转聚合，转发 GPT / Claude / Gemini / DeepSeek |
| 阿里云百炼 DashScope | 原生 | Qwen、Qwen-VL、通义万相出图/视频、CosyVoice 配音 |
| DeepSeek / 智谱 GLM / Kimi / 硅基流动 | OpenAI 兼容 | 对话、视觉、出图 |
| Ollama / LM Studio | OpenAI 兼容 | 本地模型，不用密钥 |
| **秘塔 metaso** | MiniMax H3 中转（`/api/minimax/v2`） | H3 文生/图生视频，2K，带 ratio 字段 |
| **MiniMax 海螺 / H3** | 原生（三步：提交→轮询→取文件） | H3 全模态（9 张参考图、2K、15 秒）、Hailuo 图生视频、image-01 出图、对话 |
| 可灵 Kling | 原生（AK/SK 签 JWT） | 图生视频 |
| Vidu | 原生（`Token` 而非 `Bearer`） | 参考图生视频（锁人设最好的一条路） |
| 空白请求 | — | 任意 HTTP，调什么都行 |

新增一家：在 `core/providers/catalog.js` 里加一个对象就行，UI 和路由都不用改。
OpenAI 兼容的那些只要给 baseUrl 和密钥名，一行工厂函数搞定。

**关于 FloatAI 的 baseUrl**：中转类网关基本都是 OneAPI/NewAPI 那套，入口在 `/v1`，
所以预设成 `https://router.floatai.cn/v1`。如果你的面板给的不是这个，
在「服务商与密钥」里改一行即可，改完立刻生效 —— 先点「自检」确认再用。

## 四、流水线

```
01 设定集 → 02 分镜 → 03 镜头出图 → 04 视频生成 → 05 配音 → 06 合成
```

编号是真序列：设定集必须在分镜之前跑，因为分镜要引用已冻结的人设
（所以分镜提示词里**明确要求模型不要重复写外貌**，重复写反而会和设定冲突）。

每一阶段都是"读项目 → 干活 → 落盘 → 回事件"。这类任务动辄几分钟，
中途关窗口、断网、改主意都是常态 —— 只要落了盘，下次打开就从断点接着跑，
不用从头再烧一遍额度。

项目的新建、切换、改画风、删除都在独立的**「项目」页**（左侧第 01 项），
创作台只管"这一部片子怎么往下做"。画风在建项目时定一次，之后每条提示词都从
设定集里取，不会在剧本旁边再问你一遍。

画风卡片上是**同一个镜头的十二种画法**（湖畔、远山、栈桥上一个人影），
构图完全一致，只改渲染方式和配色 —— 这样并排看过去，你比较的是
"这个风格会把画面变成什么样"，而不是"哪张图好看"。
全部是内联 SVG：离线可用、打包体积不涨、缩放不糊，也不拿别人的作品当示例。
想看它在**你自己的模型**上出什么样，选中跑一次设定集，那才是真实结果。

> 删除是真删，图、视频、成片一起没，删完列表当场更新。
> Windows 上删不掉的老毛病（页面还在播那段 mp4，文件被占用）也处理了：
> 发请求前先让页面松开文件句柄，删除本身带重试，万一还有残留会在下次启动时清掉。

### 单独重出，同样吃设定集

批量跑完总有零星几镜不满意。分镜卡片下面的「单独重出」可以只重跑那一镜，
还能临时换服务商、换模型、换清晰度。

关键是：**单独重出走的是和批量完全一样的一套设定集** ——
提示词从冻结设定装配，参考图带上「场景基准图 + 出场角色设定图 + 镜头里点到的道具图」，
场景图排第一张（多数厂商给首图的权重最高，而人物已经被首帧图锁住了）。
少带任何一样，重出的这一镜就会成为全片里唯一对不上的那张。
卡片上会列出这次带了哪几张（`景·码头、角·阿澜、道·执法记录仪`），
重出来还是不像的时候，先看这一行。

### 清晰度与画幅

「设置 → 画面规格」里选。分辨率档位跟着**当前视频服务商**走，
因为各家的写法根本不统一 —— 方舟是 `720p`，万相是 `720P`，秘塔是 `768P` 但 `480p`。
选中的档位在发送前按大小写不敏感匹配翻译成该家的原样拼写；
换了一家而新家没有这个档位（比如从秘塔的 2K 换到方舟），会退回该家默认档并在日志里说一声，
而不是把一个必然报错的值发出去。

省钱的跑法：先用低档把全流程跑通、确认分镜和人设都对，最后一遍再拉高重出。

画幅同时作用于出图和出视频 —— 分开设的话，成片里图和视频的比例会打架。
竖屏短剧选 `9:16`。

### 界面只显示当前这一步的参数

点哪一步，下面就只摆哪一步用得上的东西：

| 选中的阶段 | 分镜卡片上出现 | 时长面板 |
|---|---|---|
| 分镜 | 每镜时长 | 显示 |
| 镜头出图 | 出图服务商 / 模型 / 出图按钮 | 收起 |
| 视频生成 | 每镜时长、视频服务商 / 模型 / 清晰度 / 出视频按钮 | 显示 |
| 配音、合成 | 只看状态 | 收起 |

在出图那一步摆一堆秒数和视频模型，只会让人以为得先把它们配好才能出图。

### 出视频一直失败？

先看流水线下面的**失败汇总** —— 那里是服务端原话，答案基本都在那句话里。
轮询日志刷得飞快，所以失败原因单独留一份，不会被顶走。

已知最常踩的一个坑（这一版已经修掉）：**各家能收几张图差得很远，超了不是多余的被忽略，
而是整个任务提交失败**。

| 服务商 | 出视频最多收几张图 |
|---|---|
| 火山方舟 Seedance | **1**（只有首帧；首尾帧模式 2 张且要带 role） |
| 通义万相 | 1 |
| 可灵 Kling | 1 |
| Vidu | 3（reference2video，锁人设最好的一条路） |
| MiniMax H3（官方） | 9 |
| 秘塔中转 | 起点 3，真实上限自己试出来（见下） |

设定集参考图是按"能带多少带多少"给下去的，现在会在发送前按厂商上限截断，
并在日志里说清楚截掉了几张、一致性改由什么承担。方舟这条路上，
人和环境靠的是首帧图本身 + 提示词里的冻结设定描述。

**中转平台的上限是试出来的**：秘塔转的是 H3（官方收 9 张），但它自己会回
「输入媒体数量超过限制 (2013)」，文档里没写几张算超。目录里的数字只能当起点 ——
撞上这个错就减半重试，直到只剩首帧，试出来的值按「服务商 + baseUrl」记住，
同一批后面的镜头直接用。这类失败是参数校验失败，服务端还没开始出片，不计费。

剩下的排查顺序：① 服务端原话；②「设置 → 上线前体检」把这条能力真跑一次最小调用；
③ 模型 ID 是不是你账号里真实开通的那个（方舟的短名早已下线，填了会返回 404）。

## 数据放在哪

```
%APPDATA%\FutureDream\
├─ settings.json        明文，可以直接手改，也可以贴给同事复现问题
├─ credentials.enc      密钥，DPAPI 或 AES-256-GCM 加密
├─ api-history.json     请求记录（已脱敏）
└─ projects\<项目ID>\
   ├─ project.json      剧本、设定集、分镜
   ├─ assets\           参考图、镜头图、视频片段、配音
   └─ <标题>.mp4        成片
```

一个项目一个文件夹，没上数据库 —— 整个文件夹拷给同事就能接着做，
出问题也能手动改 JSON 救回来。

## 安全上做了什么

- 密钥存在加密保险箱里，接口只回掩码（`sk-abc***wxyz`），明文永远不出后端
- 请求记录写盘**前**就脱敏：`Authorization`、`X-Api-Key`、`Cookie` 这些头，
  以及 body 里叫 `api_key` / `secret` / `token` 的字段
- 本地服务只监听 `127.0.0.1`，并校验 `Host` 与 `Origin` —— 防的是浏览器里
  某个网页偷偷往你本地端口发请求
- 媒体接口只放行数据目录之内的文件，目录穿越会被拒
- Electron 里 `contextIsolation` 开、`nodeIntegration` 关，预加载脚本只暴露几个只读标记

> 上一版演示页把 apiKey 明文写死在 HTML 里，谁拿到文件谁就能刷账单。
> 这一版从第一行代码起就不给这条路留口子。

