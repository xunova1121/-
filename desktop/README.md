# 未来创梦 · AI 短剧工作台

把小说、剧本变成分镜和成片的 Windows 桌面应用。**内置第三方 API 联调台**，
以及一套让角色和场景前后不脱节的**一致性引擎**。

参考了 [alibaba/lumenx](https://github.com/alibaba/lumenx)（Studio 流水线形态）、
[HBAI-Ltd/Toonflow-app](https://github.com/HBAI-Ltd/Toonflow-app)（Agent 分层、供应商可编程）、
[ArcReel](https://github.com/ArcReel/ArcReel)（参考资产沉淀），
但在**一致性**和**联调**这两件事上做得更进一步 —— 具体差在哪见下文。

---

## 为什么不是直接把 lumenx 搬过来

lumenx 是 Next.js + Python/FastAPI + FFmpeg 的网页平台。在 Windows 上落地，
用户要先装 Python 3.11、跑 pip（碰上要编译的包还得装 VS Build Tools）、装 Node、
再构建前端、再配 FFmpeg。四道关，任何一道卡住就劝退。

这个版本换了形态：

| | lumenx | 未来创梦 |
|---|---|---|
| 运行时 | Python 3.11 + Node 18 | **只要 Node 18+**（打包成 exe 后连 Node 都不用） |
| 依赖安装 | pip + npm 两套 | **零第三方依赖**，后端只用 `node:` 内置模块 |
| 前端 | Next.js，需要构建 | 无构建，浏览器直接跑 ES 模块 |
| 启动 | 起两个服务 | 双击 `启动.bat`，或装成桌面应用 |
| 密钥 | 环境变量 / .env | **Windows DPAPI 加密**，绑当前用户账户 |
| 数据 | 项目目录 | `%APPDATA%\FutureDream`（不往 Program Files 里写） |

## 装和跑

### 方式一：下现成的安装包（本机什么都不用装）

GitHub Actions 每次推送都会用 Windows 机器打好包，发到 **Releases**：

- 日常构建 → [`snapshot`](../../releases/tag/snapshot) 预发布，**链接固定**，永远指向最新一次
- 打了 `v` 开头的 tag → 另出一条正式 Release

挑一个下，不用都下：

| 文件 | 大小 | 前提 | 说明 |
|---|---|---|---|
| `FutureDream-Lite-NodeOnly.zip` | **约 0.2 MB** | 装了 Node 18+ | **嫌下载慢就下这个。** 解压双击 `启动.bat`，功能一模一样 |
| `FutureDream-Setup-*.exe` | 约 90 MB | 无 | 安装版，可选目录，自动建桌面快捷方式 |
| `FutureDream-Portable-*.exe` | 约 90 MB | 无 | 免安装版，双击即用，可放 U 盘带走 |

两个 exe 大，是因为里面塞了一整个 Chromium（Electron 外壳）。
应用自身零运行时依赖，全部源码加起来才一百多 KB —— 所以已经有 Node 的话，
Lite 包是**快几百倍**的那条路，往后每次更新也只下这 0.2 MB。
没 Node 就一句 `winget install OpenJS.NodeJS.LTS`，装一次管到底。

> Lite 包和 exe 的区别只有外壳：exe 里密钥用 Windows DPAPI 加密（绑当前用户账户），
> Lite 包用本机 AES-256-GCM。功能、界面、流水线完全相同。
>
> **两边换着用要注意一件事**：DPAPI 那份 Lite 包读不出来（它没有 DPAPI），
> 反过来 AES 那份 exe 是读得出来的。所以先用 exe 存过密钥、后来改用 Lite 包打开时，
> 密钥会显示"未配置"—— 应用照常能进，「服务商与密钥」页顶部会说清楚原因和两条出路：
> 换回 exe 打开，或者就地重填一次（重填后存成 AES 格式，两边都能读，旧文件自动备份）。

首次打开 exe 时 Windows SmartScreen 会拦一下（包没做代码签名），
点「更多信息 → 仍要运行」即可。Lite 包不会被拦。

**下载还是慢**：GitHub 在国内时快时慢，把下载链接前面拼一个公共代理前缀通常会好很多
（如 `https://ghfast.top/` + 原链接）。这类是第三方公共镜像，可用性和内容都不由本项目控制，
介意的话就直连或自己挂代理。

> 为什么不用 Actions Artifacts：那份存储有独立配额，满了就传不上去
> （这个仓库踩过一次）。Release 附件不占那份配额，链接也更稳定。

### 方式二：源码直接跑（改代码时用这个）

1. 装 Node 18 或更新版本：`winget install OpenJS.NodeJS.LTS`
2. 双击 **`启动.bat`**

浏览器会自己打开。端口被占用时会自动顺延，不用管。
这一步**不需要 `npm install`** —— 后端只用 Node 内置模块。

### 方式三：自己打包

```powershell
npm install          # 只装 electron 和打包工具，应用本身没有运行时依赖
npm run dev          # 开发模式跑起来
npm run build:win    # 出安装包和免安装版，产物在 dist\
```

> 装成桌面应用后（方式一/三），密钥会自动升级为 **Windows DPAPI 加密**
> （绑定当前用户账户，文件拷到别的机器解不开）；
> 方式二的命令行模式下退化为本机 AES-256-GCM。

### FFmpeg（只有最后合成那步需要）

最省事的一条：把 `ffmpeg.exe` 丢进 `%APPDATA%\FutureDream\bin\`，
回「设置 → 本机环境」点一下「重新检测」。不用重启、不用配 PATH。

那个目录应用启动时会自动建好；不确定路径的话，**「设置 → 本机环境」里直接印着
当前这台机器该放的绝对路径**，照着放就行。

> ⚠ 别放进安装目录里的 `bin\`。装完之后 `core\` 在 `app.asar` 里，
> 那个路径是包内的虚拟路径，既放不进去也找不到；安装目录本身还可能是只读的
> （装在 Program Files 时）。`%APPDATA%\FutureDream\bin\` 是唯一任何情况下都可写的位置。
> 从源码或解压即用版跑的话，`desktop\bin\` 仍然有效。

完整探测顺序：

1. 「设置」里手填的完整路径
2. `%APPDATA%\FutureDream\bin\ffmpeg.exe` ← 推荐
3. 安装包自带的 `resources\bin\ffmpeg.exe`
4. 源码目录 `desktop\bin\ffmpeg.exe`
5. 系统 PATH（`winget install Gyan.FFmpeg` 走这条）

下载选 <https://www.gyan.dev/ffmpeg/builds/> 的 `essentials` 版本就够，
解压后只要 `bin\ffmpeg.exe` 这一个文件。

没装也能一路跑到「视频生成」，只是合成那步会给出明确提示，不会跑到一半才报错。
末帧复核也会跳过并说一声（它要抠视频最后一帧，得靠 FFmpeg）。

### 自检

```powershell
npm run selftest
```

会起一个本地打桩服务，把密钥脱敏、SSE 分片解析、异步任务轮询、
整条流水线（含一致性重试）、Windows 专属的 ESM 加载陷阱、文件名规则、目录穿越防护跑一遍。
**不碰任何真实厂商，不花一分钱。**

## 一、一致性引擎

这是和同类工具差别最大的地方。

常见做法是把角色外貌写进每一镜的提示词，指望模型记住。这条路走不通 ——
扩散模型没有跨次调用的记忆，同一段描述两次采样出来就是两张脸。

这里用四层叠加，把"碰运气"变成"可复现"：

| 层 | 做什么 | 为什么有用 |
|---|---|---|
| **① 设定冻结** | 角色/场景/道具的外貌由模型生成**一次**，之后冻成结构化字段，人工可改 | 每次重新发挥就漂一次。冻住才有基准 |
| **② 种子锁定** | 每个角色派生一颗稳定种子（项目 ID + 名字哈希），全片复用 | 把采样随机性摁住；镜号做偏移，保风格又留构图变化 |
| **③ 参考图引用** | 先出角色设定图 / 场景基准图，后续镜头走图生图、参考图生视频把它带上 | **效果最大的一层**。像素级参照比任何文字描述都稳 |
| **④ 视觉复核** | 出图后把成图和设定图一起交给多模态模型比对打分，低于阈值换种子重试 | 别人做到 ③ 就收工了。这一层把"错了没人发现"变成"错了自动重来" |

提示词的装配顺序也是刻意的：

```
风格锚 → 角色设定 → 场景设定 → 道具 → 镜头内容 → 镜头语言 → 主色调
```

越靠后越容易被稀释。把角色设定排在最前面，人设才压得住。

复核不过、重试到头仍不达标的镜头会被标成**「待人工确认」**，卡片上挂一道琥珀色警示条，
不会静悄悄混进成片里。

> 在「设置 → 一致性引擎」里可以调分数线和重试次数，也可以整个关掉换速度。

## 二、API 联调台

大多数工具的"接口测试"页是另写一套请求代码，测试过了生产照样翻车。

这里**联调台和流水线走的是同一条出站通道**（`core/http-client.js`）——
在联调台调通了，生产就是调通了。

能做的事：

- **改完就发**：服务商 / 模板下拉带出起手式，URL、Header、Body 全部现场可改
- **密钥不落界面**：写 `{{ARK_API_KEY}}` 占位符，发送时才展开；界面、历史记录、
  导出的 cURL 里始终是占位符
- **流式实时看**：SSE 分片逐条落在事件流里，OpenAI 风格的 `delta` 自动拼成正文
- **异步任务自动轮询**：国内视频模型清一色"提交 → 轮询"，勾一下就跟到终态，
  每次轮询的状态都可见
- **导出 cURL / PowerShell**：PowerShell 那份是给 Windows 用的，不用先装 curl
- **连通性自检**：一键判断这家配通了没，顺带量延迟
- **错误翻译成人话**：401/403/404/429 会给出具体该查什么，而不是把原始报文一甩了事

### 打开应用就自动探一遍

配置坏了的代价不是"自检红一下"，而是你兴冲冲跑到第 04 步、等了两分钟、
才被告知密钥没配 —— 那两分钟和那次失败都是白花的。
**问题应该在你下手之前就摆在眼前。**

所以打开应用时会自动把**当前路由到的那几家**探一遍，结果直接标在顶部信号链上
（✓ / ✕），有问题时顶上挂一条常驻横幅（toast 会自己消失，而"密钥没配"是个持续状态，
不该在你去泡茶的功夫里悄悄划过去）。

这条和「上线前体检」是两件事，别混：

| | 开机自动探 | 上线前体检 |
|---|---|---|
| 花钱 | **不花**。只发各家最便宜的探针：列模型 / `max_tokens=1` / 列任务 | 会真的出一张图、一段视频 |
| 产出媒体 | 一张都不出 | 出 |
| 谁触发 | 自动 | 必须由人点 |
| 答什么 | 密钥对不对、路径通不通 | 这个模型 ID 到底能不能出东西 |

同一家被多条能力用到时**只探一次**；横幅也按服务商归并 ——
一把密钥填错会让复核、出图、视频三条同时红，逐条列的话同一句话重复三遍，
看着像三个问题，其实只有一个。

嫌吵可以在「设置 → 本机环境」关掉。

配套的「请求记录」页留着每一次出站调用的完整请求与响应（已脱敏），
生产跑挂了先来这里翻。顶部有近 100 次的成功率和 P50/P95。

## 三、接的模型

能力是**分开路由**的 —— 剧本、复核、出图、视频、配音各选各的服务商。
各家强项差得远，绑死一家处处将就。

| 服务商 | 协议 | 能力 |
|---|---|---|
| **OpenAI（标准接口）** | 原生 | 对话、视觉、出图、**视频（Sora 2 / 2 Pro）**、配音 |
| **火山引擎 方舟 Ark** | OpenAI 兼容 + 原生任务 | 豆包对话/视觉、Seedream 出图、SeedEdit 图生图、Seedance 视频 |
| **FloatAI Router** | OpenAI 兼容 | 中转聚合，转发 GPT / Claude / Gemini / DeepSeek |
| 阿里云百炼 DashScope | 原生 | Qwen、Qwen-VL、通义万相出图/视频、CosyVoice 配音 |
| DeepSeek / 智谱 GLM / Kimi / 硅基流动 | OpenAI 兼容 | 对话、视觉、出图 |
| Ollama / LM Studio | OpenAI 兼容 | 本地模型，不用密钥 |
| **秘塔 metaso** | MiniMax H3 中转（`/api/minimax/v2`） | H3 文生/图生视频，2K，带 ratio 字段 |
| **MiniMax 海螺 / H3** | 原生（三步：提交→轮询→取文件） | H3 全模态（9 张参考图、2K、15 秒）、Hailuo 图生视频、image-01 出图、对话 |
| 可灵 Kling | 原生（AK/SK 签 JWT） | 图生视频 |
| Vidu | 原生（`Token` 而非 `Bearer`） | 参考图生视频（锁人设最好的一条路） |
| 空白请求 | — | 任意 HTTP，调什么都行 |

新增一家：在 `core/providers/catalog.js` 里加一个对象就行，UI 和路由都不用改。
OpenAI 兼容的那些只要给 baseUrl 和密钥名，一行工厂函数搞定。

**关于 FloatAI 的 baseUrl**：中转类网关基本都是 OneAPI/NewAPI 那套，入口在 `/v1`，
所以预设成 `https://router.floatai.cn/v1`。如果你的面板给的不是这个，
在「服务商与密钥」里改一行即可，改完立刻生效 —— 先点「自检」确认再用。

## 四、流水线

```
01 设定集 → 02 分镜 → 03 镜头出图 → 04 视频生成 → 05 配音 → 06 合成
```

**设定集是一整步**：写描述和出参考图一口气做完。
中途试过拆成两步（先出文字、人确认、再出图），道理上说得通，实际不好用 ——
多一次手动确认、多一个"图还没出"的中间态，而设定集本来就是
**一口气出齐才有意义**的东西。也没有"冻结/解冻"那一层：
设定集随时能改，改完点「存文字」（不花钱），想让图跟上再点「改完重出」。

**设定图出齐才能拆分镜**。这不是洁癖：缺一张角色设定图，后面引用它的每一镜
都少一张参考图、少一份复核基准，**一致性就是从那儿开始塌的**——
而等你发现时已经在出几十张分镜图了。所以创作台顶上会直接告诉你还差哪几张，
点「分镜」也会被拦住并列出缺的条目。

编号是真序列：设定集必须在分镜之前跑，因为分镜要引用已冻结的人设
（所以分镜提示词里**明确要求模型不要重复写外貌**，重复写反而会和设定冲突）。

每一阶段都是"读项目 → 干活 → 落盘 → 回事件"。这类任务动辄几分钟，
中途关窗口、断网、改主意都是常态 —— 只要落了盘，下次打开就从断点接着跑，
不用从头再烧一遍额度。

项目的新建、切换、改画风、删除都在独立的**「项目」页**（左侧第 01 项），
创作台只管"这一部片子怎么往下做"。画风在建项目时定一次，之后每条提示词都从
设定集里取，不会在剧本旁边再问你一遍。

### 画风卡片上那张图

三层，优先级从高到低：

1. **你自己模型出的真图** —— 项目页点「用我的模型出全部预览图」，
   十二张用同一句场景描述、只换风格锚，出完落盘，之后卡片上一直是它。
   这张最有用：它回答的是"这个画风在**我的模型**上长什么样"，
   而不是"在别人那儿长什么样"——后者选起来其实不作数。
2. **随应用带的示例图** —— `ui/style-img/<预设 id>.webp`。一眼就能认出画风，
   比文字描述快得多。放一张进去就自动生效，不用改代码：
   后端探一下文件在不在再告诉前端，没有的那几个照旧退回第 3 层，
   而不是留一个碎掉的图框。
3. **内置示意图** —— 同一个镜头的十二种画法（湖畔、远山、栈桥上一个人影），
   构图完全一致，只改渲染方式和配色。内联 SVG，离线可用、缩放不糊。

第 2 层的图必须是**自己有权分发**的（用户自备，或自己的模型出的）。
从网上找来的图随应用发出去，版权风险落在用它的人头上。

预览图存在 `%APPDATA%\FutureDream\style-previews\`，随时可以清掉退回下一层。

### 一个角色两套衣服、一个场景内景外景

最容易想到的做法是拆成两个条目：「阿澜」和「阿澜（便装）」。**这条路是错的**——
两条独立设定之间没有任何关系：两颗不同的种子、两张各自发挥的设定图，
一致性复核还会把它们互相判成不一致。**换套衣服等于换了个人。**
场景同理：「码头·晨雾」和「码头·夜雨」拆开之后，凭什么保证它们还是同一个码头？

真正该拆的是**"永不变的"和"这一版变的"**：

| | 写什么 | 变不变 |
|---|---|---|
| **身份锚**（条目描述） | 脸型、发型发色、瞳色、身形 / 建筑、地貌、标志物 | 全片唯一，永不变 |
| **变体**（条目下的每一版） | 只写这套衣服 / 这个时段的光线 | 想加几版加几版 |

三件事保证"还是同一个人、同一个地方"：

1. 所有变体**共用条目的那一颗种子**（身份种子），采样起点一致；
2. 每一版的出图提示词都是 **身份锚 + 这一版变的那部分**，身份锚永远在场、永远在前；
3. 一致性复核优先拿**同一个变体**的设定图当基准。只能拿别的变体比对时，
   会明确告诉复核模型"**忽略服装差异，只看是不是同一个人**"——
   不这么做的话，换套衣服必然被判"服装配色不符"，引擎会一直换种子重试，
   重到次数用尽也过不了，而问题根本不在图上，在于比错了东西。

用法：设定集卡片里展开「造型 / 时段」，加一版、写一句"变的那部分"、点「出图」。
分镜卡片的「改文案」里可以指定**这一镜**用哪一版；拆分镜时模型也会按剧情自己挑
（雨夜那几镜挑雨夜外套，值班室那几镜挑内景）。用了非默认那版的镜头，
卡片上会直接标着 `阿澜·雨夜外套` —— 出来的图"衣服不对"时，第一眼就看得见。

> 设定图**按变体计数**：一个角色三套衣服就是三张。删掉某一版时，
> 指着它的分镜会自动退回默认那版，不会留下一个指向不存在变体的引用。

### 声音也是身份的一部分

画面上做了四层一致性，声音上却是**同一个人配了所有角色**——
这个反差比画面不一致更出戏：两个人对话时，观众分不出谁在说话。

所以音色和种子一样挂在角色身上，全片唯一：

- 跑配音时会自动给每个角色分一个**互不相同**的音色，旁白也有自己的一个、且不和角色撞；
- 分镜上有「谁说的」（`speaker`），拆分镜时模型会填，也能手改。
  没标就退到出场角色，没人出场就是旁白；
- 你手选过的音色不会被自动分配覆盖——**你挑的比自动分的准，那是你听过的**；
- 音色清单跟着「配音」那条路由走，各家不一样；清单是候选不是断言，可以手填。

> 这里补的是一个一直存在的漏洞：`synthesizeSpeech` 一直有 `voice` 参数，
> 而 `generateVoice` 从来没传过它。

### 字幕

合成时自动在成片旁边生成 `.srt`。数据本来就全在手上（台词、每镜时长、裁剪策略），
只是把它们按时间轴排一遍——**而短剧没字幕基本不能发**。

时间轴用的是**合成时真正生效的那个时长**：`trim` 策略下按分镜计划时长，
`keep` 策略下按模型实出时长。拿错一个，后面每一条都会累积偏移，越到片尾偏得越离谱。

「设置 → 画面规格」里可以打开「把字幕烧进画面」，默认关：烧字幕要 FFmpeg 编进了
libass、系统里还得有能显示中文的字体，缺哪个都会失败。**就算开了，烧失败也只丢字幕、
不丢成片**——片子已经在那儿了，`.srt` 也在，播放器里挂上就行。

### 设定集可以用本地图片当基准

有些参照是**模型画不出来的**：真人演员的定妆照、客户给的产品图、
已经定稿的角色三视图 —— 你要的就是**这一张**，不是"像这一张"。

设定集每张卡片上都有「传本地图」。传上来之后它和模型出的设定图**完全同等**：
一致性复核拿它当基准去比对，每一镜的提示词从它派生，出图时作为参考图带上。
也就是说，传一张真人照片，后面所有镜头都会照着这个人画。

- 收 PNG / JPG / WebP，上限 7MB —— 和内联发给模型的上限卡在同一条线上，
  免得"存下来了、真要用的时候才报超限"。
- 文件落到项目自己的 `assets/` 里，文件名带 `-upload`，一眼看得出这张不是模型出的。
- 卡片上标「自传图」。点「改完重出」会用模型重画一张盖掉它 —— 这是预期行为，
  所以标记也会跟着换回去，界面不会一直说"你传的"。

### 图片能点开看

分镜网格和设定集里的缩略图都能点开：滚轮缩放（以鼠标位置为锚点）、拖着平移、
左右方向键翻上一张下一张、Esc 关闭。缩略图两百来像素，
判断"这张脸对不对""手指有没有崩"根本不够看。

> 删除是真删，图、视频、成片一起没，删完列表当场更新。
> Windows 上删不掉的老毛病（页面还在播那段 mp4，文件被占用）也处理了：
> 发请求前先让页面松开文件句柄，删除本身带重试，万一还有残留会在下次启动时清掉。

### 单独重出，同样吃设定集

批量跑完总有零星几镜不满意。分镜卡片下面的「单独重出」可以只重跑那一镜，
还能临时换服务商、换模型、换清晰度。

关键是：**单独重出走的是和批量完全一样的一套设定集** ——
提示词从冻结设定装配，参考图带上「场景基准图 + 出场角色设定图 + 镜头里点到的道具图」，
场景图排第一张（多数厂商给首图的权重最高，而人物已经被首帧图锁住了）。
少带任何一样，重出的这一镜就会成为全片里唯一对不上的那张。
卡片上会列出这次带了哪几张（`景·码头、角·阿澜、道·执法记录仪`），
重出来还是不像的时候，先看这一行。

### 清晰度与画幅

「设置 → 画面规格」里选。分辨率档位跟着**当前视频服务商**走，
因为各家的写法根本不统一 —— 方舟是 `720p`，万相是 `720P`，秘塔是 `768P` 但 `480p`。
选中的档位在发送前按大小写不敏感匹配翻译成该家的原样拼写；
换了一家而新家没有这个档位（比如从秘塔的 2K 换到方舟），会退回该家默认档并在日志里说一声，
而不是把一个必然报错的值发出去。

省钱的跑法：先用低档把全流程跑通、确认分镜和人设都对，最后一遍再拉高重出。

画幅同时作用于出图和出视频 —— 分开设的话，成片里图和视频的比例会打架。

**画幅记在项目上，不是全局开关。** 新建项目时就选（16:9 / 9:16 / 1:1 / 4:3 / 21:9，
一排按真实比例变形的小方块，一眼看得出横竖），之后这一部片子从出图到出视频都按它走。
「设置 → 画面规格」里那个只是**新建时的默认值**。

之所以这么分：手上同时有横屏宣传片和竖屏短剧是常事。挂在全局设置里，
就意味着每次切项目都得记得回去改一次 —— 迟早有一次忘了，整条流水线跑完才发现横竖反了。
项目卡片上直接标着当前画幅，创作台顶上那一条也标着，下手之前就看得见。
老项目没有这个字段，显示成「跟随设置」，行为和以前一模一样。

### 镜间衔接：一致性管"像不像"，衔接管"接不接得上"

这两件事经常被混为一谈，但坏起来的样子完全不同：

- **一致性坏了** → 第 7 镜的人换了张脸。逐镜看就能发现。
- **衔接坏了** → 每一镜的脸都对，可是第 6 镜是黄昏、第 7 镜突然大中午；
  人在第 6 镜往右走出画，第 7 镜却从右边走进来（观众会觉得他掉头了）。
  **逐镜看每一张都没问题，只有连起来放才露馅** —— 而那时候钱已经花完了。

处理衔接的第一件事不是"怎么接"，是**判断哪两镜该接**。
最容易想到的做法是把上一镜的末帧一路传给下一镜，这样确实处处接得上，
但整部片子会变成一个连续长镜头 —— 没有剪辑、没有机位变化，
二十镜看下来像一条没剪过的素材。电影语言里"接"和"切"是两件事。

所以每一镜和上一镜的关系分成三种，各用各的手段：

| 关系 | 什么时候 | 怎么做 |
|---|---|---|
| **换场景** | 换了地方 | 完全不接。画面本来就该变，硬接反而把转场做糊 |
| **同场景换机位**（默认） | 同一场景，机位跳了 | 提示词层面：光线、天气、时间、环境陈设保持一致；**不要越轴** |
| **连续动作** | 推门→进门这种动作不能断 | **把下一镜那张图锁成这一镜的末帧**，两镜之间无缝 |

默认给「同场景换机位」是刻意的，因为判断错的代价不对称：
该切的地方接上了，整段失去剪辑感只能重出；该接的地方切了，顶多硬切一下还能看。
「连续动作」只能是人明确选的（分镜卡片的「改文案」里有这个下拉）。

**末帧锁的方向也是刻意的**：是"拿**下一镜**的图当这一镜的末帧",
不是"拿上一镜的末帧当这一镜的首帧"。后者会让这一镜不再忠于它自己那张已经审过的图 ——
等于把一致性让给了衔接。走前者，首帧是这一镜审过的图、末帧是下一镜审过的图，
两个都保得住。收末帧的有可灵（`image_tail`）、Vidu（首尾帧接口）、方舟（两张图各带 `role`）；
**不收的那几家会明说"这一段是硬切"**，而不是默默降级 ——
界面上标着"连续动作"、实际却没锁上，是最坑人的一种情况。

还有一层最便宜的：**把上下文写进提示词**。不多花一分钱、不多调一次接口，
只是告诉模型"你是第 7 镜，接在什么后面、要交给谁"。
没有这句的话，模型只看得见一张图和一句描述，它不知道自己是一部片子里的一镜，
于是每一镜都从头起势、各演各的 —— 这就是"逐镜都对、连起来不像一部片子"的根因。

### 末帧复核：漂移都发生在后半段

出图那步的复核只看一张静态图，可**视频的人设漂移几乎都在后半段**——
首帧是我们给的，当然像；模型自己往后推五到十秒，脸才开始飘。只验首帧等于没验。

所以视频出完会用 FFmpeg 抠出**最后一帧**，再送去和角色设定图比对，
分数标在分镜卡片上（`末帧 58`）。抓的就是"开头对、结尾不对"这种逐镜看根本看不出来的问题。
没装 FFmpeg 就跳过并说一声，绝不拦住视频落盘 —— 质检坏了不该让已经花钱出好的片子丢掉。

### 长篇分章：两条路并存

| | 按字数切 | 让模型按情节切 |
|---|---|---|
| 花钱 | 否 | 是（长篇要问好几轮） |
| 速度 | 瞬间 | 看长度，几十秒到几分钟 |
| 依据 | 作者写的章节标题；没有就攒段落到目标字数 | 时间跳跃、地点转换、视角切换、情节单元结束 |
| 短板 | **不懂剧情**，可能把一场戏从中间劈开 | 要花钱 |

先用免费那条跑通全流程，觉得切得不好再让模型切一次。

长篇塞不进任何模型的上下文，所以走**滑窗**：每次只给模型一段带重叠的文本，
问它"这一段里哪些位置适合断章"，再把各窗口的答案拼起来。
重叠是必须的 —— 断点正好落在窗口边界上时，两边都只看到半截，谁也认不出来。

关键的一手是**让模型回原文片段，而不是字符位置**。模型数不准字数，
报出来的偏移基本是错的；让它引一句原文（"新的一章从『三日后，渡口起了雾』开始"），
我们自己 `indexOf` 一下就精确了 —— 把模型不擅长的事留给代码。
引文对不上原文（模型顺手润色过）的锚点直接丢掉：**与其猜一个位置，不如少切一刀**。

模型分章还会顺带给每章一个标题和一句话梗概，显示在章节列表里。

### 分镜图为什么不走图生图

带着角色设定图去出这一镜，听起来应该更一致 —— 实际不是。

SeedEdit 这类是**编辑**模型：它拿到一张图之后是**在那张图上改**，
而不是照着它另画一个场景。于是出来的分镜图长得像"被改过的角色设定图"
（人物居中、纯色背景还在），根本不是你要的那一镜。

所以分镜图默认走**能力路由里那个文生图模型** + 冻结描述 + 稳定种子，
也就是这个应用早期版本的做法 —— 实测下来一致性反而更高、构图也正常。
参考图那一层留给**出视频**（首帧图 + r2v 通道），在那边它是真的有用。

想试的话，「设置 → 画面规格」里有「分镜图改用图生图模型」的开关，默认关。

### 关于"图和描述不符"

设定图和描述对不上时，先看**真正发出去的是哪句话**——
设定卡里的「出图提示词」下面就写着"上次真正发出去的"。

这里修过一个很难查的 bug：出图提示词以前取的是
`item.sheetPrompt || item.appearance`，而 `sheetPrompt` 在生成设定集时
就被模型填满了、**永远非空**。于是你改了描述、点重出，真正发出去的一直是
那份**你看不见也没动过**的 `sheetPrompt` —— 画的还是旧描述，
而且怎么重出都没用。现在它默认空、只在你明确写了才顶上、改描述时自动清掉。

还修了**画面描述被埋**的问题。原来的提示词顺序是
「风格锚 → 每个角色 60~90 字外貌 → 场景 90 字 → 道具 → 画面描述」，
两个角色一个场景就是 250 字，而这一镜真正要画的那句话只有二十来字、
排在第 150 字之后 —— 模型读到那儿权重已经稀释干净，出来的图
"人是对的、可就是没在演这一镜"。

现在画面描述紧跟风格锚，**它才是这一镜的主语**。

角色描述压不压缩，取决于**参考图会不会真的发出去**：会发就只给
「三段特征 + 外貌以参考图为准」，把版面让给画面内容；不发就把完整外貌铺开兜底。

> 这里挂过一次，而且是最坏的一种组合：分镜图默认不带参考图之后，判断条件却只问了
> "设定集里有没有图"——于是提示词被压成三段、末尾还挂着一句"外貌以参考图为准"，
> **而那张图根本没发**。模型既没拿到图，又被砍掉了"袖口两道银线、左胸编号牌"
> 这些真正锁得住身份的细节，出来的人当然谁也不像。
> 判断的必须是"会不会发"，不是"有没有"。

### 技法库：镜头运用、光线、动作、氛围

模型拆出来的 `motion` 大多是"镜头缓慢推进"这种放之四海皆准的话。
真正让画面有电影感的是具体技法 —— 伦勃朗光、荷兰角、希区柯克变焦。
这些术语你未必天天记得住，**模型却认得很准**，那就把它们做成卡片。

分镜卡片的「改文案」里选，六个分类：

| 分类 | 例子 | 作用范围 |
|---|---|---|
| 运镜（单选） | 推镜、跟拍、手持微晃、希区柯克变焦 | **只影响视频** |
| 机位角度（单选） | 仰拍、荷兰角、过肩、大特写 | 出图就生效 |
| 光线（单选） | 伦勃朗光、逆光轮廓、百叶窗光、霓虹混光 | 出图就生效 |
| 动作（可多选） | 打斗、回眸、拔刀、落泪 | 两者 |
| 氛围（可多选） | 紧张压抑、史诗恢弘、诡异不安 | 两者 |
| 出入画（可多选） | 结尾出画、开头入画、结尾甩出 | 配合镜间衔接用 |

三个设计上的讲究：

- **卡片写的是"发给模型的原话"，而且带上视觉结果**。"伦勃朗光"不如
  "侧上方主光，暗侧颧骨下形成三角形光斑"——模型对术语的理解有强有弱，
  把术语和它的视觉结果一起给，命中率高得多。
- **插在提示词的哪个位置是每张卡自己声明的**。越靠后的描述越容易被稀释
  （这个项目踩过：风格锚放末尾几乎不起作用），所以机位和光线紧跟画面描述，
  排在"主色调"之前；运镜类**根本不进出图提示词**——对一张静态图说
  "镜头缓慢推进"没有意义，只会占掉画面描述的权重。
- **互斥组在界面上就是单选**。不能同时仰拍又俯拍，那就不该让你点得下去；
  让人选出一个自相矛盾的组合再报错，是很差的设计。选了具体运镜时，
  那句默认的"镜头缓慢推进"会被替换掉而不是并存——两条指令会打架。

**技法可以让模型挑**（分镜面板上的「让模型挑技法」）。手选的问题不在于麻烦，
在于**你未必记得住**——伦勃朗光、荷兰角、希区柯克变焦这些术语不是天天用就想不起来，
于是四十七张卡里永远只用那三张。模型读一遍每镜的画面描述就能挑出该用的，
这是它真正擅长的事。

三个讲究：**一次调用管全片**（逐镜问二十次又慢又贵，而且模型看不到上下文，
容易每镜都挑同一套）；**让它给理由**（要判断的是"它为什么这么挑"，
不是盯着一串 id 猜）；提示词里写死**宁缺毋滥**（不写这句，模型会给每镜都堆满，
每镜都有重点等于每镜都没重点）。挑完**不自动重出图**——先翻一遍，
不满意的手改掉，再统一重出。模型自创的 id 和互斥组冲突会走和手选同一条规整逻辑。

还有「套用到同场景的其它镜」：一场戏往往用同一套手法，一个个点太慢。
以及「自己加一张技法卡」——存在数据目录里跨项目复用，
你总结出来的手法不该换个项目就得重写一遍。

### 分镜描述可以直接改

分镜是模型拆的，**拆偏一句，后面每一次重出都是在错的基础上重来**——
把"雨夜"写成"清晨"、把"特写"写成"全景"，重十次也回不到对的画面。
分镜描述本身就是可点的（卡片上也有「改文案」按钮），
能改画面描述、景别、运镜、场景、出场角色和台词。改一行字比重跑十次便宜得多。

两个刻意的设计：

- **只动文案，不碰产物。** 接口只认白名单字段，已经出好的图和视频一个都不会被这次编辑弄没
  （界面上那份分镜可能是十分钟前拉的，整份回传会把中间刚写进去的路径盖掉）。
- **改完不自动重出。** 一般人会连着改好几镜再统一重出，改一个字就烧一次钱不是好事。
  改过的镜头会标「文案已手改」，上一次的一致性分数会标成「已过时」——
  那个分数是对旧描述打的，留着不说明就是在冒充现在的结论。

### 界面只显示当前这一步的参数

点哪一步，下面就只摆哪一步用得上的东西：

| 选中的阶段 | 分镜卡片上出现 | 时长面板 |
|---|---|---|
| 分镜 | 每镜时长 | 显示 |
| 镜头出图 | 出图服务商 / 模型 / 出图按钮 | 收起 |
| 视频生成 | 每镜时长、视频服务商 / 模型 / 清晰度 / 出视频按钮 | 显示 |
| 配音、合成 | 只看状态 | 收起 |

在出图那一步摆一堆秒数和视频模型，只会让人以为得先把它们配好才能出图。

### 跑起来之后

一步动辄十几分钟，所以运行状态**不绑在页面上**：中途切去别的页面看一眼，
回来进度、正在生成哪一镜、失败原因都还在，跑完了当前页面自己就把新图新视频显示出来，
不用退出去再进来。

> 媒体接口回 `Cache-Control: no-store`，前端的链接也带内容版本号 ——
> 重出的文件路径不变，少了这两道浏览器会拿缓存糊弄你，看着就像"重出了但没变"。

### OpenAI 的视频（Sora）有两处和别家不一样

1. **不走 chat 那套协议**，自己一条路：`POST /videos` → `GET /videos/{id}` → `GET /videos/{id}/content`；
2. **下载也要带密钥**。别家给的是公网直链，拿着就能下；Sora 的 `/content` 不带
   `Authorization` 会回一段 401 的 JSON —— 存下来就是一个打不开的"mp4"，
   而且文件确实在，最难查。所以鉴权头会一路带到落盘那一步，
   并且落盘前检查 `Content-Type`：回来的是 JSON 就当场报错，不假装成功。

时长只收 4 / 8 / 12 秒三档；尺寸收的是像素（`1280x720` 这种）而不是 `720p` 档位，
所以会按「设置 → 画幅」自动挑方向——竖屏短剧配个横向尺寸，等于白出一条片子。

### 关于秒数：厂商只认固定档位

模型不接受任意秒数，只认自己的那几档（方舟 5/10，Vidu 4/8，秘塔 5/10/15）。
每镜时长会**向上取整**到最近的档位 —— 宁可多出来一点合成时裁掉，
也不要少了把动作或台词切断。

所以「时长」面板里三个数是分开的：

| | 含义 |
|---|---|
| 计划 | 你设的，分镜时长相加 |
| 模型实出 | 厂商按档位实际给的，通常比计划长 |
| 成片 | 合成后的最终长度 |

默认策略是 `trim`：合成时按每镜的计划时长裁剪，**成片总长仍然等于你设的目标**。
想保留模型给的完整片段（运动更自然，但成片会变长），去「设置 → 时长策略」改成 `keep`。

界面会在跑之前就把这件事说清楚：时长面板列出当前模型的档位，
分镜卡片上直接写「这一镜会按 5 秒生成，合成时再裁回 4 秒」。

### 出视频一直失败？

先看流水线下面的**失败汇总** —— 那里是服务端原话，答案基本都在那句话里。
轮询日志刷得飞快，所以失败原因单独留一份，不会被顶走。

已知最常踩的一个坑（这一版已经修掉）：**各家能收几张图差得很远，超了不是多余的被忽略，
而是整个任务提交失败**。

| 服务商 | 出视频最多收几张图 |
|---|---|
| 火山方舟 Seedance | **1**（只有首帧；首尾帧模式 2 张且要带 role） |
| 通义万相 | 1 |
| 可灵 Kling | 1 |
| Vidu | 3（reference2video，锁人设最好的一条路） |
| MiniMax H3（官方） | 9 |
| 秘塔中转 | 起点 3，真实上限自己试出来（见下） |

设定集参考图是按"能带多少带多少"给下去的，现在会在发送前按厂商上限截断，
并在日志里说清楚截掉了几张、一致性改由什么承担。方舟这条路上，
人和环境靠的是首帧图本身 + 提示词里的冻结设定描述。

**中转平台的上限是试出来的**：秘塔转的是 H3（官方收 9 张），但它自己会回
「输入媒体数量超过限制 (2013)」，文档里没写几张算超。目录里的数字只能当起点 ——
撞上这个错就减半重试，直到只剩首帧，试出来的值按「服务商 + baseUrl」记住，
同一批后面的镜头直接用。这类失败是参数校验失败，服务端还没开始出片，不计费。

剩下的排查顺序：① 服务端原话；②「设置 → 上线前体检」把这条能力真跑一次最小调用；
③ 模型 ID 是不是你账号里真实开通的那个（方舟的短名早已下线，填了会返回 404）。

### 任务取不回来时，流水线不该卡死

"提交成功了，但状态查不到"是这条链路上最难受的一种状态：钱花了、片子在厂商那边，
我们这边缺一块 —— 既不算完成（合成时少一段），也不算失败（重跑要再花一次钱）。

所以它被单列成**待认领任务**，给三条出路：

1. **重查一次**（视频阶段的面板上）——只是再问一遍，**不重新生成、不花钱**。
   刚在「接口地址（高级）」里填对路径的话，这一下能把之前卡住的全收回来；
2. **手动补入**（每张分镜卡片里，常驻，不需要任何前提）——
   去平台复制视频/图片地址粘进来，这一镜就补齐；
3. **缺镜也能合成**——不会卡在"必须全齐"上，但会明确告诉你少了哪几镜。

分镜面板的角标把两件事分开数：`2 镜缺视频` 是压根没跑，`1 个任务待认领` 是钱花了没取回来。

### 下载那一步也可能要密钥

多数厂商给的是公网直链，拿着就能下。但有两类不是：

- OpenAI 的 `/videos/{id}/content`；
- 秘塔给的 `files.metaso.cn/...` —— 不带密钥回 `{"errCode":401,…}`。

这两种失败长得一模一样：**文件下下来了、就是打不开**，最难查。
所以先按公网直链试（绝大多数情况，也不会把密钥发给不相干的域名），
只有在回 401/403 或回了一段 JSON 时，才按域名匹配到对应服务商、带密钥重试一次。
密钥只会发给"和该服务商同一个主域"的地址；IP 地址要求连端口一起完全一致
（`127.0.0.1:11434` 和 `127.0.0.1:8080` 是两个不相干的服务）。

落盘前还会看一眼 `Content-Type`：说好是视频却回来一段 JSON 就当场报错，
不假装成功、不留一个打不开的文件。

### 阿里云百炼：只认公网 URL

本应用默认把本地图转成 `data:` URI 交给模型（Windows 用户不必先去开一个 OSS 桶），
而百炼的图生视频/参考图生图**只认公网 URL**。两者一撞，任务会**提交成功**、
然后在轮询里以 `InvalidParameter` 失败——白等一轮，报错里还看不出是这个原因。
现在发出去之前就拦下，并给两条出路：配一个上传网关，或者把这条能力换成收 base64 的那几家。

> 顺带修了一个更坑的：异步任务失败时，早期版本直接甩 `JSON.stringify(...).slice(0, 300)`，
> 而百炼把 `code` / `message` 放在对象**末尾** —— 一截就正好把最关键的那句话切掉，
> 用户看到的是 `…"message":"Field re`，等于什么都没说。现在原因排在最前面。

### 中转平台：查任务的地址是猜出来的

国内视频模型清一色"提交任务 → 轮询"，但中转平台往往只公开"提交"那一步，
查任务的路径要靠试。试的时候**必须看返回内容**，不能只看 HTTP 200 ——
中转平台常常对任何路径都回 200（首页、错误页、空对象都算），
锁到这种地址之后每次轮询都读不出状态，一路轮到十分钟超时，
界面上就是"轮询第 105 次（排队中）"，而视频在厂商那边早就出好了。

所以现在：候选路径要么提到了这个 `task_id`、要么有认得出的状态词、要么直接给了视频地址，
三者有其一才算数；真锁错了也不空等 —— 连着三次读不出状态就停下来，
把响应原样摊开，并把探出来的路径作废。

**探不出来就自己填**：「服务商与密钥 → 接口地址（高级）」里可以逐条覆盖。
查任务那条支持写 `{taskId}` 指定任务号的位置，不写就自动加 `?task_id=`。
填完立刻生效，不用等我改目录再发一版。

**外面套的那层也要看。** 各家套的名字还不一样：

```
MiniMax v2 / 秘塔   {"task":   {"status":"succeeded","content":{"url":…}}}
百炼                {"output": {"task_status":"SUCCEEDED"}}
一堆中转            {"data":   {"status":…}}
```

少看一层就等于读不出状态，然后一路轮到超时。现在这几层都认。

**还有一类要分开看：HTTP 200，但错误藏在 body 里。** 国内这一圈网关都有这毛病，
比如秘塔回过 `{"type":"error","error":{"message":"login fail: ...(1004)","http_code":"401"}}`。
把它当成"任务还没好"就会一直等下去，而鉴权错等到天荒地老也不会变。
现在这类响应会当场停下来，并且**把"密钥不对"和"路径不对"分开报** ——
提交那步是通的就说明密钥没问题，问题在于这家查任务时要的鉴权形式不一样。

**最后一条兜底：手动补入。** 任务在人家平台上跑完了、钱也花了，我们却查不到 ——
这种时候最要紧的不是继续猜路径，而是别让已经出好的东西丢掉。
分镜卡片上会显示那个 `task_id`，去平台复制视频地址粘回来，这一镜就补齐了，
流水线继续往下走。

### 连不上（UND_ERR_CONNECT_TIMEOUT 之类）

这类错误和密钥、模型一点关系都没有 —— 请求根本没发出去。报错里会直接说清楚，
并给出三步：浏览器打开那个域名试试 → 通就是缺代理 → 不通就是网络挡了。

Node 自带的 fetch **不读系统代理**，一律直连，所以公司网络下会直接连接超时。
桌面版里可以「设置 → 走 Windows 的系统代理」，它改用 Electron 的网络栈，
跟浏览器一样读系统代理。默认关着 —— 换网络栈是有风险的事，不该悄悄替所有人换。
命令行模式（Lite 包）没有这条路。

## 五、手机端

手机上看进度、审分镜、当场改文案重出、看成片、把素材打包带走。
**不需要任何服务器** —— 手机和电脑在同一个 Wi-Fi 就够了。

电脑上打开「设置 → 手机遥控」，拿到地址和 8 位配对码。

引擎始终在电脑上：密钥、FFmpeg、几百 MB 的中间文件都在那台机器上，
也只该在那台机器上 —— 手机丢了不等于密钥丢了。手机只发指令、只看结果。

### 两种用法

| | 怎么装 | 差别 |
|---|---|---|
| **浏览器** | 手机浏览器打开那个地址 | 功能一模一样，只是没有独立图标 |
| **安卓 apk** | 发布页下 `FutureDream-Remote.apk` | 真图标、独立窗口、下载走系统下载器 |

为什么浏览器里装不成"应用"：安卓 Chrome 的「安装应用」（WebAPK）要求
**安全上下文**，而 `http://192.168.x.x:5179` 不是 —— 实测 `isSecureContext = false`，
连 `navigator.serviceWorker` 都不存在。这不是能绕开的事，所以出了个 apk。
apk 里装的就是同一个网页，改功能不用重新发包。

### 出门在外

不必租服务器：装个 Tailscale 之类的组网工具，手机和电脑就像在同一个局域网里，
上面那套原样能用。

### 剪辑怎么分工

精剪在剪映里做 —— 转场、音乐、花字那些它做得比我们好，硬碰硬赢不了。
这一端负责**把素材备齐**：成片页有「打包下载全部」，一个 zip 里装着

```
成片_<片名>.mp4
字幕.srt              剪映专业版可直接导入，省一次语音识别
分镜片段/01_….mp4     按编号命名，解压出来按名字排序就是分镜顺序
配音/01_….mp3
分镜表.txt            每个片段是哪一镜、多长、说了什么
```

进剪映依次拖进时间线就是初剪的起点。

## 六、放到服务器上（24 小时开着）

电脑关着的时候也想用手机跑 —— 那就得有一台一直开着的机器。
代价必须先说清楚：

- **API 密钥会存在那台服务器上**。加密存着，但能 ssh 进去的人就在你的信任边界里了。
  用 `FD_VAULT_PASS` 可以让解密用的钥匙**不落盘**（口令只在环境变量里），
  这样拿到磁盘也解不开 —— 强烈建议配上。
- **按月付费**，一台 2 核 4G 的小机器就够（出图出视频都是调厂商接口，本机不吃算力；
  只有合成那一步吃 CPU）。
- 必须走 HTTPS。访问口令在明文 HTTP 上跑等于在公网广播它。

### 三条命令

先把域名的 A 记录指到服务器 IP，然后：

```bash
git clone <这个仓库> && cd desktop
cp .env.example .env && vi .env      # 填 FD_HOST / FD_VAULT_PASS
docker compose up -d
```

Caddy 会自动去 Let's Encrypt 签证书并续期，不用碰 certbot。
访问口令看 `docker logs`（`.env` 里没填 `FD_TOKEN` 时第一次启动会生成一个）。

浏览器打开 `https://你的域名` 输口令即可；手机上打开同一个地址，
因为是 HTTPS，安卓 Chrome 这次**能真正「安装应用」**（WebAPK）——
局域网那条路做不到的事，上了服务器反而顺带解决了。

### 从零开一台：完整步骤

**① 买机器。** 2 核 4G、50G 盘就够 —— 出图出视频都是调厂商接口，本机不吃算力，
只有合成那一步吃 CPU。盘要留够：一部 20 镜的片子连中间产物大概几百 MB。

**机房位置按你用的厂商挑**，这条比配置重要：服务器要去调火山方舟 / 百炼，
那就别放在需要翻墙的地方；反过来主要用 OpenAI 的话，国内机器会很难受。

**② 域名。** A 记录指到服务器 IP。⚠ 国内机房 + 域名要**备案**，没备案的域名在
80/443 上会被拦掉；不想折腾就用香港 / 新加坡 / 日本的轻量服务器，免备案。

**没有域名也能上。** 用 `<你的IP>.nip.io` —— 这个公共 DNS 会把
`47.243.29.184.nip.io` 直接解析成 `47.243.29.184`，不用注册、不用配 A 记录，
Caddy 照样签得到真证书。填进 `.env` 的 `FD_HOST` 就行。以后有了自己的域名再换，
改一行重启即可。

**③ 连上去装 Docker。**

```bash
ssh root@你的IP
curl -fsSL https://get.docker.com | sh
```

**④ 拉代码、配置、起服务。**

```bash
git clone <这个仓库> fd && cd fd
git checkout claude/windows-app-third-party-api-8h0qec   # 代码在这个分支上
cd desktop
cp .env.example .env
vi .env          # FD_HOST=你的域名   FD_VAULT_PASS=一串够长的口令
docker compose up -d
docker compose logs app | grep -A3 访问口令     # 把口令记下来
```

**⑤ 防火墙有两层，两层都要开。** 这是最容易卡住的一步：

- **云控制台的安全组** —— 虚拟机**外面**那层。阿里云 / 腾讯云 / AWS 都有，
  默认只放行 22。控制台 → 实例 → 安全组 → 入方向，加 80 和 443。
- **机器里的 ufw** —— 虚拟机**里面**那层。

只开了 ufw 而忘了安全组，从机器上 `curl localhost` 一切正常，外面却完全连不上，
Caddy 会一直签不到证书（日志里是 `Timeout during connect (likely firewall problem)`）。

应用那个 5178 两层都**不要**开 —— 它只需要被同一台机器上的 Caddy 连到。

```bash
ufw allow 22 && ufw allow 80 && ufw allow 443 && ufw enable
```

**⑥ 浏览器打开 `https://你的域名`**，输口令进去，在「服务商与密钥」里配一把 API Key。
手机打开同一个地址，因为是 HTTPS，安卓 Chrome 会提示「安装应用」。

### 起不来的时候，先看这三条

**`docker compose ps` 里 app 是 `Restarting`。** 看 `docker compose logs app | tail -40`
的**最后**几行 —— 前面通常一片成功（口令都打印出来了），真正的原因在最后。
`grep 访问口令` 是看不到它的。

**Caddy 日志里 `Timeout during connect (likely firewall problem)`。**
外面连不进来，八成是上面 ⑤ 里的**安全组**没开。补开之后要注意：Let's Encrypt
连着失败几次会被限流，Caddy 已经自己退到 **staging**（测试）证书上了 ——
浏览器会报证书不受信任。放行端口之后重启 Caddy 让它重新去要正式证书：

```bash
docker compose restart caddy
docker compose logs caddy | tail -20      # 看到 certificate obtained 就成了
```

还不行就把它攒下的证书状态清掉重来（只删证书，不动你的项目数据）：

```bash
docker compose down && docker volume rm desktop_caddy-data && docker compose up -d
```

**浏览器打开是 401 或者一片空白。** 那是正常的登录屏，填 ④ 里记下来的访问口令。
口令丢了：`docker compose exec app cat /data/settings.json`，或者在 `.env` 里
写一个新的 `FD_TOKEN=` 再 `docker compose up -d`。

### 日常怎么维护

```bash
docker compose logs -f app        # 看它在干什么
docker compose restart app        # 重启
docker compose down               # 停（数据在卷里，不会丢）

# 更新到最新版
git pull && docker compose up -d --build

# 备份：项目、密钥、设置全在这一个卷里
docker run --rm -v desktop_fd-data:/data -v $PWD:/out alpine \
  tar czf /out/fd-backup-$(date +%F).tar.gz -C /data .

# 换访问口令：改 .env 里的 FD_TOKEN，重启即可
```

**把电脑上已有的项目搬上去**：一个项目就是一个文件夹，
`%APPDATA%\FutureDream\projects\<项目ID>\` 整个传到服务器的 `/data/projects/` 下。
密钥要在服务器上重配一次 —— `credentials.enc` 是绑机器的，拷过去解不开。

```bash
scp -r "项目文件夹" root@你的IP:/tmp/proj
ssh root@你的IP 'docker cp /tmp/proj $(docker compose ps -q app):/data/projects/'
```

### 服务器模式和本机模式的规矩差在哪

| | 本机 | 局域网（手机） | 服务器 |
|---|---|---|---|
| 监听 | 只听 127.0.0.1 | 另开一个端口 | 0.0.0.0，前面挡一层 Caddy |
| 谁算自己人 | 能打开这个端口的人 | 私网 IP + 8 位配对码 | **只认你配的那个域名 + 32 位口令** |
| 口令查得到吗 | 不需要口令 | 手机那侧查不到 | 每条请求都要带，包括图片和健康检查 |
| 配错了会怎样 | — | — | **直接拒绝启动**，并印出缺什么 |

最后一条是刻意的：一个"少配了一项、于是谁都能进"的服务，
比起不来危险得多 —— 因为它看起来一切正常，没人会去查。

## 数据放在哪

```
%APPDATA%\FutureDream\
├─ settings.json        明文，可以直接手改，也可以贴给同事复现问题
├─ credentials.enc      密钥，DPAPI 或 AES-256-GCM 加密
├─ api-history.json     请求记录（已脱敏）
└─ projects\<项目ID>\
   ├─ project.json      剧本、设定集、分镜
   ├─ assets\           参考图、镜头图、视频片段、配音
   └─ <标题>.mp4        成片
```

一个项目一个文件夹，没上数据库 —— 整个文件夹拷给同事就能接着做，
出问题也能手动改 JSON 救回来。

---

## 安全上做了什么

- 密钥存在加密保险箱里，接口只回掩码（`sk-abc***wxyz`），明文永远不出后端
- 请求记录写盘**前**就脱敏：`Authorization`、`X-Api-Key`、`Cookie` 这些头，
  以及 body 里叫 `api_key` / `secret` / `token` 的字段
- 本地服务只监听 `127.0.0.1`，并校验 `Host` 与 `Origin` —— 防的是浏览器里
  某个网页偷偷往你本地端口发请求
- 媒体接口只放行数据目录之内的文件，目录穿越会被拒
- Electron 里 `contextIsolation` 开、`nodeIntegration` 关，预加载脚本只暴露几个只读标记

> 上一版演示页把 apiKey 明文写死在 HTML 里，谁拿到文件谁就能刷账单。
> 这一版从第一行代码起就不给这条路留口子。
