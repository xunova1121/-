# V1.2 文档闭环与超越 Claude 验收说明

本版本以《AI_Drama_Studio_Complete_Development_Specification_V7》《工业级AI短剧平台技术设计文档 V3.0》《Windows版工业级AI短剧平台最终技术方案 V3.0》和《AI影视工业系统架构设计方案（提供给Claude）》为约束来源，不以页面数量作为完成标准。

| 文档目标 | V1.1 真实缺口 | V1.2 闭环 | 相对 Claude 的工程优势 | 验收证据 |
|---|---|---|---|---|
| 全量分镜后再批量生成 | 离线正则拆镜，AI导演只给建议 | AI导演一次事务化写入全量场次、镜头、Story Bible、价值分和模型要求 | 输出直接成为可编辑生产数据，失败不破坏旧分镜 | `test_ai_director_atomically_builds_bible_storyboard_and_state_graph` |
| 100+ 集实体记忆 | 提示词记忆，没有可证明的状态传递 | 版本化 Story Bible + 跨镜头/跨集状态快照；人物、服装、伤势、道具状态确定性继承 | 模型负责提案，状态引擎负责事实，避免仅靠上下文窗口 | `test_story_state_recomputes_after_edit_and_blocks_production` |
| 连续动作与转场 | 生成额外 5 秒桥接片，可能重复动作并拉长时长 | `continuous` 镜头等待上一镜完成，提取真实尾帧后作为下一镜首帧条件；时间线保持硬切 | 连续性成为任务依赖，不是后期遮掩；不增加剧情时长 | `test_continuous_video_waits_for_previous_tail_frame` |
| Shot Value Score / Model Router | 所有镜头同一优先级和质量参数 | 价值分与模型要求决定任务优先级、关键帧质量和 720P/1080P 路由 | 关键镜头优先且高质量，普通镜头节省成本 | 自动生产任务 payload 中的 `routing` 决策 |
| QualityReport → Repair | 只审关键帧，成片无质量门 | 关键帧、逐镜视频、自动返工后复检、最终成片四级质量门 | 只重生失败镜头；返工一次仍不达标则进入 `review_required`，不伪装成功 | 自动化阶段 `video_review`、`video_repairs`、`video_repair_review`、`final_review` |
| 真实维护中的模型协议 | UI 展示未实现或临近停用的供应商 | 目录只展示已实现能力；OpenAI 已弃用视频接口不再作为生产视频提供方；Wan 2.7 按现行首帧/首尾帧协议 | 能力目录与运行时注册表一致，未实现能力直接拒绝 | `test_claude_borrowed_architecture_endpoints` |
| Windows 可靠交付 | 单 EXE 可运行 | 保留随机端口、版本/实例握手、SQLite 任务租约、内置 FFmpeg，并提升到 V1.2 | 避免旧后台 404 串线，崩溃后任务可恢复 | Windows CI 的服务握手、桌面冒烟与单文件校验 |

## 不再采用的假闭环

- 不把“有供应商名称”算作“已实现适配器”。
- 不把 VACE/RIFE 策略名称算作本地可执行引擎。
- 不用额外桥接视频掩盖动作不连续。
- 不让低于质量阈值的成片显示为成功。
- 不让镜头编辑绕过 Story Bible 和故事状态图。

## 生产状态机

`全剧本 → AI生产设计 → 状态图门禁 → 全量关键帧 → 关键帧质检/返工 → 尾帧依赖视频 → 逐镜视频质检/返工 → 配音/字幕/时间线 → MP4 → 最终质检门`
