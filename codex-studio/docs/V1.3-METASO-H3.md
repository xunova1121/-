# V1.3 秘塔 MiniMax H3 接入与路由闭环

## 真实接入范围

- 提供方：`metaso`
- 默认地址：`https://metaso.cn/api/minimax/v2`
- 密钥：`METASO_API_KEY`，Windows 正式版继续使用 DPAPI 加密保存
- 模型：`MiniMax-H3`
- 提交：`POST /video_generation`
- 首帧/尾帧：`content[].role = first_frame / last_frame`
- 多参考图：`content[].role = reference_image`，最多 9 张
- 查询：优先 `GET /query/video_generation/{task_id}`，兼容 Claude 分支实测的秘塔中转查询路径
- 成品：从 `task.content.url` 下载；`files.metaso.cn` 同域下载自动携带 Bearer 鉴权

## 相比直接复制 Claude 适配器的增强

1. 外部 `task_id` 在提交成功后立即写入 SQLite；服务崩溃、重启或网络中断后继续查询，不重复提交和扣费。
2. HTTP 200 内嵌业务错误会被识别，不会把鉴权失败误判为“仍在生成”。
3. 查询路径只有返回真实任务结构才会缓存，避免把中转首页或空 JSON 当作任务接口。
4. 首尾帧与参考图模式明确互斥，符合 H3 v2 协议；界面不再把 9 张参考图错误当成首尾帧。
5. 请求体限制为 64 MB，单图限制为 30 MB；超限在提交前阻断，避免无效付费调用。
6. H3 原生音频与独立 TTS 同时启用时，提示词强制只生成环境音和动作音，避免双重对白。

## 下一步闭环：H3 → Wan 降级

- 主模型选择秘塔且已配置 Wan 时，自动生产写入备用路由。
- 秘塔排队超时，或临时网络/限流/5xx 连续失败达到重试上限后，任务切换到 Wan。
- 秘塔原始任务 ID 保存在路由记录中，任务台显示 `metaso→dashscope · 秘塔待升级`。
- 401/403 鉴权、400 参数、422 内容审核等确定性错误不自动降级，避免掩盖真实问题。
- 降级任务清空当前执行 ID，但不删除秘塔原始 ID，确保可追踪且不会重复提交秘塔任务。

## 自动化验收

- 秘塔提交、轮询、同域鉴权下载
- 服务重启后凭外部任务 ID 续查且不重新 POST
- HTTP 200 业务错误分类
- 首尾帧与多参考图 role 校验
- H3 排队超时切换 Wan 并保留原任务 ID
- 鉴权失败禁止误降级
- H3 原生音频与后期 TTS 防冲突
