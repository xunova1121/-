# V1.5.6 导演输出恢复与分镜审片体验

## 本版解决的问题

1. 导演模型返回缺冒号、尾随逗号、Markdown 代码块、解释文字或中文全角分隔符时，服务不再立即返回 422。
2. OpenAI-compatible 导演请求现在真正发送 `max_tokens=16000`，并优先请求 JSON object；不支持结构化参数的兼容服务会安全回退普通聊天协议。
3. 严格 JSON 解析失败后使用 `json-repair` 做本地恢复；仍不能形成完整场次和镜头时，才使用同一岗位模型自动重生成一次。
4. 主界面删除重复的第二排全局菜单，保留一条唯一制作流程导航；资产、任务、模型归入全局工具区。
5. 分镜台从数据库宽表改成“场次筛选—核心镜头表—镜头检查器”，不再向创作者展示状态 JSON、动作链 ID 等内部字段。
6. Markdown 时间轴脚本会去除粗体、分隔线和时间码，并把同一时间段的画面、细节和动作合并为一个镜头。

## 数据安全

- 旧项目打开时只做展示清洗，不自动删除镜头或原始素材。
- 用户点击“保存修改”后才写回已清洗的文字字段。
- Story Bible、场次、分镜和状态图仍在导演结果完整校验后一次性提交，失败不会写入半套数据。

## 开源依赖

- `json-repair 0.63.3`
- 许可：MIT
- 用途：仅在标准 JSON 解析失败后修复常见 LLM 结构错误，不参与剧本或镜头内容生成。
