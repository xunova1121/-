# V1.4 动作连续性与价值路由闭环

V1.4 的目标不是增加供应商名称，而是把文档要求的 Shot Graph、动作阶段、模型分级和跨镜质检落实到生产执行。

## 已实现

- 每个镜头保存 `action_id`、`action_phase` 和 `momentum`。
- 连续镜头会检查动作链错配、相位倒退、跨级以及相反动量；阻断项未修复时禁止自动生产。
- 视频提示词会注入动作链、当前相位、运动方向、冻结 Story Bible 和场景预演信息。
- 连续镜头以“上一镜真实尾帧”为起点，以“当前已确认关键帧”为目标帧，交给支持首尾帧约束的 H3/Wan。
- 视频 VLM 审核把上一镜尾帧和当前镜头首帧放在同一次审核中，检查人物姿态、手部、道具、动作相位和动量跳变。
- 失败镜头只做选择性重生成，不重做已经通过的镜头。
- 高价值镜头路由到秘塔 MiniMax H3；普通镜头路由到 Wan，H3 临时失败可降级 Wan 并保留待升级信息。
- 自动生产窗口提供生成前路由预检，逐镜显示提供方、模型、分辨率、时长和选择原因；预检不会创建付费任务。

## 可执行验收

1. `start → end` 的连续动作会因跨级被阻断。
2. `end → middle` 会因动作相位倒退被阻断。
3. 连续动作从 `down` 突然变为 `up` 会因反向动量被阻断。
4. 价值分 80 及以上或 `premium` 镜头走 H3，其他镜头走 Wan。
5. 路由预检与真正入队使用同一个纯路由函数，避免界面显示与执行不一致。
6. 自动生产前先完成全量分镜和连续性校验，再批量提交生成任务。

## 与 Claude 分支的关键区别

Claude 分支提供了秘塔调用范例和较完整的供应商层。V1.4 在此基础上把模型调用纳入可阻断、可预检、可追踪、可质检、可选择性返工的生产闭环；模型不再由整集统一选择，而是由每个镜头的叙事价值和连续性要求决定。
